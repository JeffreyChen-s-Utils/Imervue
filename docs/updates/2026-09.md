## U-20260923-19 · 2026-09-23 · Brush jitter changed on every reopen: seed it with CRC32, not hash() · #incident #annotation

- **Symptom**: found while pixel-comparing the annotation canvas for U-20260923-18 — two runs of the same code on the same annotations differed in 6,658 pixels, all inside the spray, charcoal and crayon strokes. A saved annotation project therefore looked different every time it was reopened, and the baked PNG did not match what had been on screen in an earlier session.
- **Cause**: those brushes scatter their marks from `random.Random(hash(ann.id) & 0xFFFFFFFF)`, in four places in the Qt preview (`annotation_drawing.py`) and four in the PIL bake (`annotation_models.py`). The intent (the bake comment says "seeded RNG so repeated bakes of the same annotation match") holds only inside one process: Python randomises `str` hashes per process unless `PYTHONHASHSEED` is set.
- **Fix**: `annotation_models.jitter_seed(annotation_id)` returns `zlib.crc32` of the id, and all eight sites use it.
- **Result / numbers**: `tests/test_annotation_jitter_seed.py` (6) bakes spray, charcoal, crayon and pencil strokes in subprocesses with different `PYTHONHASHSEED` values and requires identical output, and in-process output equal to a subprocess's; three of its tests failed before the fix. Two canvas renders with `PYTHONHASHSEED=random` now differ in 0 pixels (6,658 before).
- **Files**: `Imervue/gui/annotation_models.py`, `Imervue/gui/annotation_drawing.py`, `tests/test_annotation_jitter_seed.py`, `architecture_explore.md`.
