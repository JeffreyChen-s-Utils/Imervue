## U-20260925-62 · 2026-09-25 · AVIF opens and saves without pillow-heif; the install hint is for HEIC only · #fix #formats #avif

**問題**：AVIF 一直被當成 pillow-heif 的格式，但 pillow-heif 從 1.0 起就拿掉了 AVIF（[pillow_heif CHANGELOG](https://github.com/bigcat88/pillow_heif/blob/master/CHANGELOG.md)），改由 Pillow 自己讀寫：Pillow 11.3 起的 wheel 內含 libavif，用 dav1d 解碼、aom 編碼（[Pillow 11.3.0 release notes](https://pillow.readthedocs.io/en/stable/releasenotes/11.3.0.html)）。專案要求 Pillow ≥ 12.3，所以：
- 資料夾裡有 `.avif`、沒有裝 pillow-heif 時，會跳「安裝 pillow-heif 以檢視 HEIC/AVIF 影像」。照做也不會有任何改變，AVIF 本來就開得了。
- 匯出、批次匯出、批次轉檔的格式清單沒有 pillow-heif 就不列 AVIF；MCP `convert_format` 轉成 `.avif` 會丟「AVIF output requires the pillow-heif package」。其實 Pillow 自己就寫得出 AVIF。
- `heif_support` 的說明寫「pillow-heif 1.x 一次註冊 HEIF 與 AVIF」，實測 1.4.0 的 `register_heif_opener()` 只註冊 `HEIF`。

**修正**：
- 新增 `image/avif_support.py`：`AVIF_EXTENSIONS` 與 `avif_available()`（`PIL.features.check("avif")`；從原始碼編譯、沒有 libavif 的 Pillow，以及 Windows ARM64 的 wheel 會回 False）。
- `heif_support.HEIF_EXTENSIONS` 拿掉 `.avif`，提示只在有 HEIC / HEIF 時出現，文字（英、簡、繁、日、韓）改成只提 HEIC。
- `formats.STILL_IMAGE_EXTENSIONS` 另外併入 `AVIF_EXTENSIONS`，能開的副檔名不變；`ensure_pillow_opener(".avif")` 不再去註冊 pillow-heif。
- `save_formats.available_formats()`：HEIC 看 pillow-heif、AVIF 看 `avif_available()`、JXL 看 pillow-jxl-plugin，順序固定為 HEIC、AVIF、JXL；`save_image` 對寫不出的 AVIF 丟「AVIF output requires a Pillow built with libavif.」。
- MCP `convert_format` 的工具說明改成 avif 內建、heic / jxl 需要選用後端。
- README ×10 與 docs ×10：CLI 的解碼說明、Save As / Export 的格式、MCP 表格；docs 的「支援格式」補上一行 AVIF / HEIC / JPEG XL，「單張匯出」的格式列表與 MCP `convert_format` 說明（quality 適用 JPEG / WebP / AVIF / HEIC / JXL）一併更新。

**驗證**：
- 新增 `tests/test_avif_support.py`：`avif_available()` 跟著 Pillow 的外掛狀態走；把 `pillow_heif` 設成無法匯入時，`load_image_file` 照樣把 `.avif` 解成正確尺寸與顏色的 RGBA。
- `tests/test_save_formats.py`：沒有 pillow-heif 時 AVIF 仍在清單上、而且真的存得出 RGBA 的 AVIF；Pillow 沒有 libavif 時 AVIF 不在清單、存檔丟出 `ValueError` 且不留檔案；四個選用格式都在時的清單順序。
- `tests/test_heif_support.py`：`.avif` 不算 HEIF，只有 AVIF 的資料夾不需要提示；`tests/test_formats.py`：`.AVIF` 不註冊任何選用 codec。
- `py -m sphinx -W --keep-going -b html docs` 無警告。

## U-20260925-63 · 2026-09-25 · Tool workers report every failure instead of leaving their dialog stuck · #fix #workers

**問題**：約三十個工具對話框各自帶一個 `QThread` worker，按下「套用」後，對話框停用按鈕、等 worker 的 `done` 訊號。但這些 worker 的 `run()` 只接 `(OSError, ValueError)`，有的再加上 `RuntimeError`／`ImportError`。以下例外會直接跑出執行緒：
- `DecompressionBombError`：超過 Pillow 像素上限的大圖，它不是 `OSError`；
- `MemoryError`；
- `cv2.error`；
- 選用後端的 `ImportError`。

這時 `done` 永遠不會發出，對話框的 `_worker` 一直不是 None，之後再按「套用」也沒有反應，只能關掉重開。共用的 `gui/_apply_save.EffectWorker` 早就因為同樣的原因改成全接並記錄，這些各自帶 worker 的對話框沒有跟上。

**修正**：
- 26 個對話框的 worker 原本就在 handler 裡 `logger.exception` 並回報失敗，改成 `except Exception`，和 `EffectWorker` 一致：
  - 單圖工具：CLAHE、HSL 混色、相框、比例尺、網點、色彩對應、扭曲、二值化、Otsu、日曬、輝光、像素排序、局部對比、背景平坦化、梗圖、證件照排版、目標大小、仿製印章、小星球、隱寫；
  - 多圖工具：立體圖、拼貼、影像堆疊、動畫編輯、列印排版；
  - 挑片對話框的自動挑片。
- OCR、套件安裝（`plugin/pip_installer._InstallWorker`）、影片擷取外掛（`video_source`）的預期錯誤原本就回報得比較安靜，不帶 traceback；這三個保留原本的處理，後面再加一層 `except Exception`，先 `logger.exception` 再回報。
- `video_source` 外掛已同步到 Imervue_Plugins 的 `main`。
- `architecture_explore.md` §10 的「Worker 邊界」補上新的檢查測試。

**驗證**：新增 `tests/test_workers_always_report.py`：
- AST 檢查 `Imervue/` 與 `plugins/` 裡每個 `QThread.run` 最上層的 `try`：都要以 `Exception`／`BaseException` 或 bare `except` 收尾，或在 `finally` 發訊號。修正前會列出 29 處。
- CLAHE worker 的 `load_rgba` 丟出 `DecompressionBombError` 時，`done` 送出 `(False, "too many pixels")`。
- OCR worker 遇到 `RuntimeError` 或 `MemoryError` 時照樣送出失敗，並留下 traceback log。
