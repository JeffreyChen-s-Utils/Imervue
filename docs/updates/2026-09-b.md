## U-20260925-68 · 2026-09-25 · Animation frames of 10 ms or less play for 100 ms, as in browsers · #fix #animation

**問題**：GIF 的影格延遲以 1/100 秒為單位，很多舊 GIF 寫的是 0 或 1（0／10 ms）。瀏覽器不照字面播：Firefox 一律把 10 ms 以下的影格當成 100 ms，Chrome 跟進，Chromium 原始碼的註解寫著「很多廣告用 0 讓圖片閃得越快越好」（[Mozilla bug 232822](https://bugzilla.mozilla.org/show_bug.cgi?id=232822)、[IEInternals: Animated GIF Timing](https://learn.microsoft.com/vi-vn/archive/blogs/ieinternals/trivia-animated-gif-timing)）。這些 GIF 本來就是照 100 ms 設計的。

`gpu_image_view/actions/animation_player._frame_duration` 只把 0 或缺值當成 100 ms，10 ms 的影格就真的播 10 ms。同一張 GIF 在 Imervue 裡比在瀏覽器快 10 倍。

**修正**：10 ms 以下（含 10 ms）的影格一律播 100 ms，和瀏覽器一致；11 ms 以上照檔案寫的播。README ×10 與 docs ×10 的動畫播放說明補上這一點。

**驗證**：`tests/test_animation_player.py` 新增參數化測試：10、1、10.0 ms 播 100 ms；11、20 ms 照原值。原本 0、None、缺值播 100 ms 的測試照常通過。

**問題**：用唯讀代理人逐節核對 docs 的「整理圖片」「圖片比對」「幻燈片」「搜尋」「動畫播放」「旋轉與翻轉」與程式，找到一個行為不一致與七處文件錯誤。

行為：
- 顏色標籤鍵 `F1`–`F5` 對多選沒有「全都已是這個顏色就清除」的規則。
  - 單張圖片時再按一次同鍵會清除（`toggle_color_label`），多選時卻永遠只是套用（`cull_actions.apply_color_label`）；
  - 評分鍵 `1`–`5` 與我的最愛 `0` 在多選時，只要全部已是該狀態就會清除（U-20260926-15），唯獨顏色鍵不行。
- 所以多選後按同一個顏色鍵，永遠清不掉；文件說「再按一次同鍵清除」也只對單張成立。

文件（英文，9 個語系跟著翻譯）：
- 「為圖片加標籤／加入相簿」寫成「右鍵 > Add to Tag / Add to Album」。
  - 單張圖片（大圖模式）的右鍵子選單其實叫 **Tags**／**Albums**；
  - 「Add to Tag / Add to Album」只在多選縮圖的右鍵 > Batch Operations 裡。
- 「依副檔名篩選」少了一層：實際是 `Filter > By Extension > JPEG / PNG / RAW`。
- 清單檢視的欄位：寫成「Star Rating」欄，實際標題是「Rating」；README 與 docs 的欄位清單都漏了 Rating 欄。
- 圖片比對：寫「選 2 到 4 張」。
  - 並排只能顯示 2 或 4 張：選 3 張時什麼都不會顯示；
  - 對話框也能直接在清單裡挑。
- 挑片對話框的路徑是 `Extra Tools > Workflow > Culling`，文件少了 Workflow 這層。
- 旋轉的選單項目寫成「Rotate CW / Rotate CCW」（程式的後備字串）；英文介面實際顯示「Rotate Clockwise / Rotate Counter-clockwise」。

**修正**：
- `apply_color_label`：多選時，若每張都已是這個顏色，就全部清除並提示「Colour label cleared」；否則全部套用。
  - 單張照舊切換；清單檢視的標記鍵走同一個函式，行為一致。
- 以上文件錯誤在 README.md 與 9 份翻譯、docs 10 個語系全部更正。
  - 顏色鍵的說明補上「多選時只有每張都已是該顏色才會清除」。
- 核對過、確認正確的部分：幻燈片、搜尋、動畫播放三節，以及評分、我的最愛、書籤、挑片按鍵等。
