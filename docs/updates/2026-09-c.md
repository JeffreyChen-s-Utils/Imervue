## U-20260926-56 · 2026-09-26 · Record U-20260926-54 lost its file names to shell quoting and was repaired in place · #incident #docs

**經過**：記錄 U-20260926-54 時，紀錄內文是放在 Bash 雙引號裡的 `py -3 -c "..."` 字串中產生的。
- 雙引號內的反引號會被 shell 當成命令替換執行。所以內文裡每一段 Markdown 行內程式碼（`tests/test_docs_parity.py`、`puppet_guide.zh-CN.md` 等）都被當成命令執行了：
  - 輸出只有「command not found」；
  - `puppet_guide.<lang>.md` 裡的 `<lang` 被當成輸入重新導向，因找不到檔案而失敗；
  - 沒有產生任何檔案，也沒有其他副作用（事後以 `git status` 與目錄檢查確認）。
- 結果寫進紀錄的是替換後的空字串：U-20260926-54 的內文少了全部的檔名與測試名稱。
- 發現後在 commit `ae474db` 直接把那筆紀錄的檔名補回去。
  - 這違反了本目錄「不改寫已記錄的條目」的規則（批次規則第 5 條），所以補記這一筆，並在 U-20260926-54 末尾加上指向本筆的註記。
  - 補回的只是被吃掉的行內程式碼，其餘文字不變。

**之後的做法**：紀錄內文一律先用檔案寫好（`*_body.md`），再由腳本讀檔組成 spec，不在 shell 字串裡內嵌含反引號的文字。

## U-20260926-57 · 2026-09-26 · 65-point and 1D LUTs load, Graduated Density offers its tint, and the library docs match the code · #fix #lut #develop #docs #i18n #Imervue_Plugins

**問題**：用唯讀代理人逐節核對 docs 的「圖庫與中繼資料管理」「進階顯影與合成」兩章與程式，找到兩個功能問題與十處文件錯誤。

功能問題：
- **`.cube` LUT 的尺寸上限寫錯**：`lut.py` 只有一個 `_MAX_CUBE_SIZE = 64`，1D 和 3D 共用。
  - Adobe Cube LUT 規格 1.0：1D 表 N ∈ [2, 65536]（6.1 節），3D 格 N ∈ [2, 256]（7.1 節）。
  - 所以常見的 1024／4096 點 1D 曲線全部被拒；DaVinci Resolve 與 ARRI 匯出的 **65³** 3D LUT 也會被拒，這是最常見的尺寸之一。
- **漸層減光鏡（Graduated Density）沒有色調可選**：
  - `apply_graduated_density` 本來就接受 `tint`（每個色版的乘數），README 也寫「with an optional tint」、docs 寫「optionally tinted」；
  - 但對話框只有角度、密度、硬度、偏移四個滑桿，從不傳 `tint`。

文件錯誤（英文，9 個語系跟著翻譯）：
- 相似圖片搜尋的欄位叫「Max Hamming distance」，不是「Max distance」。
- 自動標籤的清單漏了常見的 `auto/graphic`（不是文件、截圖或相片時就歸到這類）。

- XMP 顏色標籤：只有新的或改過的顏色才照 Lightroom 的寫法匯出；sidecar 原本就是 Bridge 的同色用詞時，會保留原用詞（`xmp_sidecar.py`）。
- 時間軸與月曆的日期來源少了一層：實際依序是 DateTimeOriginal → DateTimeDigitized → **DateTime** → 檔案修改時間。
- 鏡頭校正「不放進 recipe 是因為輸出尺寸可能改變」：輸出尺寸永遠和原圖相同，這個理由不成立。
