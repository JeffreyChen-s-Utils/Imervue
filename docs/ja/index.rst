Imervue ユーザーガイド
======================

GPU アクセラレーション画像ワークステーション。 **5 つのトップレベルタブ** を提供します。
本ガイドの大部分はこの 5 つのタブを軸に構成されています。

.. list-table::
   :header-rows: 1
   :widths: 18 82

   * - タブ
     - 機能
   * - **Imervue**
     - 画像ライブラリの閲覧・表示・整理・検索・バッチ処理。
       「画像を開く」「画像の閲覧」「画像の整理」を参照。
   * - **Modify**
     - 非破壊現像パイプライン — スライダー、カーブ、LUT、マスク、レタッチ、多画像合成。
       「画像の編集（修正タブ）」を参照。
   * - **Paint**
     - フル機能のラスター描画スタジオ。ブラシ、レイヤー、アニメ、漫画ツール、PSD I/O 搭載。
       「ペイントワークスペース（ペイントタブ）」を参照。
   * - **Puppet**
     - ゼロから構築した 2D リギング・パペットアニメーター — メッシュ、デフォーマー、パラメータ、モーション、物理。
       「Puppet ワークスペース（Puppet タブ）」を参照。
   * - **Desktop Pet**
     - フレームレス・透明・常に最前面のオーバーレイで、同じ ``.puppet`` rig を
       デスクトップ上でライブドライバー（アイドル / まばたき / マイク / ウェブカメラ /
       ドラッグ追従）付きで実行します。「デスクトップペットワークスペース（Desktop Pet タブ）」を参照。

「はじめに」「キーボードショートカット一覧」「追加ツールメニュー一覧（Extra Tools）」「プラグインシステム」
「コマンドライン」「MCP Server」の各章は横断的で、5 つのタブすべてに共通です。

**Puppet** と **Desktop Pet** は任意で使えるタブです。``File`` > ``Preferences`` > **Optional tabs** でどちらかをオフにすると、次回の起動からそのタブは追加されず、コードも読み込まれないため、Imervue の起動が速くなりメモリ使用量も減ります。どちらも既定ではオンで、それぞれ初めてタブを開いたときに構築されます。Desktop Pet タブは、ペットを起動時に表示する設定のときは起動時に構築されます。

サムネイル一覧は新しい GPU テクスチャを読み込む前に画面外のものを解放し、表示中の画像を保持しながらメモリ予算を守ります。画面端に触れるだけで表示面積がゼロの画像は容量を占有しません。

Modify は調整中にバックグラウンドで低解像度のプレビューを作成し、操作を妨げず、調整を止めると完全な画質で描画します。連続した調整や写真の切り替えでは古い結果を破棄し、注釈の座標は画像の元のサイズを維持します。保存や破壊的な効果の適用では、先に完全な画質の計算を完了します。

----

はじめに
--------

Imervue を起動すると、3 つのエリアが表示されます：

::

   ┌──────────┬──────────────────────┬──────────┐
   │ フォルダ │                      │  EXIF    │
   │ ツリー   │   画像ビューアー     │ サイドバー│
   │          │                      │          │
   └──────────┴──────────────────────┴──────────┘

- **左側**：フォルダツリー。フォルダをクリックすると中の画像を閲覧できます
- **中央**：画像表示エリア。サムネイルグリッドですべての画像を表示します
- **右側**：EXIF サイドバー。起動時は細い帯に折りたたまれており、クリックすると開きます。開いている画像の撮影情報を表示します

Imervue はセッションごとのログをプログラムの隣の ``imervue.log`` に書き込みます（プログラムのフォルダが読み取り専用の場合は ``%LOCALAPPDATA%\Imervue``、Windows 以外では ``~/.cache/imervue``）。前回のセッションのログは ``imervue.previous.log`` として残るため、クラッシュした後に Imervue を再び起動しても、その原因がわかるログが残っています。問題を報告するときは両方を添付してください。

対応画像フォーマット
^^^^^^^^^^^^^^^^^^^^

- **一般**：PNG、JPEG（.jpg、.jpeg、.jpe、.jfif、.jif）、BMP、TIFF、WebP、GIF、APNG、SVG
- **RAW**：CR2 / CR3 / CRW（Canon）、NEF / NRW（Nikon）、ARW / SRF / SR2（Sony）、DNG（Adobe）、RAF（Fujifilm）、ORF（Olympus / OM System）、RW2（Panasonic）、RWL（Leica）、PEF（Pentax）、SRW（Samsung）、3FR（Hasselblad）、IIQ（Phase One）、MEF（Mamiya）、MOS（Leaf）、ERF（Epson）、MRW（Minolta）、KDC / DCR（Kodak）
- **新しい形式**：AVIF（標準で対応）、HEIC / HEIF（オプションの ``pillow-heif`` が必要）、JPEG XL（オプションの ``pillow-jxl-plugin`` が必要）
- **その他**：ICO、TGA、DDS、QOI、JPEG 2000（.jp2／.j2k／.jpf／.jpx）、Netpbm（PPM／PGM／PBM／PNM）、PCX、PSD（統合画像） —— 表示用です。その場での回転などの書き戻しは行わないため、編集は「名前を付けて保存」/「エクスポート」で保存します

画像の閲覧
----------

サムネイルグリッドモード
^^^^^^^^^^^^^^^^^^^^^^^^

フォルダを開くと、すべての画像がサムネイルグリッドで表示されます。

.. list-table::
   :header-rows: 1
   :widths: 30 70

   * - 操作
     - 方法
   * - スクロール
     - マウスホイール
   * - パン（移動）
     - マウス中ボタンを押しながらドラッグ
   * - 拡大表示に切替
     - サムネイルを左クリック
   * - サムネイルサイズ変更
     - メニュー ``サムネイルサイズ`` > 128 / 256 / 512 / 1024 を選択
   * - サムネイル密度
     - ``サムネイルサイズ`` > ``サムネイル密度`` > コンパクト / 標準 / ゆったり
   * - ホバープレビュー
     - サムネイル上にカーソルを 500 ms 置くと拡大プレビューを表示
   * - 複数画像を選択
     - 左クリックしながらドラッグして矩形選択
   * - キーボードでサムネイル間を移動
     - 矢印キーでフォーカス枠を動かし、見える位置までスクロールします。``Enter`` で画像を開きます

サムネイルにはステータスバッジが表示されます：左端のカラーストリップ（カラーラベル）、
左上の ❤（お気に入り）、右上の ★（ブックマーク）、左下の評価星。未ロードのサムネイルは
回転するドットのプレースホルダーで表示されます。

リスト（詳細）モード
^^^^^^^^^^^^^^^^^^^^

``Ctrl + L`` でサムネイルグリッドとソート可能なリストビューを切り替えます。列：
プレビュー · ラベル · 評価 · 名前 · 解像度 · サイズ · 種類 · 更新日。行をダブルクリック
（または ``Enter``）で拡大表示モードに入り、``Esc`` でリストに戻ります。サムネイルと
メタデータはワーカースレッドで遅延ロードされるため、大量の画像があっても応答性を保ちます。

``Delete`` で選択した行を削除し、``Ctrl + Z`` で元に戻せます。評価（``1`` – ``5``）、お気に入り（``0``）、カリング（``P`` / ``Shift + X`` / ``U``）、カラー（``F1`` – ``F5``）のキーも選択した行に付きます（グリッドと同じ）。``F1`` – ``F5`` 以外のキーはショートカット設定に従います。

拡大表示モード（Deep Zoom）
^^^^^^^^^^^^^^^^^^^^^^^^^^^

サムネイルをクリックすると拡大表示モードに入り、高画質で画像を閲覧できます。

Pillow の安全上限（1 億 7900 万画素）を大きく超えるパノラマも開けます。上限はパソコンのメモリ量に合わせて決まり（16 GB なら約 14 億画素）、こうした巨大な画像は 1 枚ずつデコードします。

途中で切れた JPEG・PNG・TIFF・GIF・BMP（ダウンロードやコピーの中断、故障したメモリーカードから復旧した写真）も、開けないのではなく、ブラウザと同じく読めた部分までを表示します。

他のプログラムが画像を上書き保存すると（外部エディタによる直接の上書きでも、コピーを書いてからの置き換えでも）、ビューアは新しい版を表示します。ディープズームで開いている画像は最後の書き込みから 1 秒以内、グリッドのサムネイルとリストの行は数秒以内に更新されます。

16 ビットのグレースケール PNG / TIFF（スキャン、深度マップ、科学・天体の画像）や浮動小数点 TIFF も、ほぼ真っ白や真っ黒ではなく、ビューア・サムネイル・プレビュー・ツールで本来の明るさで表示されます。16 ビットの値は全範囲でスケーリングし、0〜1 の浮動小数点値は黒から白に、それ以外の範囲は引き伸ばして表示します。

カラープロファイルを埋め込んだ画像（スマートフォンの Display P3、カメラの Adobe RGB、CMYK、Photoshop がグレースケール画像に埋め込む Dot Gain 20% や Gray Gamma 1.8 などのグレープロファイル）は、ビューアとサムネイルで sRGB に変換して表示します。グレースケール画像はグレースケールのままです。プロファイルなし・sRGB の画像はそのまま表示します。

Windows で隠し属性の付いたファイル（エクスプローラーやフォルダーツリーでも非表示）と、ドットで始まる名前（macOS がメモリーカードやネットワークドライブで写真ごとに書く ``._photo.jpg`` など）は、サムネイル一覧、フォルダーアイコン、バッチツールのフォルダー一覧、監視フォルダー、ライブラリのスキャン、CLI、MCP サーバーのフォルダーツールから除外されます。再帰スキャンは ``$RECYCLE.BIN`` や Mac の ``.Trashes`` などの隠しフォルダーに入りません。意図して開いた隠し画像はそのまま開けます。

   * - 次の画像

   * - 番号でジャンプ

分割表示・見開き表示
^^^^^^^^^^^^^^^^^^^^

Compare ダイアログを開かずに、メインウィンドウ内で 2 枚を並べて表示：

.. list-table::
   :header-rows: 1
   :widths: 35 65

   * - 操作
     - ショートカット
   * - 分割表示（任意の 2 枚）
     - ``Shift + S``
   * - 見開き表示（現在 + 次の画像）

マルチモニターウィンドウ
^^^^^^^^^^^^^^^^^^^^^^^^

``Ctrl + Shift + M`` で副ディスプレイに枠なしの第 2 ウィンドウを開き、メインビューアーで
表示中の画像をミラーリングします。メインウィンドウは独立して閲覧を続けられます —
展示、デュアルスクリーンの編集ワークフロー、クライアントへのプレゼンに便利。
もう一度 ``Ctrl + Shift + M`` で閉じるか、第 2 ウィンドウ内で ``Esc`` を押します。

画像の整理
----------

評価とお気に入り
^^^^^^^^^^^^^^^^

拡大表示では表示中の画像を評価します。グリッドでは選択中のサムネイル、なければ矢印キーで選んだサムネイル、なければマウスの下のサムネイルを評価します（カラーラベルやカリングの対象と同じ）。対象がすべて同じ評価のときは解除します。

.. list-table::
   :header-rows: 1
   :widths: 30 70

   * - 操作
     - キー
   * - お気に入りに追加 ❤
     - ``0``
   * - 1～5 つ星で評価
     - ``1`` ``2`` ``3`` ``4`` ``5``\ （もう一度押すと解除）

カラーラベル (F1 -- F5)
^^^^^^^^^^^^^^^^^^^^^^^

1 -- 5 の星評価とは別に保存されるカラーフラグ。素早い分類に便利です（例：赤＝削除候補、
緑＝採用、青＝要レタッチ）。

.. list-table::
   :header-rows: 1
   :widths: 30 70

   * - 操作
     - キー
   * - 赤 / 黄 / 緑 / 青 / 紫
     - ``F1`` / ``F2`` / ``F3`` / ``F4`` / ``F5``\ （同じキーでクリア。選択中は、選択したすべての画像がすでにその色のときだけクリア）
   * - 選択に一括適用
     - 複数サムネイルを選択後、対応する F キーを押す
   * - 色でフィルター
     - ``フィルター`` > ``カラーラベルで絞り込み`` > 色／ラベル付き／ラベルなし

ステータスバーに現在の画像のカラーチップ、サムネイルの左端にカラーストリップ、
**リストビュー** には並び替え可能な「ラベル」列と「評価」列があり、
評価列（星）のセルをクリックするとリストを離れずに評価を設定できます。

タグとアルバム
^^^^^^^^^^^^^^

タグとアルバムで画像を分類・管理できます。

.. list-table::
   :header-rows: 1
   :widths: 30 70

   * - 操作
     - 方法
   * - 管理画面を開く
     - ``T`` を押すか ``ファイル`` > ``タグとアルバム``
   * - 画像にタグ付け
     - 拡大表示モードでは右クリック > ``タグ``\ 、選択したサムネイルでは右クリック > ``一括操作`` > ``タグに追加``
   * - アルバムに追加
     - 拡大表示モードでは右クリック > ``アルバム``\ 、選択したサムネイルでは右クリック > ``一括操作`` > ``アルバムに追加``
   * - 単一タグ／アルバムでフィルター
     - ``フィルター`` > ``タグで絞り込み`` / ``アルバムで絞り込み``
   * - 複数タグフィルター (AND / OR)
     - ``フィルター`` > ``複数タグフィルター…`` — 複数選択し「いずれか (OR)」または「すべて (AND)」を指定
   * - 整理
     - 管理画面の **整理…** ボタンは、件数を確認したうえで、存在しなくなったファイルの記録を外し、
       大文字と小文字だけが違う名前をまとめます（画像の多い方の表記が残ります）。
       タグやアルバムを作成・名前変更するとき、既存の名前と大文字・小文字または空白だけが違う名前は拒否され、タブや改行を含む名前も同様です

画像の編集（修正タブ）
----------------------

上部の **「修正」** タブに切り替えると、編集モードに入ります。拡大表示モードで右クリック > ``修正`` > ``現像 / 調整`` を選んでも、表示中の画像をこのタブで開けます。
``E`` キー（または右クリック > ``修正`` > ``注釈 / モザイク``）では、代わりに別の注釈エディタで開きます。

::

   ┌────────┬──────────────────────┬────────────┐
   │ ツール │                      │ プロパティ │
   │ バー   │ キャンバス（直接描画）│ ブラシ、色 │
   │        │                      │ 現像調整   │
   └────────┴──────────────────────┴────────────┘

これらの調整は **非破壊的** です。各スライダーは画像ごとの Edit Recipe に書き込まれ、
``リセット`` でいつでも元に戻せるほか、スライダーの下の ``元に戻す`` / ``やり直し`` で変更を
1 つずつたどれます。Recipe は再起動後も保持され、XMP sidecar
経由でエクスポート / 同期できます（メタデータのセクションを参照）。

ディスク上のファイルが変わるのは指示したときだけです。**Apply Crop** と注釈の **Save** は結果を元ファイルに書き戻しますが、EXIF（カメラ、撮影日時、GPS）、XMP、DPI は保持されます。カメラ RAW、HEIC、アニメーション / マルチページのファイルは決して上書きされず、切り抜きはエクスポートを促し、注釈の保存は新しいファイル名を尋ねます。単発のツール(CLAHE、HSL ミキサー、フォトフレーム、自動水平補正など)は結果を
元画像の横に ``photo_clahe.png`` として保存し、もう一度実行すると前回の結果を
置き換えずに ``photo_clahe_1.png`` として保存します。**EXIF で自動回転**、**EXIF 一括削除** のコピー、**ページ分割…** も同じように番号を付けます。Imervue が写真をロスレス回転する(切り抜き枠も
一緒に回る)か EXIF を書き換える(GPS ジオタグ、EXIF エディター)と、写真のレシピと
仮想コピーも付いていきます。ローカルマスク、レイヤー、レンズフレア、顔タグを含む
レシピは回転前の版に残り、元に戻せば再び使えます。

ペイントワークスペース（ペイントタブ）
--------------------------------------

3 つ目のトップレベルタブ — **ペイント** — はフル機能のペイント
ワークスペースで、複数ドキュメントタブ、ベクター・ラスターレイヤー、漫画
ツール、アニメーションフレーム、PSD インポート / エクスポートに対応します。
Undo / Redo はレイヤーの追加、削除、並べ替え、結合に加え、属性、マスク、ベクター、グループ、選択範囲、参照レイヤーの状態を復元します。レイヤーメニュー、レイヤーパネル、漫画レイヤー、素材挿入の操作はそれぞれ履歴に記録され、文書ごとに独立した履歴を保持します。

Paint の各文書は、現在の基準状態と Undo/Redo の分岐を含めて 512 MiB の容量内で最大 50 ステップの履歴を保持します。変更のないピクセルは共有し、ブラシと消しゴムは変更されたタイルだけを保存します。上限に達すると古いステップを削除します。文書の単一スナップショットが上限を超える場合は履歴を消去しますが、編集可能な文書は保持します。

Paint に切り替えても、ドキュメント、レイヤー、未保存の変更、元に戻す履歴は保持されます。初回は空白のキャンバスが開きます。``File > Open Current Image in Paint``\  で、ビューアーの画像を新しいドキュメントとして開けます。Paint のメインタブバーの左／右キーも、前／次のビューアー画像を新しいドキュメントとして開きます。ディープズームの ``E``\  は別の注釈エディタを開きます。

使い勝手の工夫 — ペイントワークスペースには、ズームに合わせて大きさが変わる
ブラシサイズカーソル、ツールごとに異なるカーソルアイコン、キャンバスの下に敷く
透明を示す市松模様、ドラッグ＆ドロップ時のハイライト表示、タブごとの変更済み
アスタリスク、元に戻す / やり直しのトースト通知、ステータスバーの自動保存
表示、そして前回クラッシュしたセッションのスナップショットを起動時に提示する
自動保存復元プロンプトが備わっています。

上級者向けホットキー：``Tab`` ですべてのドックの表示を切り替えて描画に集中、
``Ctrl+Tab`` でタブを巡回、``,`` / ``.`` でブラシの種類を巡回、``0–9`` で
ブラシの不透明度を 10 % 刻みで設定、``Alt+[`` / ``Alt+]`` でアクティブ
レイヤーを 1 つずつ切り替えます。キャンバスを右クリックすると、元に戻す /
やり直し / すべて選択 / 選択解除 / 全体表示 / 100 % のクイックメニューが開きます。

カラードックには「透明 / 色なし」スロットがあり（背景色の既定値 = 透明）、
塗りつぶしと自動選択はどちらもアルファの境界を尊重するため、消去した
ピクセルが塗り直し時ににじみ出ることはありません。カラースロットの下には、
彩度 / 明度の三角形を囲む色相リングがあります。リング上をドラッグすると色相を、
三角形の中をドラッグすると色合いを選べ、HSB / RGB スライダーと HEX 欄が
それに追従します。ほかの場所で色を設定すると、ホイールのマーカーもその色の
位置へ移動します。**スウォッチドック** には最近使った色か、その上のボックスで
選んだパレットが表示されます。パレットは組み込みの Standard、Pastel、Manga か、
自分で作ったものです。**パレットとして保存…** は最近使った色に名前を付けて
保存し、**パレットを削除** は自分のパレットを 1 つ削除します（組み込みの
パレットは残ります）。``フィルター`` > ``スウォッチに合わせる…`` は、ドックに
表示されている色で塗り直します。

::

   +------+----------------------+----------------+
   |ツール|                      | カラー · ブラシ|
   | バー |   キャンバス（描画） | レイヤー · ナビ|
   |      |                      | 素材 · …       |
   +------+----------------------+----------------+

右側の 14 個のドックは単一の列にタブ化され、キャンバスは可視高さ全体を
保てます。ドックは 3 つのグループに分かれています：

- **描画** — カラー、ブラシ、バケツ、スウォッチ
- **キャンバス** — レイヤー、ナビゲーター、ヒストリー、ページ、アニメーション、ヒストグラム
- **ライブラリ** — 素材、スタンプ、ポーズ、リファレンス

各ドックは ``ウィンドウ`` メニューから個別に表示 / 非表示を切り替えられます。
任意のドックタイトルをドラッグして再配置 / フロート化できます。``設定`` >
``ワークスペース…`` はどのドックを表示しているかを記憶します
（*ワークスペースレイアウト* を参照）。

ブラシ
^^^^^^

.. list-table::
   :header-rows: 1
   :widths: 25 75

   * - ブラシ
     - 効果
   * - 鉛筆
     - 細くて少し質感のある鉛筆線
   * - ペン
     - 鋭いアンチエイリアス線。日常使い
   * - マーカー
     - 重ね塗りで濃くなる半透明の太い線
   * - エアブラシ
     - 散らばる点が重なって柔らかなスプレーになる
   * - 水彩
     - 縁に顔料がたまったような、内側が明るいにじみの縁
   * - 墨
     - かすれた縁を持つ書道風の墨線

Crayon、Highlight、Sumi calligraphy はこれらの種類をベースにしたブラシ
プリセットです。各ブラシは **ブラシドック** で サイズ / 不透明度 / 硬度 /
密度 / 描画モード を調整でき、上部 **オプションバー** には サイズ / 不透明度 /
硬度 があります。タブレットペンの筆圧は ``設定`` > ``筆圧カーブ…`` で設定した
カーブに従ってブラシのサイズと不透明度を変化させます（点をドラッグ、クリックで追加、
右クリックで削除、または リニア / ソフト / ハード から開始）。マウスでは常に最大
筆圧で描画されます。ブラシドックの **散布** はブラシのダブ一つひとつを、
ブラシサイズに対する設定値の割合を上限としてストロークからずらし、
**カラージッター** はダブごとに色相・彩度・明度を変え、**ペンの傾きに追従** は
タブレットペンが傾いた方向と直交する向きに先端を細め、
傾きに合わせて先端の向きを変えます（Sumi calligraphy プリセットではオンになっています）。
ピクセルアートブラシは正方形の先端のままです。``編集`` > ``選択範囲からブラシ形状を取得…`` で選択範囲をカスタム
ブラシ先端に変換できます。**素材ドック** には、組み込みのトーンやテクスチャより
先に自分の素材が並びます。Imervue のプログラムのフォルダにある ``materials``
フォルダ内の画像（その直下に ``texture``、``tone``、``pattern``、``brush_tip``、
``pose`` という名前のフォルダを作ると、中の画像はそのカテゴリに分類されます）と、
取得したブラシ先端です。``編集`` > ``選択範囲を素材として保存…`` は、表示中の絵の
選択部分を、指定した名前とカテゴリでそこに保存します（選択範囲外のピクセルは透明に
なり、同じ名前の既存の素材は上書きされずに残ります）。保存した素材はすぐにドックに
表示されます。

レイヤー
^^^^^^^^

**レイヤードック** はサムネイル、表示切替、その場リネーム、↑ / ↓ ボタンによる
並び替え（または ``Ctrl + ]`` / ``Ctrl + [``）、アクティブレイヤーのブレンド
モードと不透明度を提供します。``レイヤー`` メニューにはさらに：

- **新規 / ベクター / 複製 / 下に結合**\ （``Ctrl + Shift + N`` /
  ``Ctrl + Shift + V`` / ``Ctrl + J`` / ``Ctrl + E``）
- **マスク** — 追加 / 選択範囲から / 反転 / 適用 / 削除
  （``Ctrl + Shift + M`` 追加；``Ctrl + Alt + Shift + M`` 選択範囲から）
- **クリッピングマスク** — アクティブレイヤーのクリッピングを切り替え、下の
  レイヤーの alpha でクリップ（``Ctrl + Alt + G``）
- **レイヤー効果** — ドロップシャドウ / アウターグロー / 縁取り、効果クリア
- **参照レイヤー** — **塗りつぶし** バケツが色を照合する参照元として 1 つの
  レイヤーを固定
- **1-bit レイヤー** — 線画用に二値化レイヤーへ切替
- **色でレイヤー分割** — 単色塗りを色ごとに分割、塗り直しが容易に
- **グラデーションマップ** — プリセット（セピア / 夕焼け / シアノタイプ …）

選択範囲
^^^^^^^^

矩形 / 投げ縄 / 自動 / クイック選択ツールを使い、``編集`` メニューの
**選択範囲を縁取り…** で、ダイアログの「幅」と「配置」に従って前景色で
境界を描画。``Q`` で **クイックマスクモード** を切り替え、任意のブラシで
赤い領域として境界を整え、再度 ``Q`` で選択範囲に戻します。

アニメーション
^^^^^^^^^^^^^^

**アニメーションドック** はドキュメントをフレーム列に変えます：

- ``+ フレーム`` で統合した絵を新しいフレームとして保存。
- フレームサムネイルをクリックすると、そのフレームをアクティブレイヤーに読み込み。
- ``オニオンスキン``\ （表示メニュー）で前のフレームを薄く重ね表示。
- ``▶ 再生`` で選んだ FPS でフレームを順に表示。
- ``書き出し…`` でフレームをアニメーション GIF、WebP、PNG として保存。
  形式は選んだファイルの種類で決まり、種類のない名前は GIF になります。
  各フレームの長さは選んだ FPS の 1 コマ分です。WebP は可逆で書き出し、
  GIF は各フレームを 255 色に減らし、アルファの低い薄い画素を透明にします。

     - ``Ctrl + Shift + P`` — キャンバスを 行 / 列 / ガター / 枠線 / 余白 でコマ割り。ブラシのオプションバーで **コマにスナップ** をオンにすると、以降の各ストロークは描き始めたコマの中に収まります（キャンバスサイズが変わるまで）
   * - トーンレイヤー切替
     - アクティブレイヤーをスクリーントーン化
   * - ページ番号スタンプ
     - 複数ページに番号を押印
   * - 集中線
     - 放射 / 平行 / 爆発 の 3 種の集中線生成
   * - アクションフラッシュ
     - 漫画風の爆発 / 衝撃のフラッシュ
   * - 選択範囲に沿ったテキスト…
     - 選択範囲の輪郭に沿ってテキストを新しいレイヤーに配置 — テキスト、フォント、サイズ、色、太字、斜体は「テキストを追加」ダイアログで指定

フィルター
^^^^^^^^^^

スライダーが 1 本だけのフィルター（ポスタリゼーション、二値化、ハーフトーン化、
色の一致）は、ドラッグ中にレイヤー中央の 480 × 480 ピクセルを原寸で
ライブプレビューし、OK でその値をレイヤー全体に適用します。それ以外は、
シンプルな OK / キャンセルのパラメータダイアログを開きます：

- **レベル補正** — 黒点 / 白点 / ガンマ スライダー
- **トーンカーブ** — プリセット（S カーブ、シャドウを持ち上げ、ハイライトを圧縮）と強さスライダー
- **ポスタリゼーション** — 色を N 段階に量子化
- **二値化** — しきい値でモノクロ化
- **オートカラーバランス** — グレーワールド / ホワイトポイントでキャストを除去
- **フィルムグレイン** — 粒径と量を調整できる輝度ノイズ
- **ハーフトーン化** — 新聞風のドットスクリーン
- **色の一致** — 参照画像を選ぶよう求め、その画像の色の雰囲気をレイヤーに与えます（各チャンネルが参照画像の平均と広がりを受け継ぎます）。\ **強さ**\ で変化なしから完全な一致までをブレンドします
- **スウォッチに合わせる** — すべてのピクセルをスウォッチドックで最も近い色で塗り直します（先に色を選ぶかインポートしておきます）

表示補助
^^^^^^^^

- **ピクセルグリッド**\ （``Ctrl + Shift + '``）— 高倍率で 1 ピクセルグリッドを重ね表示
- **ピクセルにスナップ / エッジにスナップ** — ピクセルにスナップはブラシのダブを整数ピクセル上に置き、エッジにスナップは点を近くのキャンバスやレイヤーの端に吸着させます
- **オニオンスキン** — 前のアニメーションフレームを重ね表示
- **裁ち落としガイド** — 印刷の裁ち落とし / セーフゾーン
- **キャンバス回転**\ （``Ctrl + Shift + H``）— 非破壊的なビュー回転

ファイル I/O
^^^^^^^^^^^^

- **新規キャンバス…** — 選んだサイズの新しいタブを白または透明の背景で開きます。サイズは用紙・漫画・画面のプリセット（A4、B5 漫画原稿、1080p、4K …）、**プリセットとして保存…** で保存したもの、または最大 16384 px までの任意の幅と高さから選べます（**新しいタブ**\ （``Ctrl + N``）は引き続き既定の 1024 × 1024 の白いキャンバスを開きます）
- **PSD を開く…**\ （``Ctrl + O``）はファイルを 1 枚のレイヤーに統合して新しいタブで開きます。
  **PSD として保存…**\ （``Ctrl + S``）はレイヤーをブレンドモード付きで書き出します（マスクとレイヤー効果は含みません）
- **画像をエクスポート…** — 平坦化して、選んだファイル形式に応じて PNG・JPEG・WebP・TIFF・BMP で保存（透明度を持たない JPEG と BMP は白背景に合成）。タブを保存済みにするのは **PSD として保存…** だけで、エクスポートした後も Imervue を閉じるときにはタブの未保存の変更について確認します
- **ページをエクスポート → CBZ** / **→ PDF** — 漫画プロジェクトのページを書き出し。**コミックプロジェクトを保存…** は漫画全体を、全ページのレイヤーも含めて 1 つの ``.imervue-proj`` ファイルに保存し、**コミックプロジェクトを開く…** でそれを再び開けます
- **ブラシプリセットをインポート…**、**パレットをインポート…** — 他のインストールやアプリからブラシとパレットを取り込み
- **自動保存** — 変更された各文書を 2 分ごとに保存し、文書ごとに最新の 8 世代を保持します。**File > Restore Autosave** は最新の読み取り可能な版を新しい変更済みタブで開き、現在の編集を保持します。最新のスナップショットが壊れている場合は古い版を試します。ネイティブ保存は漫画のコマのクリッピングも保持します。ステータスバーはアクティブ文書の最終保存時刻を示し、書き込み失敗を通知します。タブを閉じるとその文書自身のスナップショットだけを削除します。

ワークスペースレイアウト

Puppet ワークスペース（Puppet タブ）
-------------------------------------

4 番目のトップレベルタブ — **Puppet** — はゼロから構築した 2D リギング・パペットアニメーションシステムです。メッシュ変形リギング、パラメータ、モーション、物理、表情、ポーズグループ、リップシンク、ウェブカメラ追跡を、**プロプライエタリ SDK なし**、``live2d-py`` **なし**、完全にオープンな ``.puppet`` ファイルフォーマットで実現します。

.. note::

   エンドツーエンドのチュートリアル（新規インストールから OBS ライブ配信または MP4 出力まで）は
   リポジトリルートの ``puppet_guide.md`` にあります（中国語版は ``puppet_guide.zh-TW.md`` /
   ``puppet_guide.zh-CN.md``）。本章はリファレンス、ガイドはステップバイステップ解説です。

::

   +-----------+----------------------+----------------+
   | ツールバー|                      | Parameters     |
   +-----------+   GL キャンバス      | ドック         |
   |           |                      |                |
   +-----------+----------------------+                |
   |               Motions ドック                      |
   +---------------------------------------------------+

右側のドックは 1 つのタブ領域を共有します：**Parameters**\ （パラメータごとのスライダー）、**Expressions**\ （各表情のオン／オフ）、**Pose**\ （各ポーズグループで表示するメンバーを選択。別のメンバーを選ぶまではグループの最初のメンバーを表示）、**Bones**\ （デフォーマー階層）。

エンドツーエンドのワークフロー
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

1. **PNG をインポート** — ``File`` > ``Import PNG…`` が ``puppet.auto_mesh.puppet_from_png`` を実行：アルファ境界の三角化、単一 drawable、即レンダリング可。
2. **デフォーマー追加** — ``Edit`` > ``Add Rotation Deformer``\ （アンカー + 角度）または ``Add Warp Deformer``\ （行 × 列の双線形格子；境界外の頂点はそのまま）。
3. **パラメータ追加** — ``Edit`` > ``Add Parameter`` で右側の **Parameters** ドックにスライダー追加（自動命名 ``Param1``、``Param2`` …）。
4. **キー設定** — スライダーを片端まで動かし、デフォーマーの form をコードで編集して **Set key**。中立値と反対端でも繰り返し。Runtime はスライダー移動時に隣接キー間で各フィールドを補間します。**Set key** が記録するのはデフォーマーの form だけです：**Edit mesh** は drawable の rest 頂点そのものを動かすため、メッシュ編集はキーになりません。
5. **保存** — ``Save As…`` で rig + テクスチャ + モーション + 表情 + 物理を 1 つの ``.puppet`` zip に書き出し。

サンプル
^^^^^^^^

リポジトリ同梱のフルリグ済みデモ：``examples/puppet/imeru.puppet`` — Imervue オリジナルのマスコット **Imeru**。すべて ``examples/puppet/imeru/build.py`` が作成します（``py -3`` で実行するとファイルを再生成。Blender 4.2 以降が必要）。髪、体、衣装、腕は Blender でモデリングし、3D のアニメ調ゲームのシェーディング技法（なめらかな代理形状の法線でライティングした髪、描き込んだ毛束とハイライトのストローク、ベイクしたオクルージョン）でセルシェーディングを行ってパペットのレイヤーごとに 1 枚ずつレンダリングし、顔は SDF フェイスシャドウマップで陰影を付け、目、眉、口は 3D ゲームのキャラクターのように描き込み、そのうえでレイヤーをリギングしているため、デモにサードパーティーの権利は含まれません：1024 × 1336 のキャンバス上に 45 個の drawable、Live2D 風の視差頂点モーフによる頭の振り向き、光から顔をそむけるにつれて形が変わる顔の影、白目にクリップされた虹彩、rotation deformer で組んだ 2 関節の腕、髪を揺らす 3 本の物理チェーン。

Cubism 標準パラメータすべて（``ParamAngleX/Y/Z``、``ParamEyeLOpen/ROpen``、``ParamBreath``、``ParamMouthOpenY`` …）に加えて腕用の ``ParamArmLA/LB/RA/RB`` を持つため、標準入力ドライバ（ウェブカメラ、まばたき、リップシンク、カーソル追従）が rig 固有設定なしで動きます。同梱モーションは 8 個：``Idle`` グループにループ再生の待機モーション 2 個、``TapHead`` に ``tap_head``、``TapBody`` に ``shy``\ （頭や体をクリックすると再生）、``Gesture`` に ``greet``、``wave``、``surprised``、``sleepy``。あわせて表情 7 個（smile、happy、surprised、sad、angry、blush、sleepy）も入っています。

Puppet タブのツールバー → **Examples ▾** ドロップダウンから直接 Imeru（``imeru.puppet``）や自分の ``.puppet`` を開けます。下部の **Motions** ドックでモーションをクリックして再生。

**同梱サンプルの実行手順：**

1. **Imervue を起動**。ソースから：``python -m Imervue``。パッケージ版：``Imervue`` 実行ファイル / app bundle を直接起動。``examples/`` ディレクトリは Nuitka 版と PyInstaller 版にバンドルされています。pip / wheel でのインストールには含まれません（ソースチェックアウトでは rig は ``examples/puppet/`` にあります）。
2. ウィンドウ上部の **Puppet** タブをクリック。
3. **File > Examples > Imeru**\ （またはツールバーの **Examples ▾** ドロップダウン）。rig が中央にロードされ、パラメータドックがその rig のスライダーで満たされます。
4. 下部の **Motions** ドックでモーションエントリ（``idle_look``、``wave``、``tap_head`` …）をシングルクリック。即座に再生開始；もう一度クリックすると最初から再生し直し、ドックの **Stop** ボタンで停止、別のモーションを選ぶとクロスフェード。
5. ツールバーのライブ入力トグルを切り替えて自分の入力で rig を動かす — **Drag-track head**\ （カーソルがキャンバス上を動くと頭と目がその方を向く）、**Auto-blink**\ （自動まばたき）、**Auto idle** + **Idle motions**\ （呼吸 + ランダム idle モーション）、**Mic lip-sync**\ （マイク RMS から口の開閉）、**Webcam tracking**\ （MediaPipe FaceLandmarker による頭 / 目 / 口の追跡）。
6. ツールバーの **Reset to rest** で全モーション停止、全ライブドライバ OFF、expressions / pose オーバーライドをクリア、全パラメータをデフォルトに戻します — 標準の「最初からやり直し」ボタン。
7. 別の rig を後で開く場合：**File > Open Puppet…** でディスクから任意の ``.puppet`` zip を開く；**File > Examples ▾** は常に同梱リストにバインドされます。

``.puppet`` ファイルフォーマット（v1）
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

``.puppet`` ファイルは zip アーカイブです：

::

   imeru.puppet
   ├── puppet.json              # 必須 — マニフェスト、drawables、deformers、parameters
   ├── textures/
   │   ├── face.png             # drawables[].texture から参照
   │   └── body.png
   ├── motions/                 # 任意
   │   ├── idle.json
   │   └── wave.json
   ├── expressions/             # 任意
   │   └── smile.json
   └── physics.json             # 任意

トップレベルの ``puppet.json`` の例：

::

   {
     "version": 1,
     "size": [2048, 2048],
     "drawables": [ ... ],
     "deformers": [ ... ],
     "parameters": [ ... ],
     "motions": ["idle", "wave"],
     "expressions": ["smile"],
     "pose": {"groups": [ ... ]},
     "physics": "physics.json"
   }

完全な仕様（drawables、deformers、parameters、motions、expressions、pose、physics）はリポジトリの ``Imervue/puppet/FORMAT.md`` にあります。JSON + PNG のみ — プロプライエタリなバイナリはなく、git で差分を完全に追跡できます。

フォーマットはオープンで、機械的に検証できます：

- 保存された ``.puppet`` は ``application/vnd.imervue.puppet+zip`` を格納した無圧縮の ``mimetype``
  エントリで始まるため、プログラムは先頭のバイトからそれと判別できます。
  また、すべての JSON ファイルは ``$schema`` で自身の JSON Schema を示します。
- 4 つの JSON Schema（draft 2020-12）— ``puppet``、``motion``、``expression``、``physics`` — を
  ``docs/schemas/`` で公開しています。``$schema`` に従うエディターでは、入力中にファイルが検証されます。
- ``py -m Imervue.cli puppet-validate examples/puppet/imeru.puppet``\ （MCP ``puppet_validate``）は、スキーマ、
  ローダーの規則、rig チェックに照らしてファイルを検証します。
  ``puppet-schema``\ （MCP ``puppet_schema``）はスキーマを表示します。
- ``docs/examples/read_puppet.py`` は Python 標準ライブラリだけで ``.puppet`` を読み込む、
  他のプログラム向けのリファレンスです。
  仕様とスキーマは MIT ライセンスなので、どのプログラムでもこのフォーマットを読み書きできます。
- より新しいフォーマットバージョンのファイルは、使われているバージョンを示して読み込みを拒否します。
  そのため古い Imervue は誤って読み込まず、更新を促します。

カスタムモーションの録画
^^^^^^^^^^^^^^^^^^^^^^^^

キーフレームを手動で打つ代わりに、ライブ take を録ります：

1. **Output > Record motion** をオン — 名前ダイアログ表示。
2. 録画中にスライダーを動かす、**Webcam tracking** を有効に、物理を動かす — パラメータ値を書く動作は何でも OK。
3. **Record motion** をオフ — レコーダーが 30 Hz ストリームをベイクして ``Motion`` 化（実際に動いたパラメータごとに 1 つの linear-segment トラック、変動なしのトラックは破棄）。新しいモーションが下部 **Motions** ドックに即表示。

カスタムモーションは手動オーサリングしたモーションと同じ ``motions/<name>.json`` JSON ペイロードで保存されます。

**Edit > Edit motion…** を選ぶと、モーションプレイヤーに読み込まれているモーションのタイムラインが開きます。キーやベジェハンドルをドラッグする、**イージング** と **このトラックに適用** で選んだトラックを名前付きのイージングに整形する（31 種類のカーブ。elastic と bounce は 1 セグメントあたり 16 個の linear キーになります）、または **キーを間引く** で 30 Hz の take を間引く、のいずれかを行えます。**キーを間引く** は、前後のキーを結ぶ線から許容誤差（各パラメータの範囲に対するパーセンテージ）以内にあるキーをすべて削除します。

OBS ライブ配信
^^^^^^^^^^^^^^

2 つの出力パス。どちらもキャラクターのみを off-screen framebuffer にレンダリング（市松模様の背景もエディタ chrome も含まれない）して配信先に渡します。出力の長辺は 1080 px までキャップ（高さ 3000–8000 px になることも多い Cubism ネイティブキャンバスが DirectShow 仮想カメラドライバに拒否されるのを防ぐ）。

**A. 仮想カメラ** — OBS の「映像キャプチャデバイス」ソース一覧にウェブカメラとして表示。``pip install pyvirtualcam`` + プラットフォーム別ドライバ：OBS Studio 26+（Windows / macOS）に *OBS Virtual Camera* ドライバ同梱（OBS 初回起動で *Start Virtual Camera* クリックして登録）；Linux は ``v4l2loopback-dkms`` + ``modprobe v4l2loopback exclusive_caps=1 card_label="Imervue"``。**Output > Virtual camera** メニューのトグルで配信開始。

DirectShow / AVFoundation / v4l2loopback はすべて **RGB のみ・アルファチャンネルなし** のため、Imervue はキャラクター外の領域を **マゼンタ #FF00FF** で塗ってクロマキーとします。OBS で除去：

1. 映像キャプチャデバイスソースを右クリック → **フィルタ**
2. **エフェクトフィルタ > + > Color Key**
3. **Key Color Type** = ``Custom Color``、**Custom Color** = HEX ``FF00FF``、**Similarity** = ``80–300``、**Smoothness** = ``30–50``

フィルタはソースに付随するため、仮想カメラを再開するたびに自動適用されます。

**B. NDI 出力** — LAN 上 < 50 ms 遅延・ネイティブ RGBA、OBS / vMix が自身のシーンに直接合成でき、クロマキーパス不要。``pip install ndi-python`` + `NDI Tools <https://ndi.video/tools/>`_ ランタイム + `obs-ndi <https://github.com/obs-ndi/obs-ndi/releases>`_ プラグイン。**Output > NDI output** メニューのトグルで配信開始（デフォルトソース名 *Imervue Puppet*）。

``ndi-python`` はソース配布のみで、pip が C++ からビルドします。Windows ユーザーは Visual Studio Build Tools 2022（C++ ワークロード）、CMake を PATH に、NDI SDK（<https://ndi.video/for-developers/ndi-sdk/> から取得、NDI Tools とは別物）をデフォルト場所にインストール、環境変数 ``NDI_SDK_DIR`` を SDK に向ける必要があります。

詳細な手順とトラブルシューティングは ``puppet_guide.md`` § 1.2 を参照。

オプション依存
^^^^^^^^^^^^^^

* ``sounddevice`` — リップシンク用マイク
* ``opencv-python`` + ``mediapipe`` — ウェブカメラ顔追跡
* ``imageio-ffmpeg`` — MP4 / WebM 録画（既にスライドショー動画用に同梱）
* ``pyvirtualcam`` — 仮想カメラ出力（「OBS ライブ配信」参照）
* ``ndi-python`` — NDI 出力（「OBS ライブ配信」参照）
* ユーザー提供 Cubism Native SDK DLL — ``.moc3 → .puppet`` 変換（Live2D Free Material License により再配布不可；``<cwd>/sdk/`` に置くか ``CUBISM_CORE_DLL`` 環境変数を設定）

Python パッケージが不足していても Puppet タブは優雅にフォールバック — 該当トグルはオフのままで依存関係インストーラーが開き、インストールを提案します。インストールが終わるとトグルがオンに戻ります。テキストのヒントが出るのは、パッケージはあるのにデバイスやドライバーが失敗した場合だけです。**File > Install dependencies…** ですべての Python オプションパッケージを一括インストール。

デスクトップペットワークスペース（Desktop Pet タブ）
----------------------------------------------------

タブ 5 — **Desktop Pet** は、任意の ``.puppet`` キャラクターを、フレームレスで透明なオーバーレイとしてデスクトップに表示します。タブ自体はコントロールパネルであり、実際のキャラクターは独立したトップレベルウィンドウとして、Puppet ランタイム全体（モーション、表情、物理、アイドルドライバ、マイク / ウェブカメラ入力）を共有しています。ペットはクリックに反応したり、タイマー駆動のアニメーションを再生したり、カーソルを追いかけたり、他のアプリがフルスクリーンのときに隠れたり、JSON ファイルで書いた独自のセリフを話したりできます。

本章はこのタブの完全なリファレンスです。章は次のように構成されています。

#. **クイックスタート** — 「Imervue を開いたばかり」から「デスクトップにパペットがいる」までの 5 ステップ。
#. **rig の読み込み** — ファイルピッカー、同梱サンプル、起動間の復元。
#. **オーバーレイウィンドウ** — ウィンドウレベルのすべての挙動（ドラッグ移動、エッジスナップ、クリックスルー、アンカーロック、常に最背面、フルスクリーン時非表示、非表示時一時停止、不透明度、サイズ、マルチモニター復元）。
#. **インタラクションモデル** — 左クリックのヒットエリア、右クリックコンテキストメニュー全体、システムトレイ。
#. **ライブドライバ** — 7 つの入力ドライバ（うち 3 つはデフォルトでオン）と、それぞれのオプション依存。
#. **ペットスクリプト** — ペットの声を自分のセリフで置き換え、リマインダーをスケジュールし、ヒットエリア / モーションごとに応答をバインドするための JSON ファイル。
#. **永続化** — 起動間に記憶される項目と、設定スキーマの詳細。
#. **新しいペットの作成** — Puppet タブと ``.puppet`` ファイル形式へのポインタ。
#. **トラブルシューティング** — よくある驚きと対処法。

クイックスタート
^^^^^^^^^^^^^^^^

1. **Desktop Pet** タブに切り替えます。
2. **Load bundled Imeru** をクリックして同梱キャラクターを使うか、**Open Puppet…** で自分の ``.puppet`` ファイルを選びます。
3. オーバーレイがデスクトップに現れ、**Show pet on desktop** チェックボックスが自動的にオンになります。（Imervue を閉じずにペットだけ隠したいときは、このチェックを外すか、システムトレイアイコンを使ってください。）
4. キャラクターを好きな位置までドラッグします。画面端の近くで離すと、その端にぴったりスナップします。
5. **Live drivers** — アイドル呼吸、まばたき、カーソル追従、マイクリップシンク、ウェブカメラトラッキング — を、ワークスペースタブまたはペットの右クリックメニューから選びます。

設定はすべて次回起動時も保持されるので、ステップ 5 は rig / ペルソナごとに一度だけ決めればよい設定です。

rig の読み込み
^^^^^^^^^^^^^^

タブには 3 つの読み込み経路があります。

* **Open Puppet…** — ディスク上の任意の ``.puppet`` ファイルを選びます。
* **Load bundled Imeru** — ``examples/puppet/imeru.puppet`` 配下に同梱されている rig を開きます。リゾルバはまず ``examples_dir()`` を検索し（パッケージ化された Nuitka / PyInstaller 版ではプログラムの隣、ソースチェックアウトではリポジトリのルート）、見つからなければ現在の作業フォルダーからの相対パスにフォールバックします。
* **Last rig** — 前回読み込んだ rig は、設定の ``last_rig_path`` フィールドから Imervue 起動時に自動復元されます。Desktop Pet タブはオーバーレイを目に見えない形で再生成するので、前回終了時と同じ状態からワンクリックでペットを再表示できます。

読み込みに成功すると **Show pet on desktop** が自動的にオンになり、ペットが即座に現れます。失敗した場合はチェックボックスはそのままで、エラーがタブのステータスラベルに表示されます。

オーバーレイウィンドウ
^^^^^^^^^^^^^^^^^^^^^^

キャラクターは Imervue メインウィンドウとは別のトップレベルウィンドウに存在します。このウィンドウはフレームレスでタスクバーエントリを持たず、（デフォルトでは）他のすべてのウィンドウの上に表示されます。

.. list-table:: ウィンドウの挙動
   :header-rows: 1
   :widths: 28 72

   * - 挙動
     - 詳細
   * - フレームレスオーバーレイ
     - ウィンドウ装飾なし、最小化 / 閉じるボタンなし、タスクバーエントリなし。キャラクター自体が可視サーフェスのすべてです。
   * - 透明背景
     - キャラクターが覆っていない部分は完全に透明です。背後のデスクトップ / アプリがピクセル単位でそのまま透けて見えます。
   * - ドラッグ移動
     - 本体のどこでも左クリックで押し、ドラッグして離します。カーソルの移動が 6 ピクセル未満ならクリックとして認識され、それ以上動かすとジェスチャは移動として扱われ、クリックハンドラは発火しません。
   * - エッジスナップ
     - 画面端の近く（デフォルト: 24 px 以内）で離すと、ペットがその端にぴったり「カチッ」と吸着します。しきい値は 0（オフ）から 200（非常に粘着）まで設定可能です。スナップは軸ごとに独立して動作するので、コーナーへドラッグすれば両端に同時にドックします。
   * - 行き過ぎクランプ
     - 画面端を超えた位置で終わったドラッグは内側にクランプされます。掴み直せないオフスクリーンにペットを置き去りにすることはできません。
   * - クリックスルーモード
     - 有効にすると、すべてのマウスイベントがペットを通過して背後のものに渡ります。キャラクターは表示されたままですが、ドラッグも右クリックもモーション発火もできません。純粋に装飾として置いておきたいときに使います。
   * - 位置ロック
     - クリックスルーに影響を与えずにドラッグ移動を無効化します。ペットをちょうど良い位置に置き、誤ドラッグで動かしたくないときに便利です。
   * - 常に最背面
     - ペットを常に最前面から常に最背面に切り替えます。ペットは他のすべてのウィンドウの後ろにデスクトップウィジェットのように座ります。フォーカス受け入れフラグも解除されるので、ペットをクリックしてもウィンドウが浮上しません。
   * - フルスクリーン時に非表示
     - 1 Hz のバックグラウンドポーリングが、ペットのいるモニターの最前面ウィンドウを監視します。そのウィンドウが画面の 99% 以上を、エッジごとの許容 4 px 以下で覆っているとき（真のフルスクリーンとボーダーレスウィンドウのゲームの両方をキャッチ）、ペットは自動的に隠れます。フルスクリーンが終わるとペットは元の位置に戻ります。検出は Windows では Win32 ``GetWindowRect`` API を使用し、macOS / Linux ではグレースフルに何もしません（ペットは表示されたままになります）。
   * - 非表示時に一時停止
     - 約 30 FPS の描画ティック、1 Hz のスクリプトティック、フルスクリーンのポーリング（ペットを隠したのがフルスクリーンでない場合）が ``hideEvent`` で停止し、次の ``showEvent`` で再開します。ライブドライバのタイマー（まばたき、アイドル、アイドルモーション、視線）は動き続けます。
   * - サイズプリセット
     - Small（200 × 300）、Medium（320 × 480）、Large（480 × 720）。ペットは現在の中心を基準にリサイズされるので、サイズ変更でペットが移動することはありません。リサイズ後にスナップが再実行されます。
   * - 不透明度スライダー
     - 10 〜 100%。``setWindowOpacity`` 経由でウィンドウレベルで作用するので、テクスチャだけでなくペット全体がフェードします。最低 10% の下限は、ペットを常に見て掴めるように設定されています — 完全に不可視にするとペットを見失う恐れがあるためです。
   * - 位置メモリ
     - リリースごとのスナップ後の ``(x, y)`` が、そのときペットがいるモニターと一緒に永続化されます。次回起動時、ペットはその位置に、そのモニターの内側にクランプされて戻ります。そのモニターがなくなっている場合（前回起動以降に抜いたなど）、ペットは最初のスクリーンに移り、保存された位置がそのスクリーン内にクランプされます。右下隅を使うのは、位置が一度も保存されていない場合だけです。

インタラクションモデル
^^^^^^^^^^^^^^^^^^^^^^

ペットは 3 つの独立したチャンネルでマウス入力に応答します。

**本体を左クリック**

クリック位置はパペットキャンバス座標に逆マッピング（キャンバスのパン / ズームを元に戻す）され、既存の ``hit_test`` パイプラインを通ります。結果に応じて以下のように動作します。

#. ``HitArea`` がクリックされた drawable を覆っており、かつそのエリアにモーションが結びついていれば、そのモーションが再生されます。
#. モーションが再生されたかどうかに関わらず、ペットがスピーチバブルを出すことがあります — セリフ選択の優先順位については *ペットスクリプト* セクションを参照してください。
#. ヒットエリアがクリックを覆っていない場合、ペットは挨拶（スクリプトの ``greetings`` リスト、または組み込みフォールバック）にフォールバックします。

ドラッグ移動ジェスチャはクリックハンドラを抑制するので、ペットを動かしてもスピーチバブルは出ません。rig に ``Drag`` / ``Land`` グループがあれば、押したときに ``Drag`` グループのモーションが、ドラッグ後に離したときに ``Land`` グループのモーションが再生されます。

**本体のどこでも右クリック**

次のような構造のコンテキストメニューが開きます。

* **Hide pet** — オーバーレイを閉じるトップレベルアクション。
* **Live drivers** サブメニュー — 7 つのチェック可能なトグル（Auto idle、Idle motions、Auto-blink、Drag-track head、Mouse gaze、Mic lip-sync、Webcam tracking）。チェック状態はライブドライバの状態を反映するので、メニューを見れば現在動いているものがわかります。
* **Play motion** サブメニュー — アクティブな rig の ``document.motions`` リストから生成されます。エントリを選ぶとそのモーションが再生されます。``motion_lines`` のセリフは話しません（それはヒットエリアのクリックにだけ応答します）。
* **Apply expression** サブメニュー — rig の ``document.expressions`` から生成されます。表情がオンの間は各エントリにチェックが付きます。選択すると表情のパラメータオーバーレイを追加し、もう一度選択すると外します。
* **Pose** サブメニュー — rig のポーズグループごとに 1 つのサブメニュー（グループの表示名、なければ ID をラベルに使用）があり、そのグループのメンバーを一覧表示します。表示中のメンバーにチェックが付き、別のメンバーを選ぶと代わりにそれが表示されます。rig にポーズグループがないときは無効化されます。
* 5 つのトップレベルチェック可能トグル: **Lock position**、**Click-through**、**Always on bottom**、**Hide on fullscreen**、**Speech bubble** — ワークスペースタブと同じトグルへのクイックアクセス。
* **Size** サブメニュー — Small / Medium / Large。現在のプリセットにチェックが入ります。

rig が読み込まれていないときはモーション / 表情サブメニューは無効化されます。

**システムトレイアイコン**

トレイアイコン（トレイをサポートしているプラットフォームでのみインスタンス化）は、最もよく使うアクションの 4 つ目のサーフェスを提供します。

* 左クリックでペット表示をトグル。
* 右クリックで **Show pet**\ （チェック可能）、**Click-through**、**Open puppet…**、**Hide pet** のメニューが開きます。
* チェック可能な Show / Click-through 項目は ``sync_visibility`` / ``sync_click_through`` 経由でワークスペースのチェック状態をミラーするので、ユーザーがどのスイッチを切り替えても同期が保たれます。

ライブドライバ
^^^^^^^^^^^^^^

各ライブドライバは初回有効化時に遅延生成されるので、休止中のペットは決してオンにしないドライバのタイマー / スレッドコストをゼロに保ちます。各ドライバの状態は永続化されており、オンにして Imervue を閉じ、再起動すると、同じドライバが動いた状態で rig が復元されます。オーバーレイ自体が起動時に表示されるのは、タブの **ウィンドウ** グループで **Imervue の起動時にペットを表示** にチェックが入っているときだけです。

.. list-table::
   :header-rows: 1
   :widths: 22 50 28

   * - ドライバ
     - 何をするか
     - オプション依存
   * - **Auto idle**
     - 標準パラメータ（``ParamBreath`` など）への呼吸 + ささやかなドリフトで、他に何もアニメーションしていなくてもキャラクターが生きているように見えます。
     - なし
   * - **Idle motions**
     - rig の ``Idle`` グループからモーションをランダムに選んで再生します — オンにした直後に 1 つ、その後は数秒おき。Idle 以外のモーションが再生中は控えます。
     - なし
   * - **Auto-blink**
     - 約 4.5 秒ごとに、滑らかなコサインカーブで目を閉じて開きます。ドライバはパラメータを強制書き込みするので、他の目の開閉値に触れるドライバがまばたきを抑制することはありません。
     - なし
   * - **Drag-track head**
     - カーソルがペットの上を動いている間、頭 + 目がカーソルの方を向きます。``ParamAngleX`` / ``ParamAngleY`` / ``ParamEyeBallX`` / ``ParamEyeBallY`` を駆動します。
     - なし
   * - **Mouse gaze**
     - 画面上のどこにあっても、目と頭がペットの中心を基準にカーソルを追います（目が先に動きます）。同じ 4 つのパラメータを駆動します。
     - なし
   * - **Mic lip-sync**
     - マイクの RMS 振幅が ``ParamMouthOpenY`` を駆動します。
     - ``sounddevice``
   * - **Webcam tracking**
     - MediaPipe FaceLandmarker が約 30 FPS でウェブカメラを読み取り、頭のポーズ + 目の開閉 + 口の開閉パラメータを駆動します。ペットではプレビューウィンドウは開きません（カメラのプレビューは Puppet タブの機能です）。
     - ``opencv-python`` + ``mediapipe``

オプション依存の 2 つのドライバはグレースフルに劣化します。必要なパッケージがインストールされていない場合、チェックボックスをトグルしても跳ね返ってオフに戻り、ワークスペースのステータスラベルに「install sounddevice」/「install opencv-python + mediapipe」のヒントが表示されます。

ペットスクリプト — カスタムボイスとスケジュールイベント
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

ペットのスピーチバブルは、タブの **Pet script** グループから作成・読み込みできる JSON ファイルから引かれます。スクリプトは次の 5 つを制御します。

* **挨拶（Greetings）** — より具体的なものがマッチしないときのデフォルトクリックセリフ。
* **時間帯の挨拶（Time-of-day greetings）** — ローカル時刻の時間帯（``morning`` 5–11 時、``afternoon`` 12–17 時、``evening`` 18–21 時、``night`` 22–4 時）ごとの挨拶。通常の挨拶より先に使われ、セリフのない時間帯は通常の挨拶にフォールバックします。
* **ヒットエリア応答（Hit-area responses）** — ``HitArea.id`` ごとのセリフバケット。
* **モーションセリフ（Motion lines）** — モーション名ごとのセリフバケット。ヒットエリアのクリックでそのモーションが再生されたときに話します（コンテキストメニューから開始したモーションでは話しません）。
* **スケジュールチャイム（Scheduled chimes）** — モノトニックなウォールクロックの ``every_seconds`` 秒ごとに発火する、タイマー駆動のセリフ。

スキーマ（バージョン管理されており、将来のフィールドは前方互換）:

.. code-block:: json

   {
     "version": 1,
     "name": "Imeru — cheerful voice",
     "greetings": [
       "Hi!", "Hello hello!", "Need a break?"
     ],
     "time_of_day_greetings": {
       "morning": ["Good morning!"],
       "night": ["Still up?"]
     },
     "hit_responses": {
       "HitAreaHead": ["Hey, my head!", "Stop poking!"],
       "HitAreaBody": ["Hehe~", "Pat pat?"]
     },
     "motion_lines": {
       "wave": ["Hi!", "Hello!"],
       "curtsy": ["Cheers!"]
     },
     "scheduled": [
       {"every_seconds": 1800, "messages": ["Stretch break!"]}
     ]
   }

読み込みルール:

* リストはバケットごとにラウンドロビンでサンプリングされるので、同じセリフが連続して表示されることはありません。
* 不明なトップレベルキーは無視されます（前方互換 — 将来の v2 ファイルでも v1 ランタイムで読み込めます）。
* 不正なリストエントリ（型が違う、不正な形式のスケジュールエントリ、ゼロまたは負の ``every_seconds``）はスキップされます — 1 行の不正で読み込み全体が失敗することはありません。完全にパース不能な JSON のみがエラーを送出し、パスがステータスラベルに表示されます。
* ヒットエリア / モーション / 挨拶のカスケードは階層化されています。左クリックはまず ``hit_responses[area.id]`` を参照し、次に ``motion_lines[area.motion]``、次に ``time_of_day_greetings``、次に ``greetings``、最後に下限として組み込みのデフォルト挨拶セットを参照します。
* 時間追跡には ``time.monotonic`` を使うので、ノート PC をサスペンドしたりシステム時計を飛ばしたりしても、キューに溜まったイベントが一気に発火することはありません。

**Reset to default** はユーザースクリプトを破棄し、組み込みの挨拶セットに戻します。永続化されていたスクリプトパスもクリアされるので、次回起動時に再読み込みされません。

動作するサンプルが ``examples/desktop_pet/imeru.petscript.json`` にあります — 挨拶 6 件、時間帯ごとのセリフ、ヒットエリアバケット 2 つ（``Head`` / ``Body``）、5 つのモーションのセリフ（wave / greet / surprised / sleepy / shy）、30 分間隔のストレッチリマインダーが入っています。バケット名は Imeru のヒットエリア名なので、頭と体へのクリックに応答します。ヒットエリアに Cubism の名前（``HitAreaHead`` / ``HitAreaBody``）を使う rig では、その名前でバケットを用意する必要があります。

新しいペットの作成
^^^^^^^^^^^^^^^^^^

どんな ``.puppet`` ファイルでも Desktop Pet キャラクターとして動作します — Desktop Pet タブは純粋にレンダラ + インタラクションシェルで、rig のオーサリングは Puppet タブで行います（*Puppet ワークスペース（Puppet タブ）* を参照）。

自分のペット rig を作るには:

#. Puppet タブに切り替えて、**File > Import PNG…** または **File > Import PSD…** で原画をインポートするか、**File > Import Cubism…** で Cubism モデルを取り込みます。
#. 回転 / ワープデフォーマ、パラメータ、モーション、表情、（オプションで）Desktop Pet の左クリックハンドラでモーションを発火できるように、ボディパーツに紐付いたヒットエリアを作成します。
#. **File > Save As…** で rig を ``.puppet`` zip として保存します。
#. Desktop Pet タブに戻り、**Open Puppet…** で新しいファイルを読み込みます。

rig が ``HitArea`` エントリを定義していれば、``hit_responses`` キーがエリア ID と一致するような ``.petscript.json`` でヒットエリアごとのスピーチバブルセリフを作成できます。

トラブルシューティング
^^^^^^^^^^^^^^^^^^^^^^

**ペットが完全に透明にならず、灰色の長方形の中に表示されます。** OS レベルの半透明背景属性には、アルファ対応の GL サーフェスと、埋め込まれた GL ウィジェット上の対応する属性が必要です。サードパーティーのウィンドウ管理ツールがオーバーレイウィンドウの ``WA_TranslucentBackground`` 属性を上書きしていないか確認してください（Linux のカスタムウィンドウマネージャの一部はこれを行います）。Windows / macOS では「そのまま動く」はずです。

**「Load bundled Imeru」がファイルが見つからないと報告します。** リゾルバはまず ``examples_dir()``\ （パッケージ化ビルドが使用するフローズン対応の場所）を参照し、CWD 相対パスにフォールバックします。どちらにも rig が含まれていない場合、ステータスラベルに期待されるパスが表示されます。インストール時に同梱されている ``examples/`` ディレクトリを確認してください — ソースチェックアウトの場合はリポジトリのルートから Imervue を起動してください。

**クリックしてもペットが話しません。** 3 つのチェック:

#. **Speech bubble on click** トグルがオンになっていることを確認してください（タブまたは右クリックメニュー）。
#. カスタムスクリプトを読み込んだ場合、JSON がパースできることを確認してください — タブのステータスラベルに読み込みエラーが表示されます。
#. **Click-through** がオンだと、クリックはペットの背後のウィンドウに届きます。タブかトレイメニューでオフにしてください。（スピーチがオンなら、どのクリックにもセリフが返ります。ヒットエリアのない rig ではモーションは再生されませんが、クリックすれば挨拶します。）

**ウェブカメラトラッキングのチェックボックスが跳ね返ってオフに戻ります。** ウェブカメラトラッキングには ``opencv-python`` と ``mediapipe`` が、Imervue が動いているのと同じ Python 環境にインストールされている必要があります。``pip install opencv-python mediapipe`` でインストールしてください。インストール後にもう一度チェックを入れてください。ペットはプレビューウィンドウを開きません。カメラが何を検出しているかを見るには、Puppet タブで **Webcam tracking** をオンにすると、顔のランドマークが表示されます。

**フルスクリーンアプリ中にペットが自動的に隠れません。** フルスクリーン検出器は最前面ウィンドウを 1 Hz でポーリングします。Windows では ``GetWindowRect`` Win32 API を使用します。macOS / Linux では信頼できるクロスプラットフォーム相当機能がないため、何もしません（ペットは表示されたままです）。Windows の場合: **Hide when other app is fullscreen** がチェックされていることを確認し、フルスクリーンウィンドウが実際にペットと同じモニターの 99% 以上を覆っていることを確認してください。

**起動間でペットの位置が画面外にドリフトします。** これは、ペットがいたスクリーンが次回起動時にもう接続されていないとき（ノート PC のドック、セカンドモニターを抜いたなど）に発生します。この場合、ペットは最初のスクリーンに移り、保存された位置がそのスクリーン内にクランプされます — 好きな位置にドラッグすれば、次回保存時にその古い位置が上書きされます。

単一エクスポート

バッチエクスポート
^^^^^^^^^^^^^^^^^^

複数画像を選択し、右クリック > ``一括操作`` > ``一括エクスポート``

- 一括フォーマット変換
- 最大幅／高さの設定（アスペクト比を維持して自動縮小）
- 品質調整
- リアルタイム進捗バー
- **処理デバイス**：CPU、または GPU 現像プラグインを入れている場合は専用 GPU（下記参照）

GPU 現像プラグイン
^^^^^^^^^^^^^^^^^^

**GPU 現像** プラグイン（``Plugins`` > ``Download Plugins``、カテゴリ ``plugins``、名前
``gpu_develop``）を使うと、バッチエクスポートで現像レシピを専用 GPU で処理できます。
``Plugins`` > ``GPU 現像…`` は初回に ``wgpu`` をインストールし、使用する GPU の名前を表示します。
以後バッチエクスポートには **処理デバイス** が表示され、その GPU が選択されています（従来どおりに
処理するには **CPU** を選びます）。

- ホワイトバランス、露出、ハイライト / シャドウ、白レベル / 黒レベル、明るさ、コントラスト、自然な彩度、彩度、トーンカーブは GPU で処理され、回転、反転、切り抜き、およびトーンカーブより後の処理（スプリットトーン、LUT、マスク、レベル補正など）は CPU に残ります
- 24 MP の写真は、デコードと保存を除くと、CPU では約 7 秒かかるところを GPU では約 0.1 秒で処理します
- 使うのは専用 GPU だけで、内蔵 GPU やソフトウェアレンダラーは決して使いません。Windows ではまず Vulkan、次に Direct3D 12 を使います
- GPU で処理に失敗した画像は CPU で処理されるため、エクスポートは最後まで完了します
- 出力は CPU レンダラーと一致し、差が出るのはごく一部のピクセルで、それも数階調以内です

アニメーション再生
------------------

GIF、APNG、アニメーション WebP を開くと、自動的にアニメーションが再生されます。デコード後に 512 MB を超える
アニメーションは再生しながら 1 フレームずつデコードするため、開いてもウィンドウが
固まったりメモリを使い切ったりしません。
10 ms 以下のフレームはブラウザーと同じく 100 ms 表示します（多くの GIF がこれを前提にしています）。

複数ページの TIFF（スキャンした文書）は再生せず、1 ページずつ表示して ``,`` と ``.`` でめくります。表示は「2/5 ページ」のようになります。アニメーションではないフレーム、つまりカメラが JPEG に埋め込むプレビュー（MPF）、PSD のレイヤー、APNG の既定画像（APNG 非対応のプログラム向けの静止画）も再生しません。

.. list-table::
   :header-rows: 1
   :widths: 30 70

   * - キー
     - 操作
   * - ``Space``
     - 再生／一時停止
   * - ``,``
     - 前のフレーム
   * - ``.``
     - 次のフレーム
   * - ``]``
     - 速度アップ
   * - ``[``
     - 速度ダウン

画像の比較
----------

サムネイルモードで 2 枚または 4 枚の画像を選択し、右クリック > ``画像を比較``\ （またはダイアログのリストで選択）。

ダイアログには 4 つのタブがあります：

.. list-table::
   :header-rows: 1
   :widths: 25 75

   * - タブ
     - 用途
   * - **並列**
     - 2 枚または 4 枚を同時表示。各ペインで自動フィット。
   * - **オーバーレイ**
     - 2 枚を α スライダーで合成（0 → A のみ、100 → B のみ）。2 枚選択が必要。
   * - **差分**
     - ピクセルごとに ``|A − B|`` を表示。ゲインスライダー（0.10×–20×）で微細な違いを強調。
   * - **A | B 分割**
     - before / after の分割ビュー。ドラッグ可能な垂直仕切りで左右をスイープ。Develop の調整や
       書き出し結果の比較に便利。2 枚選択が必要。

サイズが異なる場合、B を Lanczos で A のサイズにリサンプルします。非常に大きい画像は
内部で長辺 2048 px にダウンスケールしてリアルタイム性を保ちます。

.. seealso::
   ダイアログを開かずにメインウィンドウ内で並べる場合は、**分割表示**\ （``Shift + S``）や
   **見開き表示**\ （``Shift + D`` / ``Ctrl + Shift + D``）を使います。

バッチ操作
----------

サムネイルモードで複数画像を選択後、右クリック > ``一括操作`` で以下の操作が可能です：

.. list-table::
   :header-rows: 1
   :widths: 30 70

   * - 機能
     - 説明
   * - バッチリネーム

   * - EXIF で自動回転
     - 各写真の向きを正した PNG コピーを ``<name>_oriented.png`` として保存
   * - PDF／TIFF に結合…

   * - アルバムに追加
     - 選択した全画像をアルバムに追加

sidecar も一緒に移ります:``IMG.xmp``、``IMG.JPG.xmp``、

フォルダを Imervue で開いている間に他のプログラムでリネームした写真も、同じ
データを保ちます。新しい名前にすでにあったデータはそのままです。

プラグインの作成
^^^^^^^^^^^^^^^^

プラグインは ``plugins/<name>/`` に置く Python パッケージです。ソースチェックアウトでは ``Imervue``
パッケージの隣、パッケージ版では実行ファイルの隣にあります（``Plugins`` > ``Open Plugin
Folder`` で開けます）。その ``__init__.py`` で ``plugin_class`` に
``Imervue.plugin.plugin_base.ImervuePlugin`` のサブクラスを設定します。``plugins/`` 直下の単一の
``.py`` ファイルも読み込まれますが（最初の ``ImervuePlugin`` サブクラスが使われます）、プラグイン
ダウンローダが配布するのはパッケージだけです。クラス属性 ``plugin_name``、``plugin_version``、
``plugin_description``、``plugin_author`` は省略可能です（既定値は ``"Unnamed Plugin"``、
``"0.0.1"``、空文字列）。メインウィンドウはそれぞれ各プラグインのインスタンスを個別に作成して自身を
渡すため、フックからは ``self.main_window`` と ``self.viewer``\ （``GPUImageView``）を使えます。
必要なフックだけをオーバーライドしてください。各呼び出しはラップされているため、例外が起きても
Imervue は止まらず、プラグイン名付きでログに記録されます。例を含む完全なガイドは
`PLUGIN_DEV_GUIDE.md <https://github.com/JeffreyChen-s-Utils/Imervue/blob/main/PLUGIN_DEV_GUIDE.md>`_
にあります。フックのほかに、``on_plugin_loaded()`` の中で ``Imervue.image.develop_backends.register``
を使って ``BackendProvider`` を登録すると、バッチエクスポートに現像レシピ用の別のレンダラーを
追加できます。GPU 現像プラグインがその例です。

**OK** で画像変換を 1 つ実行するダイアログは、ボタン列、オプションパッケージのインストール、
ワーカースレッド、結果のトーストを ``Imervue.plugin.tool_dialog.ToolDialogMixin`` から受け取れます。
ダイアログ側は ``output_suffix`` とトーストのキーを設定し、``_transform()`` から変換を返します。
旧リリース以降に追加されたメインプログラムのコードを import するプラグインは、必要なプラグイン
API バージョンを ``__init__.py`` と同じ場所に置いた ``plugin.json`` ファイルに書きます
（``{"min_api_version": 2}``）。古すぎる Imervue では ``Plugins`` > ``Download Plugins`` がそのような
プラグインを拒否し、インストール済みのコピーはそのまま残して、必要なバージョンをステータス行に
表示します。プラグインローダはそのプラグインを import せずにスキップし、理由をログに記録します。

.. list-table::
   :header-rows: 1
   :widths: 28 40 32

   * - フック
     - 呼び出されるタイミング
     - 引数 / 戻り値
   * - ``register_languages()``\ （クラスメソッド）
     - 各インスタンスを作成する前にプラグインクラスに対して（読み込みのたびと ``Reload
       Plugins`` のたび）、および保存された言語が組み込み言語でない場合は起動時、メインウィンドウの
       構築前。この起動時の処理はすべてのプラグインをインポートするだけで、他には何も実行しません
     - 引数なし。ここで ``language_wrapper.register_language(language_code, display_name,
       word_dict)`` を呼び出します。組み込み言語のコードは拒否されます。空の文字列や
       ``{placeholders}`` が英語と異なる文字列は破棄されてログに記録され（組み込みのテキストが
       表示されます）、不足しているキーもログに記録されます。戻り値は無視されます。
       例外はログに記録され、プラグインはそのまま読み込まれます
   * - ``on_plugin_loaded()``
     - インスタンスの作成直後：メインウィンドウの構築中と、``Plugins`` > ``Reload Plugins`` の後
     - 引数なし。戻り値は無視されます
   * - ``get_translations()``
     - ``on_plugin_loaded()`` の直後、読み込みごとに 1 回
     - ``{language_code: {key: text}}`` を返します（既定値 ``{}``）。文字列は言語テーブルに
       マージされます。既存のキーは上書きされず、未知の言語コードはスキップされます。空の文字列や、
       ``{placeholders}`` がそのキーに対するペイロードの英語の文字列と異なる文字列は破棄され、
       問題はログに記録されます
   * - ``on_build_main_tabs(tabs)``
     - メインウィンドウの構築中に 1 回、5 つの組み込みタブの後、``on_build_menu_bar`` の前。
       ``Reload Plugins`` では再実行されません
     - ``tabs``：メインウィンドウのトップレベル ``QTabWidget``。``tabs.addTab(widget, label)`` で
       タブを追加します。戻り値は無視されます
   * - ``on_build_menu_bar(plugin_menu)``
     - 共有の ``Plugins`` メニューの構築後に 1 回、および ``Reload Plugins`` の後に再度
     - ``plugin_menu``：``Plugins`` の ``QMenu``\ （``QMenuBar`` ではありません）。ここでプラグインが
       メニューバーのどこかに追加した項目は、再読み込み時に削除されます。戻り値は無視されます
   * - ``on_build_context_menu(menu, viewer)``
     - ビューアーの右クリックメニューが構築されるたび、組み込み項目の後、開く直前
     - ``menu``：コンテキストの ``QMenu``。``viewer``：``GPUImageView``。戻り値は無視されます
   * - ``on_folder_opened(folder_path, image_paths, viewer)``
     - 開いたフォルダーのスキャンが完了したとき
     - ``folder_path``：フォルダー。``image_paths``：スキャンで見つかったすべての画像。戻り値は
       無視されます
   * - ``on_image_loaded(image_path, viewer)``
     - 開き方にかかわらず、画像がディープズームでフルサイズ表示されるたび。編集後に再読み込み
       されたときにも呼ばれます。大きな画像のデコード中に表示される低解像度プレビューでは呼ばれません
     - ``image_path``：画像のパス。戻り値は無視されます
   * - ``on_image_switched(image_path, viewer)``
     - 次へ / 前へ（リストの両端での折り返しを含む）で別の画像に移ったとき、その読み込みが始まった
       時点。表示されると ``on_image_loaded`` が続きます。グリッドやフィルムストリップから画像を
       開いても呼ばれません
     - ``image_path``：新しい現在の画像。戻り値は無視されます
   * - ``on_image_deleted(deleted_paths, viewer)``
     - ビューアー（現在の画像または選択中のサムネイル）やフォルダーツリーから画像がソフト削除
       （undo スタックに積まれる）された後。画像リストにないためにツリーが直接ごみ箱へ送るファイル
       では呼ばれません
     - ``deleted_paths``：削除されたパスのリスト。戻り値は無視されます
   * - ``on_key_press(key, modifiers, viewer)``
     - ビューアーがキー押下を受け取るたび、組み込みキーとショートカット設定のバインドより前。
       プラグインには読み込み順に問い合わせます。メニューやウィンドウのショートカットが先に取る
       キーはビューアーに届きません
     - ``key``：\ ``Qt.Key`` コード（int）。``modifiers``：\ ``Qt.KeyboardModifier`` フラグ。
       ``True`` を返すとキーを消費し、後続のプラグインと既定の処理はスキップされます。
       ``False``\ （既定）を返すと次に渡します。例外は ``False`` として扱われます
   * - ``on_pet_created(pet)``
     - Desktop Pet タブがペットウィンドウを作成したとき、およびペットがすでに存在する場合はプラグインの
       読み込み直後（または ``Reload Plugins`` の実行後）
     - ``pet``：ペットウィンドウ。プラグインは ``play_group(group)``、``speak(line)``、
       ``speak_notification(line)``、``speech_on``、``setting(key, default)``、
       ``persist(**fields)``、``add_integration(key, controller)`` /
       ``remove_integration(key)`` / ``integration(key)`` と、シグナル ``hit_triggered``、
       ``moved``、``visibility_changed`` を使います。戻り値は無視されます
   * - ``on_app_closing(main_window)``
     - 最後のメインウィンドウが閉じるとき。Paint の未保存タブの確認が承認され、設定が保存された後、
       プラグインがアンロードされる直前です。他のウィンドウを閉じても呼ばれません
     - ``main_window``：閉じる ``ImervueMainWindow``。戻り値は無視されます
   * - ``on_plugin_unloaded()``
     - プラグインのウィンドウが閉じるとき（最後のウィンドウでは ``on_app_closing`` の後）、および
       ``Reload Plugins`` がプラグインを再読み込みする前。プラグインは読み込みと逆の順にアンロード
       されます
     - 引数なし。戻り値は無視されます

言語の切り替え
--------------

``言語`` メニューでインターフェース言語を切り替えられます：

- English
- 繁體中文
- 简体中文
- 한국어
- 日本語

切り替え後は再起動が必要です。

プラグインは独自の言語を追加できます。**Español** はまさにこの方法で提供されています ——
プラグインダウンローダから ``spanish_translation`` プラグインを入れると、5 つの組み込み言語と
並んで ``Language`` メニューに現れます。プラグインは既存言語へ翻訳を追加することもできます。
既にあるキーが上書きされることはないため、プラグインが同梱の文字列を壊すことはありません。

ライブラリとメタデータ管理
--------------------------

Imervue は ``%LOCALAPPDATA%/Imervue/library.db``\ （Windows）または
``~/.cache/imervue/library.db``\ （POSIX）に SQLite インデックスを保持し、
フォルダー横断検索・階層タグ・スマートアルバム・pHash・メモ・セレクト
フラグを管理します。以下の機能は原則として ``Extra Tools`` メニュー下に
あります。見つけやすさのため、メニューは機能別に 8 つのサブメニューへ
分割されています：``Batch``\ （一括処理）、
``Library & Metadata``\ （ライブラリとメタデータ）、``Views``\ （表示）、
``Workflow``\ （ワークフロー）、``Export``\ （書き出し）、
``Develop (Non-Destructive)``\ （現像）、
``Retouch & Transform``\ （レタッチと変形）、
``Multi-Image``\ （マルチ画像）。以下のパスはすべて
``Extra Tools`` > ``<サブメニュー>`` > ``<ツール>`` の形で表記します。

ライブラリ検索
^^^^^^^^^^^^^^

``Extra Tools`` > ``Library & Metadata`` > ``Library Search`` で複数の\ **ルートフォルダー**\ をグローバルインデックスに追加し、バックグラウンドでクロールします。インデックス済みのルートはファイル名・最小幅／高さ・ファイルサイズで検索でき（最大 2000 件）、結果をダブルクリックすると開きます。再スキャンでは、前回以降に追加・変更されたファイルと、\ **Compute perceptual hash**\ がオンのときはハッシュなしで登録済みのファイルだけを読み込み、複数のスレッドで同時にデコードします。

右クリック > ``クエリ検索…`` で、現在のフォルダーをコンパクトなクエリ言語で絞り込めます。例：``kw:beach rating:>=4 type:video place:Paris``。``place:`` には都市・国・その両方（``Paris``、``France``、``Paris, France``）を指定でき、空白を含む値はダブルクォートで囲みます（``place:"Rio de Janeiro"``）。

スマートアルバム
^^^^^^^^^^^^^^^^

``Extra Tools`` > ``Library & Metadata`` > ``Smart Albums`` はフィルター条件（拡張子・最小サイズ・
カラーラベル・評価・お気に入り・セレクト状態・階層タグ・ファイル名部分
一致）を名前付きで保存します。再適用で現在フォルダーを即フィルター。

類似画像検索
^^^^^^^^^^^^

``Extra Tools`` > ``Library & Metadata`` > ``Find Similar Images`` は現在の Deep Zoom 画像（または
最初に選択されたタイル）の 64bit DCT pHash を計算し、ハミング距離の近い順
にインデックスから結果を提示します。``最大ハミング距離`` で厳密度を調整でき
ます。

セマンティック検索（CLIP）
^^^^^^^^^^^^^^^^^^^^^^^^^^

``Extra Tools`` > ``Library & Metadata`` > ``Semantic Search`` では、自然言語のフレーズ（例：*「雪の中のゴールデンレトリバー」*、*「夜のネオン街」*）を入力すると、開いているフォルダーの画像を関連度順に返します。各画像は CLIP のビジョン / 言語エンコーダーで埋め込み、パスと一緒に保存します。テキストクエリも同じベクトル空間に埋め込み、コサイン類似度で比較します。

埋め込みは ``%LOCALAPPDATA%/Imervue/clip_cache.npz``\ （Windows）または ``~/.cache/imervue/clip_cache.npz``\ （POSIX）に、1 つのコンパクトな ``.npz`` アーカイブとしてキャッシュされます。ダイアログは開いているフォルダーを検索します。キャッシュにまだない画像と、その後に変更された画像（サイズまたは更新日時）だけを埋め込むため、同じフォルダーをもう一度検索するとすぐに始まり、結果はそのフォルダーからのみ返されます。

.. note::
   セマンティック検索は PyTorch を使わず、\ ``onnxruntime`` 上で CLIP ViT-B/32 を実行します。
   ``onnxruntime`` がない状態で初めて開くと、Imervue がそのインストールを提案します。
   その後、モデル（約 150 MB、int8 量子化済み）を Hugging Face から固定リビジョンで一度だけダウンロードし、
   以降はローカルキャッシュから読み込みます。\ ``onnxruntime`` が CUDA に対応していれば CUDA 経由で
   NVIDIA GPU 上で、それ以外は CPU 上で実行し、内蔵 GPU を選ぶことはありません。
   別のモデルでキャッシュされた埋め込みは計算し直されます。

自動タグ付け
^^^^^^^^^^^^

``Extra Tools`` > ``Library & Metadata`` > ``Auto-Tag Images`` はヒューリスティックタグを ``auto/...``
以下（``photo`` / ``document`` / ``screenshot`` / ``graphic`` / ``landscape`` /
``portrait``）に付与します。判定には、ビューアーに表示される画像の彩度・エッジ・形状を使います。ワーカースレッドで実行しプログレスバー付き。

セマンティック検索が CLIP モデルをダウンロード済みの場合、自動タグ付けは代わりにそのモデルで各画像をゼロショットでラベル付けします。\ ``photo`` / ``document`` / ``screenshot`` / ``graphic`` / ``illustration`` / ``portrait`` / ``landscape`` / ``animal`` / ``food`` / ``text`` のうち最大 3 つを、近いものから順に付与します。CLIP で読み取れない画像にはヒューリスティックタグが付き、自動タグ付けが自分からダウンロードを始めることはありません。

階層タグ
^^^^^^^^

``Extra Tools`` > ``Library & Metadata`` > ``Hierarchical Tags`` でツリー構造のタグ（例
``animal/cat/british``）を管理できます。ノードを選ぶと子孫タグも含めた
画像一覧が表示され、現在の選択をワンクリックでタグ付け／解除できます。
右クリックメニューのフラットタグと併存します。

サムネイルを選択して右クリック > ``一括操作`` > ``キーワードを索引`` を選ぶと、
選択画像の XMP キーワードがライブラリに追加されます。
Lightroom や darktable が書いたキーワード階層(``lr:hierarchicalSubject``、
``Places|Taiwan|Taipei``)はタグパス ``Places/Taiwan/Taipei`` として登録され、
その階層を繰り返すだけの ``Places``／``Taiwan``／``Taipei`` は重ねて追加しません。

Token 一括リネーム
^^^^^^^^^^^^^^^^^^

``Extra Tools`` > ``Batch`` > ``Token Batch Rename`` はライブプレビュー表示で、
``{date:yyyymmdd}_{camera}_{counter:04}{ext}`` のようなテンプレートを入力
するとファイルごとの新名称が即座に表示されます。衝突はハイライト。対応
トークン：``{name} {ext} {counter[:NN]} {date[:fmt]} {width} {height}
{wxh} {size_kb} {camera} {year} {month} {day} {hour} {minute}``。選択中の別のファイルが今使っている名前は衝突になりません。番号の振り
直し(``002`` → ``003`` と同時に ``003`` → ``004``)や 2 つの名前の入れ替えでも選択
全体をリネームします。Batch Rename も同様です。

メタデータエクスポート
^^^^^^^^^^^^^^^^^^^^^^

``Extra Tools`` > ``Library & Metadata`` > ``Export Metadata (CSV / JSON)`` で現在のビューにある各
画像を 1 行として EXIF／サイズ／カラーラベル／評価／お気に入り／階層タグ
／セレクト状態／メモ付きで出力します。表計算や外部ワークフローに便利。

XMP サイドカー
^^^^^^^^^^^^^^

Imervue は Adobe XMP sidecar ファイル（``photo.jpg`` ↔ ``photo.xmp``）の
読み書きに対応しており、評価・タイトル・説明・キーワード・カラーラベルを
Adobe Bridge や他の XMP 対応写真管理ソフトと双方向に同期できます。

保存時は既存の sidecar にマージします。変わるのはこれらの項目だけなので、RAW 現像ソフトが保存した現像設定・切り抜き・履歴は残り、解析できない sidecar は上書きしません。

``photo.xmp``\ （Lightroom、Bridge）のほか、darktable と digiKam が書く
``photo.jpg.xmp`` も、それが唯一の sidecar なら読み込んで更新します。
カラーラベルは Lightroom の表記（``Red`` … ``Purple``）と Bridge の表記
（``Select``、``Second``、``Approved``、``Review``、``To Do``）を理解します。
新しく付けた色や変更した色は Lightroom の表記で書き出し、同じ色を Bridge の表記で
すでに持っている sidecar はその表記を保ちます。色に対応しない独自ラベルは
sidecar に残します。

除外された写真(Lightroom、Bridge、darktable の ``xmp:Rating`` -1)は、星なしの
選別 **除外** として取り込み、**除外** は -1 としてエクスポートします。除外でない
sidecar は「除外」を解除し、「採用」はそのままです。

サイドカーのないファイルは、ファイル自体に埋め込まれた内容を読み込み(取り込み)ます。
まず XMP パケット(JPEG、PNG、WebP、TIFF、CR3、RW2、RWL、ORF、RAF)、次に EXIF の ``Rating``／``RatingPercent``
です。Lightroom は JPEG の評価とキーワードを、Windows エクスプローラーや一部の
カメラは星をここに保存します。サイドカーがあればサイドカーが優先です。

``Extra Tools`` > ``Library & Metadata`` > ``XMP Sidecars`` には 2 つのボタンがあり、現在のビューにあるすべての画像に適用されます：

- **サイドカー書き出し** — 各画像の評価 / タイトル / 説明 / キーワード / カラーラベルを
  sidecar に書き出します。
- **サイドカー読み込み** — sidecar の内容を Imervue 自身の記録に読み戻します。

XML 解析は ``defusedxml`` を通しており、XXE や billion-laughs 攻撃を防ぎます。

**EXIF サイドバー** のクリック可能な **星評価ストリップ** で設定した評価が、
そのまま XMP エクスポートの値になります。

セレクト（Pick / Reject）
^^^^^^^^^^^^^^^^^^^^^^^^^

三値のセレクトフラグ。``P`` で現在の画像または選択中のタイル全てを
Pick、``Shift + X`` で Reject、``U`` でフラグ解除。``Filter`` > ``By Cull
State`` で状態別に表示、``Extra Tools`` > ``Workflow`` > ``Culling`` ダイアログには
**Delete all rejects** ボタンがあり、Reject フラグのファイルをディスクから
永久削除できます。

ステージングトレイ
^^^^^^^^^^^^^^^^^^

``Extra Tools`` > ``Workflow`` > ``Staging Tray`` はフォルダー横断のカゴ。任意のタイルを
追加（再起動後も保持）し、トレイ全体を目的フォルダーへ一括で移動／コ
ピーできます。複数セッションから採用画像を集めて書き出す際に便利。

デュアルペインファイラー
^^^^^^^^^^^^^^^^^^^^^^^^

``Extra Tools`` > ``Workflow`` > ``Dual-Pane File Manager`` は 2 ペイン構成で、
2 フォルダー間の選択を直接移動／コピーできます。

タイムラインビュー
^^^^^^^^^^^^^^^^^^

``Extra Tools`` > ``Views`` > ``Timeline View`` は現在の画像セットを日／月／年単位で
グルーピング（日付別表示）。日付は EXIF ``DateTimeOriginal``、次に
``DateTimeDigitized``、次に ``DateTime`` の順に取り、どれもなければファイル
更新日時を使用。画像をダブルクリックで Deep Zoom へ。

外部アプリへのドラッグアウト

高度な現像・合成
----------------

トーンカーブ
^^^^^^^^^^^^

``Extra Tools`` > ``Develop (Non-Destructive)`` > ``Tone Curve`` で、RGB と R/G/B の 4 チャンネルを持つ
ドラッグ可能なポイントのカーブエディターを開きます。空白部分を左クリッ
クでポイント追加、ドラッグで移動、右クリックで削除。ポイント間は
monotone cubic で補間され、カーブは recipe に保存されて非破壊に適用
されます。

.cube LUT 適用
^^^^^^^^^^^^^^

``Extra Tools`` > ``Develop (Non-Destructive)`` > ``Apply .cube LUT`` で任意の Adobe ``.cube`` ファイル
（3D は最大 65³、1D は最大 65,536 点）を選択できます。DaVinci Resolve の
``LUT_1D_INPUT_RANGE`` / ``LUT_3D_INPUT_RANGE`` は ``DOMAIN_MIN`` / ``DOMAIN_MAX`` と同じく
入力範囲を決め、BOM 付きのファイルも読み込めます。LUT はパス+mtime キーで
``lru_cache`` に保持され、トリリニア補間で適用、強度スライダーで原画
とブレンドします。LUT パスと強度は recipe に保存されます。

バーチャルコピー
^^^^^^^^^^^^^^^^

``Extra Tools`` > ``Workflow`` > ``Virtual Copies`` は同一画像に対して名前付きの
recipe スナップショットを複数保持します。現在の編集を保存して実験を
続け、いつでも別バージョンに切り替えられます。バリアントはマスター
recipe と並んで保存され、マスターを identity にリセットしても残り
ます。

HDR マージ
^^^^^^^^^^

``Extra Tools`` > ``Multi-Image`` > ``HDR Merge`` は OpenCV の Mertens 露出融合で
ブラケット撮影を 1 枚に合成します。Align を有効にすると事前に
``cv2.AlignMTB`` で位置合わせします。出力は指定ファイルに書き込み、
元画像には触れません。

パノラマ合成
^^^^^^^^^^^^

``Extra Tools`` > ``Multi-Image`` > ``Panorama Stitch`` は OpenCV の ``Stitcher`` で
重なり合う写真を結合します。風景 / 都市景観には **Panorama**、
フラットな文書や絵には **Scans** モードを使用します。合成で生じる
黒枠を自動トリミング可能です。

フォーカススタッキング
^^^^^^^^^^^^^^^^^^^^^^

``Extra Tools`` > ``Multi-Image`` > ``Focus Stacking`` は異なるピント距離で撮影した画像
を融合します。Laplacian 分散で各画素のシャープさを測り最良フレーム
を採用、選択マスクをガウシアンで滑らかにして継ぎ目を抑えます。
デフォルトで ECC によるアライメントが有効です。

ヒーリングブラシ
^^^^^^^^^^^^^^^^

``Extra Tools`` > ``Retouch & Transform`` > ``Healing Brush`` は現在画像を長辺最大 720px で
プレビュー表示します。左クリックで円形スポットを追加、右クリックで
削除、半径スライダーで新規スポットのサイズを決めます。適用時に
OpenCV inpainting（Telea / Navier-Stokes）で修復し、新規ファイルに
保存します。

レンズ補正
^^^^^^^^^^

``Extra Tools`` > ``Retouch & Transform`` > ``Lens Correction`` は純 numpy の 4 スライダー：
放射歪み ``k1``\ （樽型 / 糸巻型）、周辺光量補正、赤 / 青チャンネルの
色収差放射スケール。補正後の画像は元画像と同じサイズのまま、新規
ファイルとして保存します。

マップビュー
^^^^^^^^^^^^

``Extra Tools`` > ``Views`` > ``Map View`` は、開いているフォルダの GPS 付き画像を
Leaflet + OpenStreetMap の対話型マップ（``PySide6.QtWebEngineWidgets`` 必須）に
プロットします。マーカーは最寄りの都市ごとに 1 つで、そこにある画像の枚数を
示します。WebEngine が無い場合は、それらの場所を枚数と座標付きで並べたリストに
フォールバックするので、最小構成のインストールでも使えます。

カレンダービュー
^^^^^^^^^^^^^^^^

``Extra Tools`` > ``Views`` > ``Calendar View`` は ``QCalendarWidget`` で撮影日
のあるセルをハイライトします（EXIF ``DateTimeOriginal`` →
``DateTimeDigitized`` → ``DateTime`` → ファイル mtime の順）。日付を選択するとその
日の画像が一覧表示され、ダブルクリックでメインビューアーに開き
ます。

顔検出
^^^^^^

``Extra Tools`` > ``Retouch & Transform`` > ``Face Detection`` は OpenCV の Haar 正面顔分類器で
現在画像を走査し、矩形で表示します。リストをダブルクリックして名前
を入力し保存すると、recipe の ``extra['face_tags']`` に書き込まれ
ます。古典的手法で「顔の位置を知る」用途には十分ですが、最新の
CNN ベース認識の代替ではありません。
OpenCV 4 が必要です（``pip install "opencv-python<5"``）。OpenCV 5 では Haar
分類器が削除されたため、その場合ダイアログは検出せずにその旨を表示します。

ローカル調整マスク
^^^^^^^^^^^^^^^^^^

``Extra Tools`` > ``Develop (Non-Destructive)`` > ``Local Adjustment Masks`` はブラシ / 放射 / 線形
グラデーションのマスクを重ねて使えます。各マスクに露出、明るさ、
コントラスト、彩度、色温度、色合いの差分とぼかし量を設定でき、
``recipe.extra['masks']`` に保存されて読み込み時に非破壊で適用
されます。

スプリットトーン
^^^^^^^^^^^^^^^^

``Extra Tools`` > ``Develop (Non-Destructive)`` > ``Split Toning`` はシャドウとハイライトそれぞれ
に色相と彩度を設定し、バランスで境界を決めます。``recipe.extra``
に保存され、トーンカーブの後に適用されます。

コピースタンプ
^^^^^^^^^^^^^^

``Extra Tools`` > ``Retouch & Transform`` > ``Clone Stamp`` はソース領域をぼかしでコピーし
ます。修復ブラシとは異なりピクセル単位で内容を移動できる手法
です。Shift+クリックでソースを設定、クリックでスタンプ、右クリック
で取り消し。結果は新しいファイルに書き出されます。

トリミング / 水平補正
^^^^^^^^^^^^^^^^^^^^^

``Extra Tools`` > ``Retouch & Transform`` > ``Crop / Straighten`` は 0..1 の正規化トリミング
矩形と最大 ±15° の水平補正を組み合わせます。出力は最大内接矩形に
自動トリミングされ、黒い余白は出ません。

自動水平補正
^^^^^^^^^^^^

``Extra Tools`` > ``Retouch & Transform`` > ``Auto-Straighten`` は Hough 線で主要な地平線や
垂直線を検出し、回転角を提案します。適用前に微調整可能です。

ノイズ軽減 / シャープ
^^^^^^^^^^^^^^^^^^^^^

``Extra Tools`` > ``Retouch & Transform`` > ``Noise Reduction / Sharpening`` はエッジ保持の
バイラテラルノイズ軽減とアンシャープマスクを組み合わせます。
「輝度チャンネルのみ」は色ノイズを維持しつつ輝度ノイズのみ平滑化
します。

空 / 背景
^^^^^^^^^

``Extra Tools`` > ``Retouch & Transform`` > ``Sky / Background`` は検出した空をグラデーション
に置換したり、背景を透明 / 白に切り抜いたりします。``rembg``
(U²-Net) がインストールされている場合は前景セグメンテーション
ネットワークが自動的に使われます。

ソフトプルーフ
^^^^^^^^^^^^^^

``Extra Tools`` > ``Develop (Non-Destructive)`` > ``Soft Proof`` は ICC プロファイルを読み込み、
画像を出力色域に変換して戻した結果を表示し、往復でクリップした
ピクセルをマゼンタで強調します。印刷前の色域チェック用です。

トーンとクリエイティブエフェクト
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

``Extra Tools`` > ``Develop (Non-Destructive)`` には、適用してそのまま保存するワンショットのエフェクトがまとまっています。どれも純粋な NumPy 変換に薄いスライダーダイアログをかぶせたもので（フレームとキャプションだけは Pillow で描画します）、同じロジックは MCP ツールとしても公開されています：

- **段階フィルター**\ （Graduated Density）— 角度・硬さ・オフセットで決まるリニアな ND グラデーション。色付けもでき、手作業のマスクなしで空や前景を暗くできます。
- **トーンイコライザー**\ （Tone Equalizer）— 平滑化したマスク上で、輝度ゾーンごとに独立して露出を調整します（黒レベルから白レベルまで、ゾーンごとに 1 本のスライダー）。調整がシーンの階調に沿います。
- **ディテールイコライザー**\ （Detail Equalizer）— 周波数帯域ごとのゲインスライダー（細かなテクスチャから粗いコントラストまで）。単一のクラリティスライダーに代わるマルチスケールの手段です。
- **フィルミック トーンマップ**\ （Filmic Tone Map）— Reinhard または Hable のハイライトロールオフに、ピボット付きコントラストと彩度の復元を組み合わせます。高コントラストな単一露出向けです。
- **Velvia** — 輝度で重み付けした彩度ブースト。くすんだ色を強め、すでに彩度の高い色とシャドウには手を付けません。
- **フィルムネガ**\ （Film Negative）— スキャンしたカラーネガを反転し、自動推定したオレンジのフィルムベースを除算で取り除きます。出力ガンマのスライダー付き。
- **フリンジ除去**\ （Defringe）— 高コントラストのエッジに沿った紫 / 緑の色収差フリンジを脱色し、平坦な色の部分はそのまま残します。
- **エンボス**\ （Emboss）— 輝度のハイトフィールドから方向光のレリーフを作ります（方位角 / 仰角 / 深さ + グレースケール切り替え）。
- **極座標**\ （Polar Coordinates）— フレームを円盤状に巻き込む、または展開します（タイニープラネット / 極座標反転の表現）。
- **万華鏡**\ （Kaleidoscope）— 1 つの角度ウェッジを ``n`` 回対称にミラーリングします。
- **すりガラス**\ （Frosted Glass）— 決定論的で、シードで再現できる局所ピクセル散乱。
- **フレームとキャプション**\ （Frame & Caption）— 任意の色のマット枠、オプションで下部を太くしたポラロイド風の帯、そこに独自の色で焼き込むキャプション。

GPS ジオタグ
^^^^^^^^^^^^

``Extra Tools`` > ``Library & Metadata`` > ``GPS Geotag`` は既存の EXIF GPS を読み取り、
10 進度単位で編集・設定できます。JPEG は追加パッケージなしでその場で書き込み、
変わるのは EXIF ブロックだけなので、画素・他のタグ・サムネイルはそのままです。
WebP も同じように扱い、その他の形式にはタグ付けできません。

**EXIF エディタ**\ （EXIF サイドバーの ``Edit EXIF`` ボタン）は説明・作者・著作権・カメラのメーカー / モデル・コメントを変更します。JPEG と WebP は追加パッケージ不要で EXIF ブロックだけを書き換えます。その他の形式では編集できない理由が表示されます。説明欄の横にある **説明を生成** は、自分のコンピューター上のビジョンモデルに 1 文の代替テキストを書かせて欄に入れるので、**保存** の前に編集できます。これには ``localhost:11434`` で動く `Ollama <https://ollama.com>`__ とビジョンモデル（``ollama pull llava``）が必要です。応答するモデルがないときはダイアログがそう表示し、欄はそのままにします。画像はそのローカルサーバーにだけ送られます。

Web ギャラリー
^^^^^^^^^^^^^^

``Extra Tools`` > ``Export`` > ``Web Gallery`` は選択した画像（またはフォルダ全体）を
自己完結型のサイトとして書き出します。ライトボックス付きの ``index.html``、JPEG
サムネイル、元画像のコピーが入ります（**元画像をコピー（ポータブル）** のチェックを外すと
元画像はコピーしません）。ページタイトルとサムネイルのサイズ・品質を設定できます。
元画像をコピーした場合はサーバーが不要で、ディスクから直接開くことも、任意の静的
ホスティングに置くこともできます。コピーしない場合、フルサイズへのリンクは自分の
ディスク上の画像を指します。

**クライアントレビュー** にチェックを入れると、ギャラリーを送ってフィードバックを集められます。
各画像の下にコメント欄が付き、コメントはレビュー担当者のブラウザーに保存されます。ページの
**Export comments** ボタンで、すべてのコメントを 1 つの JSON ファイルに保存できます。

印刷レイアウト
^^^^^^^^^^^^^^

``Extra Tools`` > ``Export`` > ``Print Layout`` は複数画像をマルチページ PDF に
レイアウトします。ページサイズ、向き、グリッド、マージン、
ガター、トンボを設定できます。``reportlab`` が必要です。

追加ツールメニュー一覧（Extra Tools）
-------------------------------------

``Extra Tools`` メニューのすべての項目を、サブメニューごとにメニューの順で並べます。多くは上に
詳しい節がありますが、この一覧が完全な目録です。新しいファイルを保存する項目は元画像の隣に書き出し、
その名前が使われている場合は ``_1``、``_2`` … を付けます。「recipe に保存」と記した項目は、画像の
現像設定に対する非破壊の編集です。プラグインはこれらのサブメニューに独自の項目を追加できます。

一括処理（Batch）
^^^^^^^^^^^^^^^^^

.. list-table::
   :header-rows: 1
   :widths: 30 70

   * - 項目
     - 機能
   * - ``Batch Format Conversion``
     - フォルダーの画像（既定では現在のフォルダー）を PNG、JPEG、WebP、BMP、TIFF に、エンコーダーが
       インストールされていれば HEIC / AVIF / JXL に変換します。品質、同じ形式のスキップ、元画像を
       ごみ箱へ送るオプション付き。
   * - ``Batch EXIF Strip``
     - プライバシーのため、フォルダー内のすべての画像から EXIF、GPS などのメタデータを削除します。
       元画像を上書きするか、クリーンなコピーを出力フォルダーに書き出します。
   * - ``Image Sanitizer``
     - フォルダーの画像を生のピクセルから再レンダリングして隠れたデータ（メタデータ、
       ステガノグラフィー、末尾のバイト）をすべて取り除き、各ファイルを日付 + ランダム文字列に
       リネームします。``AI Image Upscale`` と同様に、小さな画像を目標解像度へアップスケールする
       こともできます。
   * - ``Image Organizer``
     - フォルダーの画像を日付（年月または年）、解像度、ファイル形式、ファイルサイズ、またはフォルダー
       ごとの固定枚数でサブフォルダーに振り分けます。コピーか移動かを選べ、プレビュー付きです。
   * - ``Token Batch Rename``
     - 選択した画像（またはフォルダー全体）を ``{name}_{counter:04}`` や ``{date}_{camera}`` の
       ようなトークンテンプレートでリネームします。衝突を示すライブプレビュー付きで、サイドカー、
       評価、タグもファイルに追従します。
   * - ``Deflicker (Time-lapse)``
     - 現在のフォルダーのタイムラプスフレーム間の明るさのばらつきを均し（移動平均または全体平均を
       目標にします）、補正したコピーを ``deflickered/`` サブフォルダーに書き出します。元画像には
       触れません。
   * - ``Document Binarize``
     - ページを撮影またはスキャンした画像を、Sauvola 適応二値化（ウィンドウサイズと k のスライダー）で
       白地に黒のきれいな画像に変換し、元画像の隣に ``<name>_bw.png`` を保存します。
   * - ``Otsu Threshold``
     - 現在の画像を、自動で選ばれる大津の大域しきい値で白黒に変換します。反転オプション付きで、
       ``<name>_otsu.png`` を保存します。
   * - ``Edit Animation``
     - 現在の GIF、APNG、アニメーション WebP を逆再生、ブーメラン、タイミング変更（0.25x 〜 4x）、
       または最適化（繰り返しフレームを結合）し、``<name>_edited.gif`` を保存します。
   * - ``Optimize to Target Size``
     - 現在の画像を、KB 単位のサイズ予算に収まる最高品質で JPEG または WebP に再エンコードし、
       ``<name>_opt.jpg`` または ``<name>_opt.webp`` を保存します。
   * - ``Meme Caption``
     - 現在の画像の上下に定番のミームキャプション（黒い縁取りの大文字の白テキスト、自動折り返し）を
       付け、``<name>_meme.png`` を保存します。
   * - ``Steganography``
     - 現在の画像の最下位ビットにテキストメッセージを隠してロスレスの ``<name>_stego.png`` として
       保存するか、その方法で隠されたメッセージを取り出します。

ライブラリとメタデータ（Library & Metadata）
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

.. list-table::
   :header-rows: 1
   :widths: 30 70

   * - 項目
     - 機能
   * - ``Library Search``
     - ライブラリのルートフォルダーを管理し、インデックスにスキャンして（オプションで知覚ハッシュ付き）、
       ファイル名、最小幅 / 高さ、KB 単位のファイルサイズで検索します。結果をダブルクリックすると
       開きます。
   * - ``Smart Albums``
     - ルールベースのアルバム（拡張子、名前、タグ、場所、最小サイズと評価、カラーラベル、セレクト
       状態、お気に入り）を保存し、一致する画像を表示します。GPS データから都市ごとに 1 つのアルバムを
       作成したり、アルバムをインポート / エクスポートしたりもできます。
   * - ``Find Similar Images``
     - 現在の（または最初に選択した）画像に似たライブラリ画像を、指定したハミング距離以内の知覚
       ハッシュで見つけます。先に ``Library Search`` でルートを pHash 付きでスキャンしてください。
   * - ``Semantic Search``
     - 「夕暮れのビーチ」のようなテキストの説明に一致する画像を、``onnxruntime`` 上の CLIP（初回使用時に
       インストールを提案）で現在のフォルダーから探します。約 150 MB のモデルは一度だけダウンロード
       されます。
   * - ``Find Duplicate Images``
     - フォルダー（オプションでサブフォルダーも）をスキャンし、ファイルハッシュによる完全な重複や、
       知覚ハッシュによる似た画像を探します。各グループで最良の 1 枚以外を事前に選択し、選択した
       ものをごみ箱へ移動できます。
   * - ``Auto-Tag Images``
     - 選択した画像またはフォルダー全体に、ヒューリスティックなコンテンツタグ（photo、document、
       screenshot、graphic、landscape、portrait）を階層タグツリーの ``auto/`` 以下に付けます。
       セマンティック検索がモデルをダウンロード済みなら、CLIP のラベルを付けます。
   * - ``Hierarchical Tags``
     - ``animal/cat/british`` のようなツリー構造のタグを作成・削除し、タグ配下の画像を一覧表示し、
       選択したタイルにタグを付けたり外したりします。
   * - ``Export Metadata (CSV / JSON)``
     - 現在のビューの各画像について 1 件のレコード（ファイル情報、カメラ・レンズ・露出・ISO などの
       主要な EXIF 項目、評価、カラーラベル、タグ、メモ）を CSV または JSON ファイルに書き出します。
   * - ``XMP Sidecars``
     - 現在のビューのすべての画像について ``.xmp`` サイドカーファイルを書き出し / 読み込みし、評価、
       タイトル、説明、キーワード、カラーラベルを Adobe Bridge、Lightroom などの XMP 対応ツールと
       往復させます。
   * - ``GPS Geotag``
     - 現在の画像の EXIF GPS タグに緯度と経度（10 進度）を書き込み、既存の値を置き換えます。JPEG と
       WebP ファイルのみ対応です。
   * - ``Geotag from GPX Track``
     - 選択した画像（またはビュー全体）を EXIF の撮影日時で ``.gpx`` トラックと照合します。カメラの時計が
       UTC からどれだけずれていたか、写真がトラックポイントからどれだけ離れていてよいか（ポイント間を
       補間するかどうか）を設定し、何枚がトラック上に収まるかを確認してから、位置を EXIF GPS タグに
       書き込みます。JPEG と WebP ファイルのみ対応です。
   * - ``Edit Capture Time``
     - 選択した画像（またはビュー全体）の EXIF 撮影日時を、日・時・分・秒単位で、または最初の写真を
       実際に撮影した日時を基準にずらし、DateTimeOriginal、DateTimeDigitized、DateTime を書き換えます。
       EXIF 撮影日時のない写真はそのままで、書き換えられるのは JPEG と WebP のみです。
   * - ``Metadata Template``
     - 選択した画像（またはビュー全体）に、タイトル、説明、カンマ区切りのキーワードを付けます。
       ``{filename}``、``{name}``、``{folder}``、``{date}``、``{year}`` は写真ごとに埋められます。
       **空の項目だけ埋める（キーワードは追加）** がオンなら、写真は自分のタイトルと説明を残して
       キーワードが加わり、オフならテンプレートがそれらを置き換え、テンプレートのキーワードが写真の
       タグを置き換えます。適用前に確認し、テンプレートを記憶します。結果は ``XMP Sidecars`` と
       ``Export Metadata`` で書き出します。
   * - ``Thumbnail Cache``
     - サムネイルキャッシュが使っているディスク容量を表示し、消去します。

表示（Views）
^^^^^^^^^^^^^

.. list-table::
   :header-rows: 1
   :widths: 30 70

   * - 項目
     - 機能
   * - ``By day``
     - ``Timeline View`` のサブメニュー：メインビューを、撮影日（EXIF の日付、なければファイルの日付）
       ごとの見出しでまとめた現在のフォルダーの画像に置き換えます。画像をダブルクリックすると開きます。
   * - ``By month``
     - ``Timeline View`` のサブメニュー：同じタイムラインを撮影月ごとにまとめます。
   * - ``By year``
     - ``Timeline View`` のサブメニュー：同じタイムラインを撮影年ごとにまとめます。
   * - ``Calendar View``
     - 現在のフォルダーに写真がある日（撮影日による）を強調したカレンダーを表示します。日をクリック
       するとその日の画像を一覧表示し、ダブルクリックで開きます。
   * - ``Map View``
     - 現在のフォルダーのジオタグ付き画像を OpenStreetMap の地図にプロットします。マーカーは最寄りの
       都市ごとに 1 つで、枚数を示します。地図はオンラインで読み込み、QtWebEngine がない場合は座標の
       リストにフォールバックします。
   * - ``Scopes & Inspector``
     - 現在の画像をタブで分析します：輝度波形、RGB パレード、フォールスカラー露出、フォーカス
       ピーキング、Error Level Analysis、クローン（コピー＆ムーブ）検出。
   * - ``Tiny Planet (360°)``
     - 2:1 の正距円筒図法の 360° パノラマを、指定サイズの正方形の「リトルプラネット」に再投影し、
       ``<name>_planet.png`` を保存します。画像が 2:1 でない場合は警告します。
   * - ``Image Statistics``
     - 現在の画像の R、G、B、輝度チャンネルの平均、最小、最大、標準偏差、中央値を表示し、256 階調の
       ヒストグラムを CSV でエクスポートします。
   * - ``Quality Report``
     - 現在の画像の無参照品質メトリクスを一覧表示します：colourfulness、階調エントロピー、RMS
       コントラスト、エッジ密度、推定ノイズ。
   * - ``Test Chart``
     - キャリブレーションパターン（SMPTE カラーバー、グレースケールウェッジ、グラデーションランプ、
       チェッカーボード、単色）を指定した幅と高さで生成し、ファイルに保存します。
   * - ``Off``
     - ``Color blindness preview`` のサブメニュー：色覚異常のプレビューをオフにします。
   * - ``Protanopia (red-blind)``
     - ``Color blindness preview`` のサブメニュー：1 型色覚の人の見え方で画像をビューアーに表示します。
       表示のみで、ファイルとその recipe には触れません。
   * - ``Deuteranopia (green-blind)``
     - ``Color blindness preview`` のサブメニュー：最も一般的な赤緑色覚異常である 2 型色覚を
       シミュレートします。表示のみです。
   * - ``Tritanopia (blue-blind)``
     - ``Color blindness preview`` のサブメニュー：3 型色覚（青黄色覚異常）をシミュレートします。
       表示のみです。
   * - ``Achromatopsia (greyscale)``
     - ``Color blindness preview`` のサブメニュー：全色盲のように、画像を完全なグレースケールで表示
       します。表示のみです。

ワークフロー（Workflow）
^^^^^^^^^^^^^^^^^^^^^^^^

.. list-table::
   :header-rows: 1
   :widths: 30 70

   * - 項目
     - 機能
   * - ``Culling``
     - 現在のフォルダーを Pick、Reject、フラグなしの画像で絞り込みます。似た画像のグループごとに
       最もシャープな画像を Pick にして残りを Reject にする自動セレクトができ、Reject の画像を
       すべて完全に削除することもできます。
   * - ``Staging Tray``
     - フォルダーをまたいで保持されるカゴ：任意のフォルダーから選択したタイルや現在の画像を追加し、
       すべてを 1 つのフォルダーへ移動またはコピーするか、トレイをアルバムとして表示します。
   * - ``Reference Panel``
     - 参照画像（ファイルから、ドラッグ＆ドロップで、または現在の画像から追加）を大きなプレビュー付きで
       ピン留めし、並べて比較できます。リストは再起動後も保持されます。
   * - ``Virtual Copies``
     - 現在の画像の現像 recipe の名前付きスナップショットを保存し、ファイルを複製せずに切り替えます。
   * - ``Dual-Pane File Manager``
     - 2 つのフォルダーツリーを並べ、一方から他方へ選択をコピーまたは移動したり、ファイルをビューアーで
       開いたりします。
   * - ``Macros``
     - 選択した画像に対する評価、お気に入り、カラーラベル、タグの操作のマクロを記録、編集、整理、
       再生します。
   * - ``Watched Folder``
     - ダイアログを開いている間、フォルダー（サブフォルダーを含む）を監視し、届いた新しい画像すべてに
       指定した現像プリセットを割り当てます。テザー撮影や取り込みのワークフローを手放しで回せます。

書き出し（Export）
^^^^^^^^^^^^^^^^^^

.. list-table::
   :header-rows: 1
   :widths: 30 70

   * - 項目
     - 機能
   * - ``Contact Sheet PDF``
     - 選択した画像（またはフォルダー全体）のサムネイルを、A4、A3、Letter、Legal のページに
       行 × 列のグリッドで配置します。余白、オプションのタイトル、オプションのファイル名キャプション
       付き。**レイアウト** ボックスでプリセットを選ぶと設定がまとめて入ります（数値は列 × 行）：
       標準（4 × 5、10 mm、キャプションあり）、コンパクト（6 × 8、5 mm、キャプションなし）、
       校正（5 × 6、8 mm、キャプションあり）、エディトリアル（2 × 3、18 mm、キャプションあり）、
       インデックス（8 × 10、4 mm、キャプションなし）。グリッド、余白、キャプションのどれかを手で
       変更するとカスタムになります。
   * - ``Web Gallery``
     - 選択した画像（またはフォルダー全体）を、サムネイルとライトボックス付きの自己完結型 HTML
       ギャラリーとして書き出します。元画像をコピーしたり、JSON で書き出せるクライアントレビュー用の
       コメント欄を追加したりできます。
   * - ``Slideshow Video``
     - 選択した画像（またはフォルダー全体）を、指定したサイズ、フレームレート、表示時間、品質、
       トランジション（フェード、ディゾルブ、スライド、ワイプ）で MP4 にレンダリングします。
   * - ``Print Layout``
     - ページサイズ、向き、行、列、余白、ガター、トンボを指定して、画像を複数ページの PDF グリッドに
       並べます。オプションの ``reportlab`` パッケージが必要です。
   * - ``Collage``
     - 選択した画像（またはフォルダー全体）を 1 〜 12 列のグリッドモンタージュに合成し、最初の画像の
       隣に ``collage.png`` を保存します。
   * - ``ID Photo Sheet``
     - 現在のポートレートを証明写真のサイズ（35 x 45 mm、2 x 2 in、33 x 48 mm、50 x 70 mm）で
       4x6、5x7、A4、Letter の用紙に 300 DPI で並べ、``<name>_idsheet.png`` を保存します。

現像（Develop (Non-Destructive)）
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

.. list-table::
   :header-rows: 1
   :widths: 30 70

   * - 項目
     - 機能
   * - ``Before / After Compare``
     - 現在の画像を現像 recipe なしとありで 1 つのビューに表示し、ドラッグできる境界線で分割します。
   * - ``Develop Presets…``
     - 現在の画像の recipe を名前付きプリセットとして保存し、現在の画像や選択に適用するか、有効な
       調整だけをそれぞれの recipe にマージします。
   * - ``Tone Curve``
     - マスター RGB カーブと、赤・緑・青の個別カーブをヒストグラム上で編集します（クリックで
       ポイント追加、ドラッグで移動、右クリックで削除）。recipe に保存。
   * - ``Apply .cube LUT``
     - Adobe ``.cube`` の 3D または 1D LUT を調整可能な強度で適用します。recipe に保存され、
       ``Clear`` で削除します。
   * - ``Split Toning``
     - シャドウとハイライトに別々の色相と彩度で色を付けます。バランススライダー付き。recipe に保存。
   * - ``Local Adjustment Masks``
     - ブラシ、放射、線形グラデーションのマスクを追加します。各マスクに露出、明るさ、コントラスト、
       彩度、色温度、色合い、ハイライト、シャドウ、ぼかしを個別に設定できます。recipe に保存。
   * - ``Layers``
     - 最大 8 つのテキスト、画像、LUT のオーバーレイレイヤーを、不透明度と通常 / 乗算 / スクリーン /
       オーバーレイの合成で重ねます。recipe に保存。
   * - ``Levels``
     - 黒点、白点、ガンマを設定します。recipe に保存。
   * - ``Channel Mixer``
     - 各出力チャンネルを、重み付けした赤・緑・青の入力とオフセットから作り直します。白黒変換用の
       モノクロモード付き。recipe に保存。
   * - ``Gradient Map``
     - 輝度をプリセットのグラデーション（Mono、Sepia、Cyanotype、Fire、Ocean、Magenta–Teal）で
       調整可能な強度でマッピングします。オプションで知覚的な OkLCH でブレンドします。recipe に保存。
   * - ``Auto Color Balance``
     - gray-world、white-patch、auto-levels（パーセンタイル）、Retinex の手法で色かぶりを取り除き、
       強度スライダーでブレンドして ``<name>_balanced.png`` を保存します。
   * - ``Clarity / Dehaze``
     - かすみ除去、明瞭度、テクスチャの局所コントラストスライダーを適用し、``<name>_local.png`` を
       保存します。
   * - ``HSL / Color Mixer``
     - 8 つの色帯域（赤からマゼンタまで）ごとに色相、彩度、輝度を個別に調整し、``<name>_hsl.png`` を
       保存します。
   * - ``CLAHE (Local Equalize)``
     - 輝度にコントラスト制限付き適応ヒストグラム平坦化（クリップ上限とタイル数）をかけて局所
       コントラストを高め、``<name>_clahe.png`` を保存します。
   * - ``Flatten Background``
     - 光害やむらのある照明のような滑らかな背景グラデーション（減算）や周辺減光（除算）を調整可能な
       度合いで取り除き、``<name>_flat.png`` を保存します。
   * - ``Frame & Caption``
     - 色付きのマット枠、オプションのポラロイド風の下部帯、キャプションを追加し、``<name>_framed.png``
       を保存します。
   * - ``Ordered Dither``
     - Bayer 組織的ディザパターンで各チャンネルを 2 〜 8 階調に減らしてレトロな印刷風にし、
       ``<name>_dither.png`` を保存します。
   * - ``Color Map``
     - 画像の輝度を viridis、magma、jet のカラーマップで再着色し、``<name>_colormap.png`` を保存します。
   * - ``Distort``
     - 調整可能な強さで画像を渦巻き、つまみ / 膨らみ、波紋に変形し、``<name>_distort.png`` を保存
       します。
   * - ``Polar Coordinates``
     - 画像を円盤状に巻き込むか、円盤を帯状に展開し（オプションで半径を反転）、``<name>_polar.png`` を
       保存します。
   * - ``Kaleidoscope``
     - 1 つのくさびを中心の周りに鏡映して、指定したセグメント数と回転の対称パターンにし、
       ``<name>_kaleidoscope.png`` を保存します。
   * - ``Frosted Glass``
     - 各ピクセルを近くのランダムな位置に散らして（ピクセル単位の半径、再現可能なシード）すりガラス
       風にし、``<name>_frosted.png`` を保存します。
   * - ``Pixel Sort``
     - 明るさの下限 / 上限の帯域内で、行または列に沿ってピクセルを明るさで並べ替えてグリッチ風にし、
       ``<name>_pixelsort.png`` を保存します。
   * - ``Film Grain``
     - 強度、粒子サイズ、モノクロ、シードを調整できるプロシージャルなフィルムグレインを追加します。
       recipe に保存。
   * - ``Lens Flare``
     - 指定した位置に、強度、ハローのサイズ、色を調整できる合成レンズフレアを追加します。recipe に保存。
   * - ``Threshold / Posterize``
     - 白黒のしきい値（0 〜 255）を適用するか、各チャンネルを 2 〜 64 階調にポスタリゼーションするか、
       その両方を行います。recipe に保存。
   * - ``Solarize``
     - しきい値より上の階調を反転して暗室のソラリゼーション風にし、ミックススライダーでブレンドして
       ``<name>_solarize.png`` を保存します。
   * - ``Diffuse Glow``
     - 量、半径、ハイライトのしきい値を調整できるオートン風のソフトなブルームを追加し、
       ``<name>_glow.png`` を保存します。
   * - ``Graduated Density``
     - 段階 ND フィルターのように、直線に沿ってフレームの片側を暗くし（角度、段数、硬さ、オフセット、
       オプションの色付け）、``<name>_gradnd.png`` を保存します。
   * - ``Velvia``
     - Velvia スライドフィルムのように、くすんだ色ほど強く彩度を上げます。強さとシャドウ保護の
       スライダー付きで、``<name>_velvia.png`` を保存します。
   * - ``Emboss``
     - 指定した方位角と仰角から照らしたレリーフを作ります。深さスライダーとグレースケールの
       オプション付きで、``<name>_emboss.png`` を保存します。
   * - ``Defringe``
     - 高コントラストのエッジに沿った紫、緑、またはすべての色のフリンジを脱色します。量とエッジ
       しきい値のスライダー付きで、``<name>_defringe.png`` を保存します。
   * - ``Film Negative``
     - スキャンしたカラーネガをポジに反転し、オレンジのフィルムベース（自動推定）を取り除きます。
       出力ガンマ付きで、``<name>_positive.png`` を保存します。
   * - ``Filmic Tone Map``
     - Reinhard または Hable のフィルミックカーブでハイライトをロールオフします。露出、白点、
       コントラスト、彩度のスライダー付きで、``<name>_filmic.png`` を保存します。
   * - ``Tone Equalizer``
     - 黒、シャドウ、中間調、ハイライト、白の露出を個別に設定し、ハローを避けるために平滑化して
       ``<name>_toneeq.png`` を保存します。
   * - ``Detail Equalizer``
     - 細かい、中程度、粗い、広いディテール帯域ごとにコントラストを強めたり弱めたりし、
       ``<name>_detaileq.png`` を保存します。
   * - ``Soft Proof``
     - 指定した ICC 出力プロファイルを通して現在の画像をプレビューし、色域外のピクセルをマゼンタで
       塗って数えます。何も保存しません。

レタッチと変形（Retouch & Transform）
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

.. list-table::
   :header-rows: 1
   :widths: 30 70

   * - 項目
     - 機能
   * - ``AI Image Upscale``
     - 画像のフォルダーを Real-ESRGAN（汎用 x4、アニメ x4、x2）または Lanczos、Bicubic、Nearest の
       リサンプリングでアップスケールします。AI モデルは必要に応じて ``onnxruntime`` をインストールし、
       初回使用時に自動でダウンロードされます（約 65 MB）。
   * - ``Noise Reduction / Sharpening``
     - エッジを保持するノイズ低減（オプションで輝度のみ）と、量と半径を指定するアンシャープマスクの
       シャープニングを適用し、指定したファイルに保存します。OpenCV（``opencv-python``）が必要です。
   * - ``Healing Brush``
     - プレビュー上でクリックしたスポット（右クリックでスポットを削除）を Telea または Navier-Stokes
       法のインペインティングで取り除き、指定したファイルに保存します。OpenCV が必要です。
   * - ``Clone Stamp``
     - Shift+クリックしたソース点から、プレビュー上でクリックした各点へ縁の柔らかいパッチをコピーし
       （右クリックで取り消し）、結果を指定したファイルに保存します。
   * - ``Frequency Separation``
     - 現在の画像を指定したぼかし半径で ``<name>_low.png``\ （色と階調）と
       ``<name>_high.png``\ （テクスチャ）に分け、他のアプリでレタッチできるようにします。
       low + (high - 128) で再合成します。
   * - ``Smart Crop``
     - 被写体を三分割法の点に置く、顕著性に基づくトリミング（フリー、1:1、4:5、3:2、16:9）を提案し、
       選んだものを非破壊のトリミングとして recipe に書き込みます。
   * - ``Portrait Auto-Retouch``
     - 肌色の領域を滑らかにし、赤目を除去し、最後にシャープニングをかけます。それぞれ専用の
       スライダー付きで、``<name>_retouched.png`` を保存します。
   * - ``Face Detection``
     - OpenCV の Haar カスケードで現在の画像の顔を検出し、それぞれに名前を付けられます。名前は
       recipe と一緒に保存されます。OpenCV 4（``opencv-python<5``）が必要です。
   * - ``Sky / Background``
     - 空をグラデーションに置き換えるか、背景を取り除いて透明または白にし、指定したファイルに保存
       します。OpenCV が必要で、``rembg`` がインストールされていれば背景の切り抜きに使います。
   * - ``Crop / Straighten``
     - 最大 ±15° 回転し（空いた四隅は切り落とします）、正規化座標またはアスペクト比のプリセットで
       トリミングして、指定したファイルに保存します。水平補正には OpenCV が必要です。
   * - ``Auto-Straighten``
     - 地平線や垂直線の傾きを測定し、回転を調整できるようにしてから、補正した画像を指定した
       ファイルに保存します。OpenCV が必要です。
   * - ``Lens Correction``
     - 樽型 / 糸巻き型の歪曲、周辺減光、赤 / 青の色収差をスライダーで補正し、指定したファイルに
       保存します。
   * - ``Scale Bar``
     - 単位あたりのピクセル数と単位ラベルから、校正済みのスケールバーを現在の画像に焼き込み、
       ``<name>_scalebar.png`` を保存します。

マルチ画像（Multi-Image）
^^^^^^^^^^^^^^^^^^^^^^^^^

.. list-table::
   :header-rows: 1
   :widths: 30 70

   * - 項目
     - 機能
   * - ``HDR Merge``
     - 露出の異なる 2 枚以上の写真を Mertens 露出融合（露出データ不要）で合成します。オプションで
       事前に位置合わせします。OpenCV が必要です。
   * - ``Panorama Stitch``
     - 20 〜 40 % 重なるよう順番に撮影した 2 枚以上の写真を、パノラマまたはフラットスキャンモードで
       つなぎ合わせます。オプションで黒い縁をトリミングします。OpenCV が必要です。
   * - ``Focus Stacking``
     - 各フレームから最もシャープなピクセルを残して、フォーカスブラケットを 1 枚の全焦点画像に
       合成します。オプションで事前に位置合わせします。OpenCV が必要です。
   * - ``Image Stack``
     - 位置合わせ済みの連写をピクセルごとに平均、中央値、最大、最小、シグマクリップ平均で合成します。
       長時間露光、人物の除去、星の軌跡に使えます。OpenCV は不要です。
   * - ``Anaglyph 3D``
     - 現在の画像（左目）と指定した右目用の画像を赤シアンのアナグリフ（Dubois、カラー、グレー、
       トゥルーの方式）に合成し、``<name>_anaglyph.png`` を保存します。

コマンドライン
--------------

::

   python -m Imervue                      # 通常起動
   python -m Imervue /path/to/image       # 指定した画像を開く
   python -m Imervue /path/to/folder      # 指定したフォルダを開く
   python -m Imervue --debug              # デバッグモードを有効化
   python -m Imervue --software_opengl    # ソフトウェアレンダリングを使用（GPU 非対応時）

ヘッドレスバッチ CLI
^^^^^^^^^^^^^^^^^^^^

``Imervue.cli`` は **Qt を起動せずに** 純粋な画像処理をシェルから実行します。
スクリプト、CI ステップ、ディスプレイのないサーバーで使えます::

   py -m Imervue.cli resize photos/ --max 1600 --out web/
   py -m Imervue.cli watermark a.jpg --text "(c) Me" --corner bottom-right
   py -m Imervue.cli info *.png --json
   py -m Imervue.cli list-ops          # 利用可能なサブコマンドを一覧表示

.. list-table::
   :header-rows: 1
   :widths: 30 70

   * - サブコマンド
     - 用途
   * - ``info`` / ``stats``
     - 寸法とフォーマット、無参照品質メトリクス(``--json`` で機械可読出力)
   * - ``convert`` / ``resize`` / ``thumbnail``
     - フォーマット変換(``--format`` JPEG / PNG / WEBP / TIFF / BMP / AVIF / HEIC / JXL、``--quality``)、
       長辺(``--max``)または正確な ``--width`` / ``--height`` へのリサイズ、サムネイルサイズ
   * - ``watermark`` / ``optimize``
     - テキスト透かし(``--text``、``--corner``、``--opacity``、``--font-fraction``、
       ``--color R G B``、``--no-shadow``)、``--max-kb`` 予算内でのエンコード
   * - ``dehaze`` / ``clahe`` / ``dither`` / ``distort``
     - ダークチャネル除霞、適応等化、Bayer 秩序ディザ、swirl / pinch / ripple
   * - ``auto-orient`` / ``strip``
     - EXIF 方向フラグをピクセルに焼き込み、EXIF / XMP / ICC を除いて再保存
   * - ``collage`` / ``anaglyph``
     - グリッドモンタージュ(``--columns``、``--cell-width`` / ``--cell-height``、``--gap``、
       ``--margin``、``--background R G B``)、ステレオペアから赤シアン 3D(``--method``)
   * - ``preset`` / ``pipeline``
     - 保存済み現像プリセットを名前で適用、順序付き JSON パイプラインを実行
   * - ``list-ops``
     - 全サブコマンドを一覧表示(``--json`` で機械可読出力)

すべてのサブコマンドはビューアーと同じくデコードします：出力は EXIF の向きで正立させ、埋め込みカラープロファイルから sRGB に変換します。AVIF の入力は Pillow 自身が読み込み、HEIC / JPEG XL の入力は、対応するオプションのバックエンドがインストールされていれば読み込めます。カメラ RAW は小さな埋め込みプレビューではなく、ビューアーと同じく現像して読み込みます。``resize`` と ``strip`` は PNG で書き出します。読めないファイルは報告され、残りはそのまま処理されます。途中で切れたファイルは、ビューアーと同じく読める所まで読み込みます。16 ビット・浮動小数点のグレースケールはビューアーと同じく 8 ビットにスケーリングします。``resize`` と ``strip`` は元のビット深度を保ちます。

ファイルやフォルダを受け取るサブコマンド(``collage``、``anaglyph``、``list-ops`` 以外のすべて)は、``--out``\ (出力ディレクトリ)、``--recursive``、``--dry-run``\ (アクションを列挙するだけで書き込まない)、``--overwrite``、``-j`` / ``--jobs``\ (並列ワーカー数。``0`` ですべてのコアを使用)を共通で受け付けます。``collage`` と ``anaglyph`` は ``--out`` で指定した 1 つのファイルに書き出します。``--version`` は CLI のバージョンを表示します。

MCP サーバー(`MCP Server`_ を参照)のすべてのツールはサブコマンドとしても使えます。
そのうち 10 個は上記のサブコマンドです(``convert_format`` は ``convert``、``quality_metrics`` は ``stats``、
``build_collage`` は ``collage`` など)。残りの 48 個は MCP ツール自身のコードを実行します:

.. list-table::
   :header-rows: 1
   :widths: 30 70

   * - 種類
     - サブコマンド
   * - 編集: 各元画像の隣に ``<stem>_<name>.png`` を、または ``--out`` 内に ``<stem>.png`` を書き出す
     - ``frame``、``crop``、``rotate``、``solarize``、``glow``、``velvia``、``emboss``、``film-negative``、``defringe``、``graduated-density``、``filmic-tonemap``、``tone-equalizer``、``detail-equalizer``、``colormap``、``false-color``、``split-toning``、``pixel-sort``、``polar``、``kaleidoscope``、``frosted-glass``、``local-contrast``、``posterize``、``gradient-map``、``film-grain``、``levels``、``auto-color-balance``、``channel-mixer``、``curve``、``lens-correction``
   * - その他の出力
     - ``ela``\ (Error Level Analysis マップを PNG で出力)、``video-frame``\ (動画の 1 フレーム、
       ``--frame-index``)、``puppet-from-png``\ (``.puppet`` rig、``--cell-size``)
   * - レポート: 画像ごとに 1 件の結果、``--json`` で機械可読出力
     - ``metadata``、``xmp``、``gps``、``dominant-colors``、``sharpness``、``statistics``、``histogram``、``ocr``、``puppet-inspect``、``puppet-validate``
   * - 1 回だけ実行して JSON を表示
     - ``list-images FOLDER``、``search FOLDER --query "..."``、``similar FOLDER``、
       ``collection-stats FOLDER``、``reverse-geocode --latitude .. --longitude ..``、
       ``puppet-schema --name ..``

MCP の各パラメーターは、同じ既定値と許容値を持つオプションになります。
``zone_gains`` は ``--zone-gains`` に、はい/いいえのパラメーターは ``--grayscale`` / ``--no-grayscale`` になり、
色や行列の行は値を順に並べて指定します(``--red 1 0 0``)。
``py -m Imervue.cli <subcommand> --help`` で一覧を表示できます::

   py -m Imervue.cli film-grain photos/ --intensity 0.4 --seed 7 --out grain/
   py -m Imervue.cli crop a.jpg --x 0 --y 0 --width 800 --height 600
   py -m Imervue.cli histogram a.jpg --json
   py -m Imervue.cli search photos/ --query "ext:jpg width:>1920"

``pipeline FILE INPUTS…`` は各入力に一連の処理を順に実行し、入力ごとに 1 つの PNG を書き出します：
元画像の隣に ``<stem>_pipeline.png``、または ``--out`` 内に ``<stem>.png``。``FILE`` は UTF-8 の
JSON（BOM 付きでも可）で、ステップのリストか、オブジェクト ``{"pipeline": [...]}`` を持ちます。
各ステップは、処理名を示す ``"op"`` とその処理のパラメーターからなるオブジェクトです。省略した
パラメーターは既定値になり、op が知らないキーは無視されます。パイプラインは最大 50 ステップで、
空のパイプラインは各入力をデコードしたまま書き出します。ファイルは画像を読む前に検査されます：
読めない、または解析できないファイルは ``error: …`` を表示し、50 を超えるステップ、``"op"`` 名の
ないステップ、未知の op は問題ごとに 1 行の ``pipeline error: step N: …`` を表示します。いずれの
場合もコマンドは終了コード 2 で終了し、何も書き出しません。型の誤ったパラメーター（``null`` や、
数値の位置にあるテキスト）はその画像を失敗させて報告し、終了コードは 1 になります。

.. list-table::
   :header-rows: 1
   :widths: 14 44 42

   * - op
     - パラメーター（既定値）
     - 効果
   * - ``dehaze``
     - ``strength``\ （``1.0``。0 – 1 にクランプ）
     - ダークチャネルプライアによるかすみ除去。``0`` では画像は変わりません
   * - ``clahe``
     - ``clip``\ （``2.0``。1 以上）、``tiles``\ （``8``。1 以上）
     - ``tiles`` × ``tiles`` のグリッドで輝度をコントラスト制限付き適応平坦化します
   * - ``dither``
     - ``levels``\ （``2``。2 – 8 にクランプ）
     - 4×4 の Bayer 組織的ディザでチャンネルあたり ``levels`` 階調にします。アルファは保持
   * - ``distort``
     - ``mode``\ （``"swirl"``：``swirl`` / ``pinch`` / ``ripple``）、``strength``\ （``0.5``。
       範囲は -1 – 1 にクランプ）
     - 中心を基準にした幾何学的な変形。``pinch`` では正の強さで膨らみ、負の強さでつまみます
   * - ``clarity``
     - ``amount``\ （``0.5``。-1 – 1、負の値で柔らかく）
     - 中間調に重みを付けた、大半径の局所コントラスト
   * - ``texture``
     - ``amount``\ （``0.5``。-1 – 1、負の値で柔らかく）
     - 小半径の、細部の局所コントラスト
   * - ``grayscale``
     - なし
     - 輝度（0.299 R + 0.587 G + 0.114 B）を 3 チャンネルすべてに入れます。アルファは保持
   * - ``invert``
     - なし
     - R、G、B を反転します。アルファは保持
   * - ``watermark``
     - ``text``\ （``""``：透かしなし）、``corner``\ （``"bottom-right"``：``top-left`` /
       ``top-right`` / ``bottom-left`` / ``bottom-right`` / ``center``。それ以外の値は
       ``bottom-right`` として扱います）、``opacity``\ （``0.6``。0 – 1 にクランプ）
     - ドロップシャドウ付きの白いテキストで、サイズは長辺の 3.5 %。``watermark`` サブコマンドの
       ``--font-fraction``、``--color``、``--no-shadow`` に対応するステップパラメーターはありません

例として ``look.json`` を示します::

   {
     "pipeline": [
       {"op": "dehaze", "strength": 0.4},
       {"op": "clahe", "clip": 2.5, "tiles": 8},
       {"op": "clarity", "amount": 0.3},
       {"op": "watermark", "text": "(c) Me", "corner": "bottom-right", "opacity": 0.5}
     ]
   }

   py -m Imervue.cli pipeline look.json photos/ --out graded/

----

MCP Server
----------

Imervue には組み込みの `Model Context Protocol <https://modelcontextprotocol.io>`_
サーバが同梱されており、AI アシスタント（Claude Code、Claude Desktop、Cursor、
Cline、…）が GUI を起動せずにプロジェクトの純粋ロジックヘルパーを呼び出せます。
次のコマンドで起動します::

   python -m Imervue.mcp_server

サーバは Qt 非依存で、各ツールが呼び出し時に必要とするものだけをロードします。

利用可能なツール
^^^^^^^^^^^^^^^^

.. list-table::
   :header-rows: 1
   :widths: 28 72

   * - Tool
     - 用途
   * - ``list_images``
     - フォルダ内の画像ファイル（パス、サイズ、mtime）を一覧表示します。
       ``recursive=true`` を渡すとサブフォルダも走査します。
   * - ``read_image_metadata``
     - 1 枚の画像の寸法、フォーマット、EXIF タグ、XMP フィールド(サイドカー、なければ埋め込み)を返します。
       欠落しているデータは例外を送出せず、適切な空の値として報告されます。
   * - ``read_xmp_tags``
     - XMP(サイドカー、なければ埋め込み)のみを読み取る高速パス — レーティング、カラーラベル、
       キーワード、タイトル、説明。
   * - ``convert_format``
     - 1 枚の画像を別のフォーマットに変換します。出力フォーマットは出力先の拡張子
       （``png`` / ``jpg`` / ``jpeg`` / ``webp`` / ``tiff`` / ``bmp`` / ``avif``。
       オプションのバックエンドがあれば ``heic`` / ``jxl`` も）から推測されます。
       オプションの ``quality``\ （1–100）は JPEG / WebP / AVIF / HEIC / JXL に適用されます。
   * - ``puppet_from_png``
     - Puppet プラグインのオートメッシュを使って PNG から ``.puppet`` rig を構築します。
       Cubism 標準のパラメータカタログをシードするため、rig はただちに駆動可能になります。
   * - ``puppet_inspect``
     - ``.puppet`` アーカイブを開き、構造化されたインベントリを返します:
       drawables、deformers、parameters、motions、expressions、hit areas、
       parts、parameter blends、physics rigs。
   * - ``puppet_validate`` / ``puppet_schema``
     - ``.puppet`` を v1 フォーマット（JSON Schema、ローダーの規則、rig チェック）に照らして検証します。
       公開されている 4 つの JSON Schema のうち 1 つを返します。
   * - ``image_statistics`` / ``quality_metrics`` / ``read_histogram``
     - チャンネルごとの平均/最小/最大/標準偏差/中央値、参照なしの品質メトリクス
       （colourfulness、entropy、contrast、edge density、noise）、および
       オーバー/アンダークリッピング比率を含む 256 ビンのヒストグラム。
   * - ``sharpness_score`` / ``ocr_text`` / ``image_thumbnail``
     - ラプラシアン分散によるブレスコア、Tesseract OCR テキスト（未インストール時は
       グレースフルに処理）、および上限付きの base64 PNG プレビュー。
   * - ``find_similar``
     - 知覚ハッシュ（ハミング距離のしきい値）でほぼ重複した画像をグループ化します。
       progress token が渡された場合はファイルごとの進捗を報告します。
   * - ``apply_watermark`` / ``apply_frame``
     - テキストの透かしを焼き込むか、画像をマット / ポラロイドフレームで囲み、
       オプションでキャプションを付けます。
   * - ``build_collage``
     - 複数の画像をグリッドモンタージュに合成します（列数、セルサイズ、間隔、余白、
       背景を設定可能）。進捗を報告します。
   * - ``crop_image`` / ``resize_image`` / ``rotate_image``
     - ピクセルボックスのクロップ、リサイズ（辺を 1 つ指定するとアスペクト比を維持、
       2 辺とも指定すると正確なサイズ）、およびロスレスな 90/180/270 回転または
       水平/垂直反転。
       サイズと座標は EXIF の向きを適用した画像が基準です。
   * - ``collection_stats``
     - フォルダのレーティング、お気に入り、カラーラベル、選別状態を要約します
       （カウント、0–5 星の分布、平均）。
   * - ``reverse_geocode`` / ``extract_video_frame``
     - GPS 座標をオフラインで最寄りの都市に解決し、動画の 1 フレームを静止画に
       デコードします。
   * - ``extract_gps`` / ``dominant_colors``
     - EXIF の GPS 緯度 / 経度を読み取り（結果はそのまま ``reverse_geocode`` に渡せます）、
       メディアンカットでカラーパレット（rgb / hex / ピクセル数）を抽出します。
   * - ``error_level_analysis``
     - JPEG 再圧縮による Error Level Analysis の改ざんマップを PNG データ URI で返します
       （編集された領域が背景から浮かび上がります）。
   * - ``search_images``
     - スマートアルバムのクエリ DSL（拡張子 / 名前 / サイズ / 寸法 / アスペクト比 /
       EXIF のカメラ / レンズ / 撮影地）でフォルダを絞り込みます。
   * - ``solarize_image`` / ``glow_image``
     - ソラリゼーションによる階調反転、またはディフューズグロー / オートン効果を適用し、
       結果を保存します。
   * - ``velvia_image`` / ``emboss_image`` / ``defringe_image``
     - 輝度で重み付けした Velvia 風の彩度強調、指向性ライトによるエンボス、
       紫 / 緑のエッジフリンジの彩度低減。
   * - ``film_negative_image`` / ``graduated_density_image``
     - スキャンしたカラーネガを反転（フィルムベースは自動検出）し、線形の
       グラデーション ND フィルターを適用します。
   * - ``filmic_tonemap_image`` / ``tone_equalizer_image`` / ``detail_equalizer_image``
     - Reinhard / Hable によるフィルミックなハイライトロールオフ、輝度ゾーンごとの露出、
       周波数帯域ごとのコントラスト。
   * - ``colormap_image`` / ``false_color_image``
     - 輝度を viridis / magma / jet の知覚的カラーマップで再着色するか、
       フォールスカラーの露出スケールに割り当てます。
   * - ``dither_image`` / ``split_toning_image`` / ``pixel_sort_image``
     - チャンネルあたり数階調への組織的（Bayer）ディザリング、シャドウ / ハイライトの
       スプリットトーン、明るさの帯域によるピクセルソート。
   * - ``polar_image`` / ``kaleidoscope_image``
     - 直交座標と極座標の相互変換（リトルプラネット）、またはフレームを指定した数の
       万華鏡のくさびに鏡映します。
   * - ``frosted_glass_image`` / ``clahe_image`` / ``local_contrast_image``
     - ランダムな近傍ピクセルによるすりガラス風の拡散、コントラスト制限付き適応的
       ヒストグラム平坦化（CLAHE）、中間調の明瞭度 + 細部のテクスチャ。
   * - ``posterize_image`` / ``gradient_map_image``
     - 各チャンネルを少数のフラットな階調に量子化するか、輝度を黒から白への
       グラデーションで再マッピングし、強度に応じてブレンドします。
   * - ``film_grain_image`` / ``dehaze_image`` / ``distort_image``
     - 調整可能なガウス分布のフィルムグレイン、ダークチャネルプライアによるかすみ除去、
       渦巻き / つまみ / 波紋の幾何学的な変形。
   * - ``levels_image`` / ``curve_image``
     - 黒点 / 白点とガンマによるレベル補正、およびマスタートーンカーブのプリセット
       （S 字カーブ、シャドウの持ち上げ、ハイライトの圧縮）。
   * - ``auto_color_balance_image`` / ``channel_mixer_image``
     - 自動ホワイトバランス（gray-world、white-patch、percentile-stretch、retinex）と、
       モノクロ変換付きの 3x3 チャンネルミキサー。
   * - ``lens_correction_image``
     - 樽型 / 糸巻き型の歪曲（k1）を補正し、四隅の周辺減光を明るくまたは暗くして、
       赤 / 青の色収差を打ち消します。

すべてのツールは JSON の ``outputSchema`` と読み取り専用 / 破壊的の ``annotations`` を
公開し、結果をテキストエンベロープと並んで ``structuredContent`` として返します
（後の MCP リビジョンのフィールドで、ハンドシェイクが報告するバージョンは ``2025-03-26`` です）。
これによりクライアントは再パースなしで型付きペイロードを
消費できます。長時間実行されるツールは、呼び出し側が progress token を渡した場合に
``notifications/progress`` をストリーミングします。

Prompts
^^^^^^^

サーバは ``prompts/list`` / ``prompts/get`` を通じて 4 つの prompt を公開します:
``caption_image``、``suggest_edits``、``analyze_composition``\ （saliency 駆動の構図批評）、
``flag_issues``\ （シャープネス + 品質 + クリッピングのトリアージ）。``completion/complete`` は
``suggest_edits`` の ``style`` と ``analyze_composition`` の ``focus`` の値を候補として提示します。

Claude Code (Project-Level)
^^^^^^^^^^^^^^^^^^^^^^^^^^^^

リポジトリにはプロジェクトレベルの ``.mcp.json`` がリポジトリルートに同梱されています:

.. code-block:: json

   {
     "mcpServers": {
       "imervue": {
         "type": "stdio",
         "command": "py",
         "args": ["-m", "Imervue.mcp_server"]
       }
     }
   }

``py`` は Windows の Python ランチャーです。macOS や Linux では ``python3`` か、Imervue を
インストールした環境のインタプリタを使ってください。リポジトリの任意のサブディレクトリを
Claude Code で開くと、このサーバが自動検出されます。
Claude Code は初回にプロジェクトサーバを有効化する前に確認を求めます — 使用するには
そのプロンプトを承認してください。

Claude Desktop
^^^^^^^^^^^^^^

同じエントリを Claude Desktop の設定に追加します:

* macOS: ``~/Library/Application Support/Claude/claude_desktop_config.json``
* Windows: ``%APPDATA%\Claude\claude_desktop_config.json``

絶対パスの作業ディレクトリを使うか、Imervue がインストールされた virtualenv を
アクティブ化してください。``python`` の呼び出しは ``import Imervue`` できる
インタプリタに解決される必要があります。

Protocol Surface
^^^^^^^^^^^^^^^^

サーバは stdin から改行区切りの JSON-RPC 2.0 メッセージを読み、応答と通知を stdout に 1 行ずつ
UTF-8 で書き出します。クライアントがどのバージョンを求めても、``initialize`` にはプロトコル
バージョン ``2025-03-26`` で応答します。リクエストは 1 件ずつ処理され、バッチ（JSON 配列）は
``-32600`` で拒否されます。

.. list-table::
   :header-rows: 1
   :widths: 32 68

   * - メソッド
     - 機能
   * - ``initialize``
     - ハンドシェイク。``protocolVersion`` ``2025-03-26``、``serverInfo``\ （``imervue``
       ``1.0.0``）、および capabilities の ``tools`` と ``prompts``\ （``listChanged: false``）、
       ``resources``\ （``subscribe: true``、``listChanged: true``）、``completions``、``logging``
       を返します。
   * - ``ping``
     - 空の結果を返します。
   * - ``tools/list``
     - 全 58 ツールを 1 ページで返します。各ツールには ``inputSchema``、``outputSchema``、
       ``annotations``\ （``readOnlyHint`` / ``destructiveHint`` / ``idempotentHint`` /
       ``openWorldHint``）が付きます。
   * - ``tools/call``
     - ``{"name", "arguments"}`` を実行します。結果は JSON エンコードされた戻り値を持つ ``text``
       コンテンツブロックで、戻り値がオブジェクトの場合は ``structuredContent`` も付きます。ツールが
       例外を送出した場合や、引数がそのパラメーターに合わない場合は、プロトコルエラーではなく
       ``isError: true`` と ``Error: …`` テキストを返します。未知のツール名は ``-32602`` です。
   * - ``prompts/list``
     - 4 つの prompt とその引数。
   * - ``prompts/get``
     - ``{"name", "arguments"}`` のメッセージを組み立てます。``caption_image`` と
       ``analyze_composition`` は PNG サムネイルを画像メッセージとして埋め込みます。未知の prompt や
       ``path`` の欠落は ``-32602`` です。
   * - ``completion/complete``
     - ``ref/prompt`` の引数に対する前方一致の値：``suggest_edits`` の ``style``\ （general、
       portrait、landscape、product、street、food、macro）と ``analyze_composition`` の
       ``focus``\ （all、framing、balance、subject、leading_lines）。その他の引数には空のリストを
       返します。
   * - ``resources/list``
     - ``IMERVUE_MCP_ROOT`` が示すフォルダー直下の画像（隠しファイルと SVG は除く）を、1 ページ
       100 件、``nextCursor`` 付きで返します。変数が未設定の場合は空です。
   * - ``resources/templates/list``
     - 下の表にある 2 つの URI テンプレート。
   * - ``resources/read``
     - ``imervue://image/…`` の URI を 1 つ読み取ります（下記参照）。
   * - ``resources/subscribe`` / ``resources/unsubscribe``
     - ``notifications/resources/updated`` を受け取る集合に URI を追加または削除します。
   * - ``logging/setLevel``
     - ``notifications/message`` として送る最低レベル（``debug``、``info``、``notice``、
       ``warning``、``error``、``critical``、``alert``、``emergency``。開始時は ``info``）を
       設定します。その他の値は ``-32602`` です。
   * - クライアントからの ``notifications/*``
     - 応答なしで受理されます（``notifications/initialized``、``notifications/cancelled``、…）。
       キャンセルしても実行中のツールは止まりません。
   * - ``notifications/progress``\ （送信）
     - ``find_similar`` または ``build_collage`` の実行中、``tools/call`` リクエストが
       ``params._meta.progressToken``\ （文字列または整数）を持っていた場合に
       ``{progressToken, progress, total, message}`` を送ります。``progress`` は増える一方です。
   * - ``notifications/resources/updated``\ （送信）
     - ``IMERVUE_MCP_ROOT`` 内のファイルが変更され、そのサムネイル URI が購読されているときに
       ``{uri}`` を送ります。
   * - ``notifications/resources/list_changed``\ （送信）
     - ``IMERVUE_MCP_ROOT`` 内で変更があるたび（watchdog で監視、再帰なし）、購読の有無に
       かかわらず送ります。
   * - ``notifications/message``\ （送信）
     - ``logging/setLevel`` のレベル以上のログエントリを ``MCPServer.emit_log`` 経由で送ります。
       組み込みのツールはこれを呼ばないため、標準のサーバは何も送りません。

.. list-table::
   :header-rows: 1
   :widths: 40 60

   * - URI
     - 返す内容
   * - ``imervue://image/{path}``
     - 画像の PNG サムネイル（正立、256 px に収まるサイズ）を、``mimeType`` ``image/png`` の
       base64 ``blob`` として返します。``resources/list`` はこの形式の URI を返します。
   * - ``imervue://image/{path}/metadata``
     - ``read_image_metadata`` の結果（寸法、フォーマット、EXIF、XMP）を、``mimeType``
       ``application/json`` の JSON ``text`` として返します。

``{path}`` は画像のファイルパスを、区切り文字とドライブのコロンも含めてすべてパーセント
エンコードしたものです（``C:\photos\a.jpg`` は ``imervue://image/C%3A%5Cphotos%5Ca.jpg``）。
読み取りはパスを直接解決するため、``IMERVUE_MCP_ROOT`` 以下に限らずどのファイルにも使えます。
``..`` セグメントを含むパスは ``-32602``、存在しないファイルは ``-32002``、別のスキームの URI は
``-32602`` です。

エラーには JSON-RPC のコードを使います：``-32700``\ （JSON でない行）、``-32600``\ （リクエスト
オブジェクトでない、または ``method`` がない）、``-32601``\ （未知のメソッド）、
``-32602``\ （不正なパラメーター、未知のツールや prompt、無効なログレベルやカーソル、未対応の
リソース URI）、``-32002``\ （リソースファイルが見つからない）、``-32603``\ （内部エラー）。

実装は ``Imervue/mcp_server/`` にあります:

* ``server.py`` — JSON-RPC ディスパッチャー（``MCPServer``）、stdio ループ（``run``）、
  ``IMERVUE_MCP_ROOT`` のウォッチャー。
* ``tools.py`` — ツールセットの公開窓口：すべてのハンドラを再エクスポートし、デフォルトのツールを
  登録します（``register_default_tools``）。
* ``tools_read.py`` / ``tools_edit.py`` — ツールのハンドラ（一覧、メタデータ、分析と、出力先に
  書き出す編集）。共通のヘルパーは ``tool_support.py`` にあります。
* ``tool_defs_read.py`` / ``tool_defs_edit.py`` — 各ツールの名前、説明、入力スキーマ、ハンドラを
  ``tools/list`` の順に定義します。
* ``tool_schemas.py`` — 各ツールの ``outputSchema`` と ``annotations``。
* ``prompts.py`` / ``completion.py`` — 4 つの prompt と ``completion/complete`` の候補。
* ``resources.py`` — ``imervue://image/`` リソース。
* ``progress.py`` / ``notifications.py`` / ``logging.py`` — 進捗の報告、ロック付きの stdout
  ライターとリソースの購読、ログレベルのフィルタリング。
* ``__main__.py`` — ``python -m Imervue.mcp_server`` のエントリポイント。

カスタムツールは、:class:`MCPServer` を構築し、:meth:`MCPServer.register`\ （名前、説明、入力
スキーマ、ハンドラ、オプションの出力スキーマと annotations。名前が重複すると ``ValueError`` を
送出し、``progress`` パラメーターを持つハンドラは進捗レポーターを受け取ります）を呼び出し、各
メッセージを :meth:`MCPServer.handle_message` に渡すことで登録できます。このメソッドは応答を、
通知の場合は ``None`` を返します。:func:`run` は常にデフォルトのツールで独自のサーバを構築する
ため、カスタムのツールセットには独自のループが必要です。通知を送るには、``server.notifier`` を
出力ストリーム上の ``Notifier`` に設定してください。
