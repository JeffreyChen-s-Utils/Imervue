Руководство пользователя Imervue
================================

Графическая рабочая станция для изображений с GPU-ускорением. Поставляется
с **пятью вкладками верхнего уровня**. Большая часть данного руководства
организована вокруг этих пяти разделов.

.. list-table::
   :header-rows: 1
   :widths: 18 82

   * - Вкладка
     - Назначение
   * - **Imervue**
     - Просмотр, отображение, организация, поиск и пакетная обработка
       библиотеки изображений. См. «Вкладка Imervue — Просмотр изображений
       и библиотека».
   * - **Modify**
     - Неразрушающий конвейер проявки — слайдеры, кривые, LUT, маски,
       ретушь, мультиизображение. См. «Вкладка Modify — Неразрушающая
       проявка».
   * - **Paint**
     - Полнофункциональная растровая студия рисования с кистями, слоями,
       анимацией, инструментами для манги, импортом/экспортом PSD.
       См. «Рабочее пространство Paint (вкладка Paint)».
   * - **Puppet**
     - Созданный с нуля аниматор 2D-марионеток с риггингом — меши,
       деформеры, параметры, движения, физика. См. «Вкладка Puppet —
       Анимация 2D с риггингом».
   * - **Desktop Pet**
     - Безрамочный, прозрачный оверлей, всегда поверх окон, запускающий
       те же риги ``.puppet`` на вашем рабочем столе с живыми драйверами
       (idle / blink / mic / webcam / drag-track). См. «Рабочее пространство
       Desktop Pet».

Разделы «Начало работы», «Справочник», «Система плагинов» и «MCP-сервер»,
которые следуют далее, являются сквозными — они применимы ко всем пяти
вкладкам.

Начало работы
-------------

При запуске Imervue вы увидите три области:

::

   +------------+----------------------+----------+
   |   Дерево   |                      |  Боковая |
   |   папок    |   Просмотр изобр.    |  панель  |
   |            |                      |   EXIF   |
   +------------+----------------------+----------+

- **Слева**: дерево папок. Щёлкните по папке, чтобы просмотреть изображения внутри.
- **В центре**: область отображения изображений. Показывает все изображения в виде сетки миниатюр.
- **Справа**: боковая панель EXIF, при запуске свёрнутая в тонкую полосу: щёлкните по ней, чтобы раскрыть. Она показывает информацию о съёмке открытого изображения.

Imervue записывает журнал каждой сессии в ``imervue.log`` рядом с программой (в ``%LOCALAPPDATA%\Imervue`` или, вне Windows, в ``~/.cache/imervue``, если эта папка доступна только для чтения). Журнал предыдущей сессии сохраняется как ``imervue.previous.log``, поэтому журнал, объясняющий аварийное завершение, остаётся на месте и после повторного запуска Imervue — прикладывайте оба файла, когда сообщаете о проблеме.

Поддерживаемые форматы
^^^^^^^^^^^^^^^^^^^^^^

- **Стандартные**: PNG, JPEG (.jpg, .jpeg, .jpe, .jfif, .jif), BMP, TIFF, WebP, GIF, APNG, SVG
- **RAW**: CR2 / CR3 / CRW (Canon), NEF / NRW (Nikon), ARW / SRF / SR2 (Sony), DNG (Adobe), RAF (Fujifilm), ORF (Olympus / OM System), RW2 (Panasonic), RWL (Leica), PEF (Pentax), SRW (Samsung), 3FR (Hasselblad), IIQ (Phase One), MEF (Mamiya), MOS (Leaf), ERF (Epson), MRW (Minolta), KDC / DCR (Kodak)
- **Современные**: AVIF (встроенная поддержка); HEIC / HEIF — с необязательным ``pillow-heif``; JPEG XL — с необязательным ``pillow-jxl-plugin``
- **Другие**: ICO, TGA, DDS, QOI, JPEG 2000 (.jp2 / .j2k / .jpf / .jpx), Netpbm (PPM / PGM / PBM / PNM), PCX, PSD (сведённое изображение) — для просмотра; поворот на месте и другая перезапись отклоняются, поэтому правки сохраняются через «Сохранить как» / «Экспорт»

Просмотр изображений
--------------------

Режим сетки миниатюр
^^^^^^^^^^^^^^^^^^^^

После открытия папки все изображения отображаются в виде миниатюр.

.. list-table::
   :header-rows: 1
   :widths: 30 70

   * - Действие
     - Способ
   * - Прокрутка
     - Колесо мыши
   * - Панорамирование
     - Удерживайте среднюю кнопку мыши и перетаскивайте
   * - Перейти в режим полного размера
     - Левый клик по любой миниатюре
   * - Изменить размер миниатюр
     - Меню ``Размер миниатюр`` > выберите 128 / 256 / 512 / 1024
   * - Плотность миниатюр
     - ``Размер миниатюр`` > ``Плотность миниатюр`` > Компактная / Стандартная / Свободная
   * - Всплывающий предпросмотр
     - Задержите курсор на миниатюре на 500 мс, чтобы увидеть увеличенный предпросмотр
   * - Выбор нескольких изображений
     - Левый клик и перетаскивание для построения прямоугольника выделения
   * - Перемещение по миниатюрам с клавиатуры
     - Клавиши со стрелками перемещают рамку фокуса и прокручивают к ней сетку; ``Enter`` открывает изображение

На каждой миниатюре отображаются статусные значки: цветная полоса слева
(цветная метка), сердечко слева вверху (избранное), звезда справа вверху
(закладка) и звёзды рейтинга слева внизу. Для миниатюр, которые ещё
загружаются, отображается заполнитель-спиннер.

Режим списка (детальный)
^^^^^^^^^^^^^^^^^^^^^^^^

Нажмите ``Ctrl + L`` для переключения между сеткой миниатюр и сортируемым
списком со следующими столбцами: Предпросмотр · Метка · Рейтинг · Имя · Разрешение ·
Размер · Тип · Изменено. Двойной клик по строке (или ``Enter``) для входа
в режим Deep Zoom; нажмите ``Esc`` для возврата к списку. Миниатюры и
метаданные загружаются лениво в рабочем потоке, поэтому очень большие
папки сохраняют отзывчивость.

``Delete`` удаляет выбранные строки, а ``Ctrl + Z`` возвращает их, а клавиши оценки (``1`` – ``5``), избранного (``0``), отбора (``P`` / ``Shift + X`` / ``U``) и цвета (``F1`` – ``F5``) их помечают, как в сетке; все, кроме ``F1`` – ``F5``, следуют настройкам сочетаний.

Режим Deep Zoom
^^^^^^^^^^^^^^^

Щёлкните по миниатюре, чтобы войти в режим Deep Zoom для высококачественного
просмотра отдельного изображения.

Открываются и панорамы намного больше защитного предела Pillow в 179 мегапикселей: предел зависит от объёма памяти компьютера (при 16 ГБ — около 1,4 гигапикселя), а такие огромные изображения декодируются по одному.

Обрезанный JPEG, PNG, TIFF, GIF или BMP — прерванная загрузка или копирование, фото, восстановленное с неисправной карты памяти, — открывается с прочитанной частью, как в браузере, а не отказывается открываться.

Когда другая программа сохраняет поверх изображения — внешний редактор, напрямую или переименовывая копию поверх, — просмотрщик показывает новую версию: изображение, открытое в глубоком зуме, — в течение секунды после последней записи, миниатюры сетки и строки Списка — в течение нескольких секунд.

16-битный серый PNG или TIFF — скан, карта глубины, научный или астрономический снимок — и TIFF с плавающей точкой показываются в просмотрщике, миниатюрах, превью и инструментах с настоящей яркостью, а не почти белыми или чёрными: 16-битные значения масштабируются на весь диапазон, значения с плавающей точкой от 0 до 1 идут от чёрного к белому, любой другой диапазон растягивается.

Изображения со встроенным цветовым профилем — Display P3 с телефонов, Adobe RGB с камер, CMYK, а также профили серого, которые Photoshop встраивает в полутоновые изображения, например Dot Gain 20% или Gray Gamma 1.8, — переводятся в sRGB в просмотрщике и миниатюрах; полутоновое изображение остаётся полутоновым. Изображения без профиля или в sRGB показываются как есть.

Файлы, которые Windows помечает скрытыми, — они скрыты и в Проводнике, и в дереве папок, — и имена, начинающиеся с точки, например ``._photo.jpg``, который macOS записывает рядом с каждым фото на картах памяти и сетевых дисках, не попадают в сетку миниатюр, значки папок, списки пакетных инструментов, отслеживаемые папки, сканирование библиотеки, CLI и инструменты папок MCP-сервера; рекурсивное сканирование пропускает скрытые папки, такие как ``$RECYCLE.BIN`` и ``.Trashes`` от Mac. Скрытое изображение, открытое намеренно, всё равно открывается.

   * - Действие

   * - Цветовые режимы
     - ``Shift + M`` циклически переключает Нормальный / Оттенки серого / Инверсия / Сепия (GLSL, неразрушающий)

Разделённый вид и чтение разворотов
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

Отображение двух изображений рядом непосредственно в главном окне без
открытия диалога Compare:

.. list-table::
   :header-rows: 1
   :widths: 35 65

   * - Действие
     - Сочетание клавиш
   * - Разделённый вид (два изображения)
     - ``Shift + S``
   * - Разворот (текущее + следующее)
     - ``Shift + D``
   * - Разворот, справа налево (манга)
     - ``Ctrl + Shift + D``
   * - Вернуться в предыдущий режим
     - ``Esc``

В режиме разворота клавиши со стрелками продвигают по два изображения
за раз. Вариант RTL меняет местами две панели, так что страница 1
появляется справа.

Окно для нескольких мониторов
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

Нажмите ``Ctrl + Shift + M``, чтобы открыть второе окно без рамки на
дополнительном дисплее, которое зеркально отображает изображение,
показанное в главном окне просмотра. Главное окно продолжает работу
независимо — полезно для выставок, рабочих процессов редактирования
с двумя экранами или презентаций клиентам. Нажмите ``Ctrl + Shift + M``
ещё раз, чтобы закрыть, или нажмите ``Esc`` внутри второго окна.

Организация изображений
-----------------------

Рейтинг и избранное
^^^^^^^^^^^^^^^^^^^

Клавиши оценивают изображение, открытое в Deep Zoom. В сетке они оценивают выбранные миниатюры, иначе выбранную стрелками, иначе ту, что под мышью, — те же фото, что взяла бы цветовая метка или отметка отбора. Если у всех уже эта оценка, клавиша её снимает.

.. list-table::
   :header-rows: 1
   :widths: 30 70

   * - Действие
     - Клавиша
   * - Переключить избранное
     - ``0``
   * - Оценить 1 -- 5 звёзд
     - ``1`` ``2`` ``3`` ``4`` ``5`` (нажмите ещё раз, чтобы сбросить)

Цветные метки (F1 -- F5)
^^^^^^^^^^^^^^^^^^^^^^^^

Цветные флаги, хранящиеся отдельно от рейтинга 1 -- 5 звёзд.
Полезны для быстрой категоризации (например, красный = кандидаты на
удаление, зелёный = отобранные, синий = требуют ретуши).

.. list-table::
   :header-rows: 1
   :widths: 30 70

   * - Действие
     - Клавиша
   * - Красный / Жёлтый / Зелёный / Синий / Фиолетовый
     - ``F1`` / ``F2`` / ``F3`` / ``F4`` / ``F5`` (нажмите ту же клавишу ещё раз, чтобы сбросить;
       для выделения сбрасывает, только если у всех выбранных изображений уже этот цвет)
   * - Пакетное применение к выделению
     - Выберите несколько миниатюр, затем нажмите соответствующую клавишу F
   * - Фильтр по цвету
     - ``Фильтр`` > ``По цветной метке`` > выберите цвет / Любая метка / Без метки

В строке состояния отображается цветная плашка для текущего изображения.
На миниатюрах отображается цветная полоса вдоль левого края. В **режиме
списка** есть отдельные столбцы **Метка** и **Рейтинг**, по которым
можно сортировать — щёлкните по любой ячейке столбца звёзд, чтобы
установить рейтинг, не покидая список.

Режим просмотра (сетка / список)
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

Переключение браузера изображений между плиточной сеткой и сортируемым
детальным списком:

- ``Ctrl + L`` — переключить Сетка ↔ Список

- В режиме списка любой столбец (включая Метку) можно сортировать; двойной клик по строке или ``Enter`` для открытия Deep Zoom.

Редактирование изображений (вкладка Modify)
-------------------------------------------

Переключитесь на вкладку **Modify** в верхней части окна, чтобы войти
в режим редактирования. В режиме Deep Zoom правый клик > ``Modify`` > ``Develop``

.. list-table::
   :header-rows: 1
   :widths: 25 75

     - Функция
   * - Экспозиция
     - Регулировка общей яркости
   * - Яркость
     - Тонкая настройка светлых и тёмных областей
   * - Контраст
     - Регулировка разницы между светлыми и тёмными участками
   * - Насыщенность
     - Регулировка яркости цветов
   * - Баланс белого — Температура
     - Тёплый / холодный сдвиг (синий → жёлтый); полезно для смешанного освещения или съёмок в помещении
   * - Баланс белого — Оттенок
     - Сдвиг пурпурный / зелёный; корректирует флуоресцентные оттенки
   * - Светá
     - Восстановление выбитых светов или дальнейшее поднятие ярких областей
   * - Тени

     - Вправо — растягивает самые яркие тона до белого; влево — приглушает белый до серого
   * - Чёрные
     - Влево — сжимает самые тёмные тона до чёрного; вправо — поднимает чёрный до блёклого серого
   * - Сочность
     - Усиление с учётом насыщенности — защищает оттенки кожи и уже насыщенные цвета

Эти регулировки являются **неразрушающими**. Каждый слайдер записывается
в рецепт правок, хранимый для каждого изображения; нажмите ``Сброс``
в любое время, чтобы восстановить оригинал, или ``Отменить`` / ``Повторить``
под слайдерами, чтобы пройти по отдельным изменениям. Рецепты сохраняются между
перезапусками и могут быть экспортированы / синхронизированы через
поток XMP-сайдкаров, описанный в разделе «Метаданные».

Файл на диске меняется только по вашей команде. **Apply Crop** и **Save** аннотаций записывают результат поверх файла, сохраняя его EXIF (камера, дата съёмки, GPS), XMP и DPI. RAW-файл камеры, HEIC или анимированный / многостраничный файл никогда не перезаписываются: при обрезке предлагается экспорт, а при сохранении аннотаций — новый файл. Разовые инструменты (CLAHE, HSL-микшер, фоторамка, автовыравнивание…) сохраняют
результат рядом с оригиналом как ``photo_clahe.png``; повторный запуск сохраняет
``photo_clahe_1.png``, а не заменяет прошлый результат. **Auto-Rotate by EXIF**, копии из **Batch EXIF Strip** и **Split Pages…** нумеруют свои файлы так же. Рецепт и виртуальные копии фото остаются с ним, когда Imervue
поворачивает его без потерь (кадрирование поворачивается вместе с ним) или
перезаписывает EXIF (GPS-геотег, редактор EXIF); рецепт с локальными масками, слоями,
бликом объектива или метками лиц остаётся с неповёрнутой версией, пока её не повернут
обратно.

Рабочее пространство Paint (вкладка Paint)
------------------------------------------

Третья вкладка верхнего уровня — **Paint** — это полнофункциональное
рабочее пространство рисования с многовкладочными документами,
векторными и растровыми слоями, инструментами для манги, кадрами
анимации и импортом/экспортом PSD. При переключении на неё с панели
вкладок на холст загружается изображение, открытое в просмотрщике.

Особенности UX — рабочее пространство Paint поставляется с
полнофункциональным курсором размера кисти, масштабируемым со
zoom'ом, отдельными иконками курсора для каждого инструмента,
шахматным узором прозрачности под холстом, наложением подсветки
при перетаскивании, звёздочкой изменения на каждой вкладке,
тостами подтверждения отмены / повтора, сегментом статуса
автосохранения в строке состояния и приглашением восстановления
автосохранения при запуске, которое показывает снимки из
предыдущей аварийно завершённой сессии.

Горячие клавиши для опытных пользователей: ``Tab`` переключает все
доки для рисования без отвлекающих факторов, ``Ctrl+Tab`` циклически
перебирает вкладки, ``,`` / ``.`` циклически перебирают типы кистей,
``0–9`` устанавливают непрозрачность кисти с шагом 10 %,
``Alt+[`` / ``Alt+]`` шагают по активному слою, а правый клик по
холсту открывает быстрое меню Отмена / Повтор / Выделить всё /
Снять выделение / По размеру / 100 %.

Док цвета теперь предоставляет слот «прозрачный / без цвета» (по
умолчанию BG = прозрачный), а заливка и волшебная палочка обе
учитывают границы альфа-канала, поэтому стёртые пиксели больше не
просачиваются в перерисовку.

::

   +------+----------------------+----------------+
   | Пан. |                      | Цвет · Кисть   |
   | инст.|   Холст (рисование)  | Слой · Навиг.  |
   |      |                      | Материал · …   |
   +------+----------------------+----------------+

Четырнадцать доков справа расположены вкладками в одном столбце, чтобы
холст сохранял всю видимую высоту, и сгруппированы в три блока:

- **Рисование** — Цвет, Кисть, Заливка, Образцы
- **Холст** — Слои, Навигатор, История, Страницы, Анимация, Гистограмма
- **Библиотека** — Материалы, Штампы, Поза, Референс

Каждый док можно показать или скрыть по отдельности в меню ``Окно``.
Перетащите заголовок любого дока, чтобы переставить или открепить панель;
``Настройки`` > ``Раскладки рабочего пространства…`` запоминает, какие доки
показаны (см. *Раскладки рабочего пространства*).

Слои
^^^^

**Док слоёв** предлагает миниатюры, переключатели видимости,
встроенное переименование, изменение порядка кнопками ↑ / ↓ (или
``Ctrl + [`` / ``Ctrl + ]``), а также режим наложения + непрозрачность
активного слоя. Меню ``Слой`` добавляет:

- **Новый / Векторный / Дубликат / Объединить вниз** (``Ctrl + Shift + N`` /
  ``Ctrl + Shift + V`` / ``Ctrl + J`` / ``Ctrl + E``)
- **Маски** — Добавить маску / Из выделения / Инвертировать / Применить / Удалить
  (``Ctrl + Shift + M`` добавляет; ``Ctrl + Alt + Shift + M`` добавляет из выделения)
- **Обтравочная маска** — включает / выключает обтравку активного слоя,
  обрезая его по альфе слоя ниже (``Ctrl + Alt + G``)
- **Эффекты слоя** — Тень · Внешнее свечение · Обводка; очистить эффекты
- **Референсный слой** — закрепить один слой как источник, с цветами
  которого сверяется ведро **Заливка**
- **1-битный слой** — переключить активный слой в бинарный слой штрихового рисунка
- **Разделить слой по цвету** — разбить плоский цветной слой на один слой
  на цвет для лёгкой перезаливки
- **Карта градиента** — подменю с предустановками (сепия / закат / цианотип …)

Выделения
^^^^^^^^^

Используйте инструменты прямоугольника / лассо / палочки / быстрого
выделения, затем меню **Правка** > **Обводка выделения…**, чтобы
обвести рамку цветом переднего плана с шириной и расположением,
заданными в диалоге. ``Q`` переключает **режим быстрой
маски** — рисуйте любой кистью для уточнения края выделения красным,
затем нажмите ``Q`` ещё раз, чтобы преобразовать его обратно в рамку.

Анимация
^^^^^^^^

**Док анимации** превращает документ в полосу кадров:

- ``+ Кадр`` делает снимок сведённого изображения в новый кадр.
- Щёлкните миниатюру кадра, чтобы загрузить его в активный слой.
- ``Калька`` (меню Вид) накладывает предыдущий кадр с низкой альфой.
- ``▶ Воспроизвести`` циклически показывает кадры с выбранной частотой
  (FPS). Кадры служат для предпросмотра и кальки — экспорта анимации нет
  (**Файл > Экспорт страниц** экспортирует страницы проекта комикса, а не
  кадры).

Фильтры
^^^^^^^

Каждый пункт ``Фильтр`` открывает простой диалог параметров с кнопками
OK / Отмена (без предпросмотра в реальном времени):

- **Уровни** — слайдеры точки чёрного / точки белого / гаммы
- **Кривые** — пресет (S-кривая, Подъём теней, Сжатие светов) со слайдером силы
- **Постеризация** — квантование цвета на N шагов
- **Порог** — преобразование в чисто чёрно-белое по порогу
- **Авто-баланс цвета** — нейтрализация оттенков через grey-world / white-patch
- **Зернистость плёнки** — шум яркости с регулируемым размером и количеством
- **Преобразовать в полутон** — газетный точечный растр

Вспомогательные виды
^^^^^^^^^^^^^^^^^^^^

- **Пиксельная сетка** (``Ctrl + Shift + '``) — наложение однопиксельной сетки при высоком масштабе
- **Привязка к пикселю / краям** — привязка к пикселю ставит отпечатки кисти на целые пиксели; привязка к краям притягивает точки к ближайшим краям холста или слоя
- **Калька** — накладывает предыдущий кадр анимации
- **Направляющие выпуска под обрез** — направляющие выпуска под обрез / безопасной зоны для печати
- **Поворот холста** (``Ctrl + Shift + H``) — поворот вида без растеризации

Файловый ввод/вывод
^^^^^^^^^^^^^^^^^^^

- **Открыть PSD…** (``Ctrl + O``) сводит файл в один слой в новой вкладке; **Сохранить как PSD…** (``Ctrl + S``) записывает слои с их режимами наложения (без масок и эффектов слоя)
- **Экспортировать изображение…** — свести и сохранить как PNG
- **Экспорт страниц → CBZ** / **→ PDF** — экспорт страниц проекта комикса
- **Импорт пресета кисти…**, **Импорт палитры…** — перенос кистей и палитр из других установок или приложений
- **Автосохранение** — каждые 2 минуты, пока в активной вкладке есть несохранённые изменения, записывается снимок; при следующем запуске тост предлагает снимки, а **Файл > Восстановить автосохранение** загружает самый новый в активную вкладку. Строка состояния показывает, когда был сделан последний снимок, а при закрытии Imervue спрашивает о вкладках Paint с несохранёнными изменениями.

Раскладки рабочего пространства
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

``Настройки`` > ``Раскладки рабочего пространства…`` перечисляет встроенные
раскладки **По умолчанию**, **Рисование**, **Комикс** и **Компактная**, а
также ваши собственные. **Сохранить текущую…** сохраняет под именем, какие

показанный вперёд. Параметры инструментов и размеры доков не сохраняются.

Рабочее пространство Puppet (вкладка Puppet)
--------------------------------------------

Четвёртая вкладка верхнего уровня — **Puppet** — это созданная с
нуля система анимации 2D-марионеток с риггингом: риги с деформацией
меша, параметры, движения, физика, выражения, группы поз,
синхронизация губ, отслеживание через веб-камеру — и всё это
**без проприетарного SDK**, **без `live2d-py`** и
с полностью открытым форматом файла ``.puppet``.

.. note::

   Полный сквозной учебник — от чистой установки до либо живой
   трансляции в OBS, либо запечённого MP4 — находится в
   ``puppet_guide.md`` в корне репозитория (с зеркалами
   ``puppet_guide.zh-TW.md`` и ``puppet_guide.zh-CN.md``). Данный
   раздел является справочником; учебник — пошаговое руководство.

::

   +-----------+----------------------+----------------+
   | Панель    |                      | Док            |
   | инструм.  |   GL-холст           | параметров     |
   |           |                      |                |
   +-----------+----------------------+                |
   |               Док движений                        |
   +---------------------------------------------------+

Сквозной рабочий процесс
^^^^^^^^^^^^^^^^^^^^^^^^

1. **Импорт PNG** — ``File`` > ``Import PNG…`` запускает
   ``puppet.auto_mesh.puppet_from_png``: триангулированная сетка,
   ограниченная альфой, один drawable, готовый к рендерингу.
2. **Добавить деформер** — ``Edit`` > ``Add Rotation Deformer`` (якорь + угол) или
   ``Add Warp Deformer`` (билинейная решётка rows × cols; вершины за пределами
   границ проходят без изменений).
3. **Добавить параметр** — ``Edit`` > ``Add Parameter`` добавляет слайдер в
   правый док **Parameters** с автоматически назначенным id (``Param1``,
   ``Param2``, …).
4. **Установка ключей** — перетащите слайдер в одну крайность,
   отредактируйте форму деформера в коде,
   нажмите **Set key**. Повторите в нейтральном положении и в
   противоположной крайности. Среда выполнения теперь интерполирует
   поля деформеров между соседними ключами при перемещении слайдера.
   **Set key** сохраняет только формы деформеров: **Edit mesh**
   окончательно сдвигает вершины покоя drawable, поэтому правка меша
   в ключ не попадает.
5. **Сохранение** — ``Save As…`` записывает риг + текстуры + движения +
   выражения + физику в один ``.puppet`` zip-архив, которым можно
   поделиться или открыть позже через ``Open Puppet…``.

Попробуйте проработанный пример
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

Репозиторий поставляется с полностью оснащённой демо-версией по адресу
``examples/puppet/march_7th.puppet`` — рига Cubism Live2D с 307
drawable, конвертированного внутри дерева. Текстуры и вершинные
морфы по параметрам запечены в zip ``.puppet``, поэтому демо
открывается на стандартном ``requirements.txt`` без распространения
Cubism SDK.

Риг содержит 203 параметра стандарта Cubism (``ParamAngleX/Y/Z``,
``ParamEyeLOpen/ROpen``, ``ParamBreath``, ``ParamMouthOpenY``, …),
поэтому каждый стандартный драйвер ввода (веб-камера, моргание,
синхронизация губ, отслеживание взгляда за курсором) управляет
им без настройки для каждого рига. В комплект входят восемнадцать
движений: восемь зацикленных движений простоя в группе ``Idle``, девять
зацикленных жестов в группе ``Gesture`` и однократное движение
``tap_head`` в группе ``TapHead``.

Откройте вкладку Puppet, нажмите **Open Puppet…**, укажите на
``march_7th.puppet`` — фигура появится по центру. Перетащите любой
слайдер параметра для управления суставом или щёлкните одно из
движений в доке Motions — одиночный клик привязывает движение и
сразу запускает воспроизведение.

**Запуск встроенного примера, шаг за шагом:**

1. Запустите Imervue. Из исходного кода: ``python -m Imervue``. Из
   собранного билда: запустите исполняемый файл / пакет приложения
   ``Imervue``. Каталог ``examples/`` входит в сборки Nuitka и
   PyInstaller; установка через pip / wheel его не содержит (в
   checkout исходников риги лежат в ``examples/puppet/``).
2. Щёлкните вкладку **Puppet** в верхней части окна.
3. **File > Examples > March 7th** (или
   выпадающее меню **Examples ▾** панели). Риг с 307 drawable
   загружается по центру, и док параметров заполняется 203 слайдерами
   стандарта Cubism.
4. В нижнем доке **Motions** щёлкните одиночным кликом по любой
   записи движения (``zhaiyan``, ``zhaoxiang``, ``idle_breath``,
   ``tap_head`` …). Воспроизведение начнётся немедленно; повторный
   щелчок запускает его заново, кнопка **Stop** дока останавливает
   воспроизведение, а выбор другого движения плавно переходит в него.
5. Переключайте живые входы на панели инструментов, чтобы управлять
   ригом из собственных входов — **Drag-track head**, чтобы голова и
   глаза поворачивались к курсору, пока он движется над холстом,
   **Auto-blink** для циклического моргания,
   **Auto idle** + **Idle motions** для дыхания + случайных циклов
   простоя, **Mic lip-sync** для открытия рта по RMS микрофона,
   **Webcam tracking** для полного отслеживания головы + глаз + рта
   через MediaPipe FaceLandmarker.
6. **Reset to rest** на панели инструментов останавливает все движения,
   снимает все живые драйверы, очищает выражения / переопределения
   поз и привязывает все параметры обратно к значениям по умолчанию —
   каноническое действие «начать заново».
7. Чтобы открыть другой риг позже: **File > Open Puppet…** выбирает
   любой ``.puppet`` zip с диска; **File > Examples ▾** остаётся
   привязанным к встроенному списку.

Формат файла ``.puppet`` (v1)
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

Файл ``.puppet`` — это zip-архив:

::

   my_character.puppet
   ├── puppet.json              # обязательно — манифест, drawables, deformers, parameters
   ├── textures/
   │   ├── face.png             # ссылается через drawables[].texture
   │   └── body.png
   ├── motions/                 # опционально
   │   ├── idle.json
   │   └── wave.json
   ├── expressions/             # опционально
   │   └── smile.json
   └── physics.json             # опционально

Пример ``puppet.json`` верхнего уровня::

   {
     "version": 1,
     "size": [2048, 2048],
     "drawables": [ ... ],
     "deformers": [ ... ],
     "parameters": [ ... ],
     "motions": ["idle", "wave"],
     "expressions": ["smile"],
     "pose": {"groups": [ ... ]},
     "physics": "physics.json"
   }

Полная схема (drawables, deformers, parameters, motions, expressions,
pose, physics) находится в ``Imervue/puppet/FORMAT.md`` в репозитории.
Только JSON + PNG — без проприетарного бинарного формата, полностью
diff-абельно через git.

Справочник по панели инструментов
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

На панели инструментов находятся **Examples ▾**, шесть живых
переключателей, **Edit mesh**, **Record…** и **Reset to rest**. Все
остальные записи ниже — пункты меню **File**, **Edit**, **Live**,
**Output** или **Tools**; в этих меню есть и записи панели инструментов.

.. list-table::
   :header-rows: 1
   :widths: 30 70

   * - Действие
     - Назначение
   * - Open Puppet… / Examples ▾
     - Загрузить ``.puppet`` с диска (меню **File**) или выбрать один из
       ригов, поставляемых в ``examples/puppet/``, через **Examples ▾**
       (кнопка панели инструментов, также в меню **File**)
   * - Import PNG… / Import PSD… / Import Cubism…
     - Авто-меш PNG, разбиение PSD на слои или дискретизация и
       реконструкция Cubism-рига. Выбор Cubism принимает как ``.moc3``,
       так и ``.model3.json``; без открытого рига любой путь запускает
       полное преобразование ``.moc3 → .puppet`` (требуется
       пользовательский Cubism Native SDK). Выбор ``.model3.json`` при
       загруженном риге объединяет только JSON-метаданные (motions /
       expressions / physics) с активным документом.
   * - Recent
     - Быстро снова открыть недавно открытую марионетку
   * - Save As…
     - Записать текущий риг как ``.puppet`` zip
   * - Add Rotation Deformer / Add Warp Deformer / Add Parameter
     - Создавать риг из меню **Edit**
   * - Drag-track head
     - Голова и глаза поворачиваются к курсору, пока он движется над
       холстом: смещение курсора → ``ParamAngleX`` / ``ParamAngleY`` +
       ``ParamEyeBallX`` / ``ParamEyeBallY``
   * - Auto-blink
     - Косинусоидальный цикл закрытие→открытие на ``ParamEyeLOpen`` /
       ``ParamEyeROpen`` каждые ~4,5 с (путь принудительной записи
       обходит пропуск изменений холста, чтобы конкурирующие драйверы
       не глушили моргание)
   * - Mic lip-sync
     - RMS микрофона → ``ParamMouthOpenY`` (требуется ``sounddevice``)
   * - Webcam tracking
     - MediaPipe Tasks API FaceLandmarker → рысканье / тангаж / крен
       головы + глаза + рот (требуются ``opencv-python`` + ``mediapipe``;
       открывает диалог с живым предпросмотром с обнаруженными ориентирами)
   * - Auto idle / Idle motions
     - Цикл дыхания + дрейф на стандартных параметрах, плюс
       опциональный случайный циклер по движениям группы Idle
   * - Edit mesh
     - Перетаскивание вершин холста для уточнения меша
   * - Record motion
     - Только меню **Output**: захват изменений параметров в новое
       ``Motion`` и добавление его в документ — запечь из дубля, без
       ручной разметки ключей
   * - Capture frame… / Record… / Export all motions…
     - Сохранить отдельный PNG, переключить запись GIF / WebM / MP4 или
       пакетно отрендерить каждое движение рига в отдельный файл (всё
       через тот же путь рендеринга только персонажа вне экрана,
       используемый для трансляции). Захваченный кадр сохраняет
       собственный размер рига (длинная сторона не более 4096 px) на
       прозрачном фоне; запись или пакетный экспорт вписывает персонажа
       в 1080 px на белом фоне, так как у кадров GIF / WebM / MP4 нет
       альфа-канала
   * - Output > Virtual camera / NDI output
     - Поверхности живой трансляции — см. *Прямая трансляция в OBS* ниже
   * - Reset to rest
     - Мгновенно остановить плеер движений, снять все живые драйверы,
       очистить выражения / группы поз, восстановить значения параметров по умолчанию
   * - Fit to Window
     - Меню **Tools**: снова отцентрировать + масштабировать марионетку в холсте

Запись собственных движений
^^^^^^^^^^^^^^^^^^^^^^^^^^^

Чтобы захватить пользовательский дубль вместо ручной разметки ключевых кадров:

1. Переключите **Output > Record motion** — появится диалог имени.
2. Во время записи перетаскивайте слайдеры, включите **Webcam tracking**,
   позвольте физике работать, всё что угодно, что записывает значения параметров.
3. Выключите **Record motion** — рекордер запекает захваченный поток
   30 Гц в ``Motion`` с одной линейно-сегментной дорожкой на параметр,
   который реально двигался (параметры, оставшиеся неизменными, отбрасываются).
   Новое движение немедленно появляется в нижнем доке **Motions**,
   готовое к воспроизведению / зацикливанию / сохранению.

Пользовательские движения, сохранённые таким образом, проходят
двусторонний обмен через тот же JSON-пейлоад ``motions/<name>.json``,
что и созданные вручную.

Прямая трансляция в OBS
^^^^^^^^^^^^^^^^^^^^^^^

Два пути вывода, оба рендерят марионетку отдельно (без шахматного
фона, без хрома редактора) во внеэкранный фреймбуфер перед передачей
её поверхности трансляции. Длинная сторона вывода ограничена 1080 пикс,
чтобы родные холсты Cubism (March 7th — 3503×7777) не отклонялись
драйверами виртуальных камер DirectShow.

**A. Virtual Camera** — отображается как веб-камера в списке источников
*Video Capture Device* OBS. ``pip install pyvirtualcam`` плюс драйвер
для платформы: OBS Studio 26+ поставляется с драйвером *OBS Virtual Camera*
на Windows / macOS (один раз нажмите *Start Virtual Camera* в OBS, чтобы
зарегистрировать его); Linux использует ``v4l2loopback-dkms`` +
``modprobe v4l2loopback exclusive_caps=1 card_label="Imervue"``.
Переключатель меню **Output > Virtual camera** открывает поток.

DirectShow / AVFoundation / v4l2loopback работают только с RGB — без
альфа-канала — поэтому Imervue заливает область за пределами персонажа
**пурпурным #FF00FF** в качестве цветового ключа. Удалите его в OBS
через фильтр Color Key:

1. Правый клик по источнику Video Capture Device > **Filters**
2. **Effect Filters > + > Color Key**
3. Установите **Key Color Type** = ``Custom Color``,
   **Custom Color** = HEX ``FF00FF``,
   **Similarity** = ``80–300``,
   **Smoothness** = ``30–50``

Фильтр привязывается к источнику, поэтому цветовой ключ автоматически
повторно применяется каждый раз, когда виртуальная камера возобновляет работу.

**B. NDI output** — LAN-трансляция с задержкой менее 50 мс,
несущая RGBA, поэтому OBS / vMix композитят прямо поверх своих
собственных сцен без прохода с цветовым ключом. ``pip install ndi-python`` +
рантайм `NDI Tools <https://ndi.video/tools/>`_ + плагин
`obs-ndi <https://github.com/obs-ndi/obs-ndi/releases>`_.
Переключатель меню **Output > NDI output** транслирует источник (имя
по умолчанию *Imervue Puppet*).

``ndi-python`` поставляется только в виде дистрибутива с исходниками;
pip собирает его из C++ во время установки. Пользователям Windows
требуются Visual Studio Build Tools 2022 (с компонентом C++), CMake
в PATH и NDI SDK с <https://ndi.video/for-developers/ndi-sdk/>,
установленный в расположение по умолчанию с переменной окружения
``NDI_SDK_DIR``, указывающей на него.

См. ``puppet_guide.md`` § 1.2 для полного пошагового описания плюс
список устранения неполадок (камера показывает пурпурный, сбой cmake
ndi-python, растяжение виртуальной камеры и т. д.).

Опциональные зависимости
^^^^^^^^^^^^^^^^^^^^^^^^

* ``sounddevice`` — захват микрофона для синхронизации губ
* ``opencv-python`` + ``mediapipe`` — отслеживание лица через веб-камеру
* ``imageio-ffmpeg`` — запись MP4 / WebM (уже поставляется для
  Slideshow Video)
* ``pyvirtualcam`` — вывод виртуальной камеры (см. *Прямая трансляция*)
* ``ndi-python`` — вывод NDI (см. *Прямая трансляция*)
* Пользовательский Cubism Native SDK DLL — преобразование
  ``.moc3 → .puppet`` (Free Material License компании Live2D
  запрещает перераспространение; пользователи кладут SDK в
  ``<cwd>/sdk/`` или устанавливают переменную окружения
  ``CUBISM_CORE_DLL``)

Вкладка Puppet корректно деградирует при отсутствии Python-пакета —
соответствующий переключатель остаётся выключенным, и открывается
установщик зависимостей с предложением установить пакет; после
установки переключатель снова включается. Текстовая подсказка
появляется только тогда, когда пакет установлен, но устройство или
драйвер дают сбой. ``File > Install dependencies…``
пакетно устанавливает каждый опциональный Python-пакет за один раз.

Рабочее пространство Desktop Pet (вкладка Desktop Pet)
------------------------------------------------------

Вкладка 5 — **Desktop Pet** — помещает любого ``.puppet``-персонажа
на ваш рабочий стол в виде безрамочного прозрачного оверлея. Сама
вкладка — это панель управления; настоящий персонаж — отдельное
окно верхнего уровня, которое разделяет весь рантайм Puppet
(движения, выражения, физика, idle-драйверы, ввод с микрофона /
веб-камеры). Питомец может реагировать на клики, запускать
анимации по таймеру, следовать за курсором, прятаться, пока
другое приложение работает в полноэкранном режиме, и произносить
свои реплики, которые вы пишете в JSON-файле.

Эта глава — полный справочник по вкладке. Глава построена так:

#. **Быстрый старт** — путь из пяти шагов от «я только что
   открыл Imervue» до «на моём рабочем столе появилась
   марионетка».
#. **Загрузка рига** — выбор файла, встроенный пример,
   восстановление между запусками.
#. **Окно оверлея** — каждое поведение оконного уровня
   (перетаскивание, прилипание к краю, сквозной клик, фиксация
   якоря, всегда внизу, скрывать в полноэкранном режиме, пауза
   при скрытии, непрозрачность, размер, восстановление на нескольких
   мониторах).
#. **Модель взаимодействия** — области попадания левого клика,
   полное контекстное меню правого клика, системный трей.
#. **Живые драйверы** — семь драйверов ввода (три включены по
   умолчанию) и их опциональные зависимости.
#. **Скрипт питомца** — JSON-файл, который позволяет заменить
   голос питомца своими репликами, планировать напоминания и
   привязывать ответы к каждой области попадания / движению.
#. **Сохранение состояния** — что запоминается между запусками
   и точная схема настроек.
#. **Создание нового питомца** — указатель на вкладку Puppet и
   формат файла ``.puppet``.
#. **Устранение неполадок** — типичные неожиданности и что с
   ними делать.

Быстрый старт
^^^^^^^^^^^^^

1. Переключитесь на вкладку **Desktop Pet**.
2. Нажмите **Load bundled March 7th**, чтобы использовать
   встроенного персонажа, или **Open Puppet…**, чтобы выбрать
   свой ``.puppet``-файл.
3. Оверлей появится на рабочем столе, а флажок **Show pet on
   desktop** будет установлен автоматически. (Если вы захотите
   скрыть питомца, не закрывая Imervue, снимите флажок или
   используйте иконку в системном трее.)
4. Перетащите персонажа туда, где он вам нужен. Отпустите рядом
   с краем экрана, чтобы прилипнуть к нему заподлицо.
5. Выберите нужные **Живые драйверы** — idle-дыхание, моргание,
   слежение за курсором, синхронизацию губ с микрофоном,
   отслеживание веб-камеры — либо во вкладке рабочего
   пространства, либо в правом клике на питомце.

Всё, что вы настроили, переживёт следующий запуск, так что шаг 5 —
это одноразовое решение для каждого рига / персонажа.

Загрузка рига
^^^^^^^^^^^^^

Вкладка предлагает три способа загрузки:

* **Open Puppet…** — выбрать любой ``.puppet``-файл с диска.
* **Load bundled March 7th** — открывает риг, поставляемый в
  ``examples/puppet/march_7th.puppet``. Резолвер сначала ищет
  в ``examples_dir()`` (рядом с программой в упакованных сборках
  Nuitka / PyInstaller, корень репозитория в checkout исходников),
  затем падает обратно к поиску относительно текущей рабочей
  папки.
* **Last rig** — ранее загруженный риг автоматически
  восстанавливается при старте Imervue из поля настроек
  ``last_rig_path``; вкладка Desktop Pet невидимо пересоздаёт
  оверлей, так что питомец в одном клике от того же состояния,
  в котором вы его оставили.

Успешная загрузка автоматически устанавливает **Show pet on
desktop**, чтобы питомец появился сразу. Путь ошибки оставляет
флажок нетронутым и пишет ошибку в метку статуса вкладки.

Окно оверлея
^^^^^^^^^^^^

Персонаж живёт в окне верхнего уровня, отдельном от главного окна
Imervue. Окно безрамочное, не имеет записи в панели задач и (по
умолчанию) находится поверх всех остальных окон.

.. list-table:: Поведение окна
   :header-rows: 1
   :widths: 28 72

   * - Поведение
     - Подробности
   * - Безрамочный оверлей
     - Без оконного хрома, без кнопок свернуть / закрыть, без
       записи в панели задач. Персонаж — это вся видимая
       поверхность.
   * - Прозрачный фон
     - Всё, что персонаж не закрывает, полностью прозрачно.
       Рабочий стол / приложение за питомцем просвечивает
       попиксельно.
   * - Перетаскивание для перемещения
     - Левый клик в любом месте по телу, перетаскивание,
       отпускание. Жест распознаётся как клик только если курсор
       сдвинулся менее чем на шесть пикселей — большее
       перемещение превращает жест в перемещение, и обработчик
       клика не срабатывает.
   * - Прилипание к краю
     - Отпустите рядом с краем экрана (по умолчанию: в пределах
       24 пикс), и питомец «прищёлкнется» заподлицо к этому
       краю. Порог настраивается от 0 (выкл) до 200 (очень
       липкий). Прилипание работает независимо по каждой оси,
       так что перетаскивание в угол прижимает к обоим краям
       одновременно.
   * - Ограничение перелёта
     - Перетаскивание, заканчивающееся за краем экрана,
       возвращает питомца внутрь. Вы не можете оставить
       питомца за экраном, где его не схватить снова.
   * - Режим сквозного клика
     - Когда включён, каждое событие мыши проходит сквозь
       питомца к тому, что за ним. Персонаж по-прежнему виден,
       но его нельзя перетащить, кликнуть правой кнопкой или
       использовать для запуска движений. Включайте, когда
       питомец чисто декоративный.
   * - Фиксация позиции
     - Отключает перетаскивание, не затрагивая сквозной клик.
       Полезно, когда вы поставили питомца ровно туда, куда
       нужно, и не хотите, чтобы случайные перетаскивания его
       сдвинули.
   * - Всегда внизу
     - Переключает питомца из «всегда поверх» в «всегда
       внизу». Питомец сидит позади всех остальных окон как
       виджет рабочего стола. Также снимает флаг приёма
       фокуса, чтобы клик по питомцу не поднимал его.
   * - Скрывать в полноэкранном режиме
     - Фоновый опрос с частотой 1 Гц следит за активным окном
       на мониторе питомца. Когда это окно покрывает ≥ 99 %
       экрана с допуском по каждому краю ≤ 4 пикс (ловит как
       настоящий полноэкранный, так и безрамочный оконный
       режим игр), питомец автоматически скрывается. Когда
       полноэкранный режим заканчивается, питомец появляется
       снова в прежней позиции. Детектор использует Win32 API
       ``GetWindowRect`` на Windows; на macOS / Linux он
       корректно ничего не делает (питомец остаётся видимым).
   * - Пауза при скрытии
     - Тик отрисовки ~30 FPS, тик скрипта 1 Гц и опрос
       полноэкранного режима (если питомца скрыл не сам
       полноэкранный режим) останавливаются на ``hideEvent`` и
       перезапускаются на следующем ``showEvent``. Таймеры живых
       драйверов (моргание, idle, idle-движения, взгляд)
       продолжают работать.
   * - Предустановки размера
     - Маленький (200 × 300), средний (320 × 480), большой
       (480 × 720). Питомец меняет размер вокруг текущего
       центра, так что смена размера его не перемещает.
       Прилипание выполняется заново после смены размера.
   * - Слайдер непрозрачности
     - 10 – 100 %. Действует на уровне окна (через
       ``setWindowOpacity``), так что затухает весь питомец,
       а не только текстура. Нижняя граница 10 % существует,
       чтобы вы всегда могли увидеть и схватить питомца —
       полностью невидимый означал бы его потерю.
   * - Память позиции
     - Координаты ``(x, y)`` после прилипания после каждого
       отпускания сохраняются вместе с монитором, на котором он
       находится. При следующем запуске питомец возвращается в
       эту позицию, ограниченную пределами того монитора. Если
       монитора больше нет (вы отключили его с прошлого запуска),
       питомец переходит на первый экран, а сохранённая позиция
       ограничивается его пределами. Правый нижний угол
       используется, только если позиция ещё ни разу не
       сохранялась.

Модель взаимодействия
^^^^^^^^^^^^^^^^^^^^^

Питомец реагирует на ввод мыши через три независимых канала.

**Левый клик по телу**

Позиция клика отображается обратно в координаты холста
марионетки (отменяя панорамирование / масштаб холста) и проходит
через существующий конвейер ``hit_test``. Результат управляет
поведением так:

#. Если ``HitArea`` покрывает кликнутый объект И к этой области
   привязано движение, движение проигрывается.
#. Независимо от того, проигралось ли движение, питомец может
   показать речевой пузырь — см. раздел *Скрипт питомца* для
   приоритета выбора реплики.
#. Если ни одна область попадания не покрывает клик, питомец
   откатывается к приветствию (из списка ``greetings`` скрипта
   или встроенного запасного варианта).

Жест перетаскивания подавляет обработчик клика, так что
перемещение питомца не вызывает речевой пузырь. Нажатие
проигрывает движение из группы ``Drag`` рига, а отпускание после
перетаскивания — движение из его группы ``Land``, если в риге
есть такие группы.

**Правый клик в любом месте по телу**

Открывает контекстное меню следующей структуры:

* **Hide pet** — действие верхнего уровня, закрывающее оверлей.
* Подменю **Live drivers** — семь переключателей с галочками
  (Auto idle, Idle motions, Auto-blink, Drag-track head, Mouse
  gaze, Mic lip-sync, Webcam tracking). Состояние галочек отражает
  состояние живых драйверов, так что меню показывает то, что
  сейчас работает.
* Подменю **Play motion** — заполняется из списка
  ``document.motions`` активного рига. Выбор записи проигрывает
  это движение; реплика из ``motion_lines`` при этом не звучит
  (они отвечают только на клик по области попадания).
* Подменю **Apply expression** — заполняется из
  ``document.expressions`` рига. Выбор добавляет наложение
  параметров выражения; повторное применение ничего не делает.
* Пять переключателей с галочками верхнего уровня: **Lock
  position**, **Click-through**, **Always on bottom**, **Hide on
  fullscreen**, **Speech bubble** — быстрый доступ к тем же
  переключателям во вкладке рабочего пространства.
* Подменю **Size** — Small / Medium / Large; текущая предустановка
  отмечена галочкой.

Подменю движений / выражений отключены, когда риг не загружен.

**Иконка в системном трее**

Иконка трея (создаётся только на платформах, сообщающих о
поддержке трея) предоставляет четвёртую поверхность для самых
частых действий:

* Левый клик переключает видимость питомца.
* Правый клик открывает меню с **Show pet** (с галочкой),
  **Click-through**, **Open puppet…**, **Hide pet**.
* Пункты с галочкой Show / Click-through отражают состояние
  флажков рабочего пространства через ``sync_visibility`` /
  ``sync_click_through``, так что они остаются синхронизированными,
  где бы пользователь ни переключал соответствующий тумблер.

Живые драйверы
^^^^^^^^^^^^^^

Каждый живой драйвер создаётся лениво при первом включении, так
что неактивный питомец не платит ни цента времени таймера /
потока за драйверы, которые вы никогда не включаете. Состояние
каждого драйвера сохраняется; включите переключатель, закройте
Imervue и перезапустите — риг восстановится с теми же
работающими драйверами. Сам оверлей появляется при запуске,
только если в группе Window вкладки отмечен флажок **Show the pet
when Imervue starts**.

.. list-table::
   :header-rows: 1
   :widths: 22 50 28

   * - Драйвер
     - Что он делает
     - Опциональная зависимость
   * - **Auto idle**
     - Дыхание + лёгкий дрейф на стандартных параметрах
       (``ParamBreath`` и т.п.), чтобы персонаж казался
       живым, когда ничто другое не анимируется.
     - нет
   * - **Idle motions**
     - Случайным образом выбирает движение из группы ``Idle``
       рига и проигрывает его — одно сразу при включении, затем
       каждые несколько секунд. Уступает, пока играет движение
       не из группы Idle.
     - нет
   * - **Auto-blink**
     - Закрывает и снова открывает глаза по плавной косинусной
       кривой каждые ~4,5 с. Драйвер принудительно записывает
       параметр, чтобы другие драйверы, трогающие значения
       открытия глаз, не подавляли моргание.
     - нет
   * - **Drag-track head**
     - Голова + глаза поворачиваются к курсору, пока он
       движется над питомцем. Управляет
       ``ParamAngleX`` / ``ParamAngleY`` / ``ParamEyeBallX`` /
       ``ParamEyeBallY``.
     - нет
   * - **Mouse gaze**
     - Глаза и голова следят за курсором в любом месте экрана
       относительно центра питомца (глаза опережают). Управляет
       теми же четырьмя параметрами.
     - нет
   * - **Mic lip-sync**
     - RMS-амплитуда микрофона управляет ``ParamMouthOpenY``.
     - ``sounddevice``
   * - **Webcam tracking**
     - MediaPipe FaceLandmarker читает вашу веб-камеру с ~30 FPS
       и управляет позой головы + открытием глаз + параметрами
       открытия рта. Окно предпросмотра для питомца не
       открывается (предпросмотр камеры относится к вкладке
       Puppet).
     - ``opencv-python`` + ``mediapipe``

Два драйвера с опциональными зависимостями корректно
деградируют: если требуемый пакет не установлен, переключение
флажка отскакивает обратно, а метка статуса рабочего
пространства показывает подсказку «install sounddevice» /
«install opencv-python + mediapipe».

Скрипт питомца — собственный голос и события по расписанию
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

Речевой пузырь питомца берёт реплики из JSON-файла, который вы
можете написать и загрузить из группы **Pet script** на вкладке.
Скрипт управляет пятью вещами:

* **Приветствия** — реплики клика по умолчанию, когда ничего
  более конкретного не подходит.
* **Приветствия по времени суток** — приветствия для интервала
  местного времени (``morning`` 05–11 ч, ``afternoon`` 12–17 ч,
  ``evening`` 18–21 ч, ``night`` 22–04 ч), используются раньше
  обычных приветствий; интервал без реплик откатывается к ним.
* **Ответы на область попадания** — наборы реплик для каждого
  ``HitArea.id``.
* **Реплики движений** — наборы реплик для каждого имени
  движения, звучат, когда клик по области попадания проигрывает
  это движение (но не когда движение запущено из контекстного
  меню).
* **Запланированные напоминания** — реплики по таймеру,
  срабатывают каждые ``every_seconds`` монотонного настенного
  времени.

Схема (версионная — будущие поля совместимы вперёд):

.. code-block:: json

   {
     "version": 1,
     "name": "March 7th — playful voice",
     "greetings": [
       "Hi!", "Hello hello!", "Need a break?"
     ],
     "time_of_day_greetings": {
       "morning": ["Good morning!"],
       "night": ["Still up?"]
     },
     "hit_responses": {
       "HitAreaHead": ["Hey, my head!", "Stop poking!"],
       "HitAreaBody": ["Hehe~", "Pat pat?"]
     },
     "motion_lines": {
       "wave": ["Hi!", "Hello!"],
       "curtsy": ["Cheers!"]
     },
     "scheduled": [
       {"every_seconds": 1800, "messages": ["Stretch break!"]}
     ]
   }

Правила загрузки:

* Списки выбираются по кругу для каждого набора, чтобы
  пользователь не видел одну и ту же реплику дважды подряд.
* Неизвестные ключи верхнего уровня игнорируются (совместимость
  вперёд — будущий файл v2 по-прежнему загружается на рантайме
  v1).
* Мусорные записи списка (неверный тип, неправильные
  запланированные записи, нулевой / отрицательный
  ``every_seconds``) пропускаются — одна плохая строка не
  ломает всю загрузку. Только полностью неразбираемый JSON
  поднимает ошибку и показывает путь в метке статуса.
* Каскад области попадания / движения / приветствия слоистый:
  левый клик сначала смотрит в ``hit_responses[area.id]``, затем
  в ``motion_lines[area.motion]``, затем в ``time_of_day_greetings``,
  затем в ``greetings``, затем в встроенный набор приветствий по
  умолчанию как нижний этаж.
* Отслеживание времени использует ``time.monotonic``, так что
  усыпление ноутбука или скачок системных часов не могут
  залпом выпалить накопленные события.

**Reset to default** сбрасывает пользовательский скрипт и
возвращает встроенный набор приветствий; сохранённый путь
скрипта очищается, так что следующий запуск не перезагрузит
его.

Рабочий пример лежит в
``examples/desktop_pet/march_7th.petscript.json`` — шесть
приветствий, два набора областей попадания (голова / тело), три
набора реплик движений (wave / curtsy / cheer) и
30-минутное напоминание о растяжке. Реплики для головы / тела
отвечают на клики по ригу, у которого области попадания
называются ``HitAreaHead`` / ``HitAreaBody`` (соглашение
Cubism); поставляемый в комплекте риг March 7th их не
определяет, поэтому клик по нему вместо этого выбирает
приветствие.

Сохранение состояния
^^^^^^^^^^^^^^^^^^^^

Всё состояние Desktop Pet циркулирует через
``user_setting_dict["desktop_pet"]`` (слот в стандартном
файле пользовательских настроек Imervue). Каждое поле имеет
значение по умолчанию + ограничение диапазона при загрузке,
так что испорченный файл настроек не может уронить запуск.

.. list-table:: Сохраняемые поля
   :header-rows: 1
   :widths: 28 18 54

   * - Поле
     - По умолчанию
     - Примечания
   * - ``last_rig_path``
     - ``""``
     - Автоматически восстанавливается при запуске, если файл
       ещё существует.
   * - ``script_path``
     - ``""``
     - Автоматически восстанавливается при запуске, если скрипт
       ещё разбирается; нечитаемый скрипт молча откатывается к
       значениям по умолчанию.
   * - ``position``
     - ``[-1, -1]``
     - Экранные координаты ``(x, y)`` от последнего
       отпускания перетаскивания. ``-1, -1`` (ещё не сохранялось)
       означает «использовать правый нижний угол». Если
       сохранённого монитора больше нет, позиция ограничивается
       пределами первого экрана.
   * - ``size_preset``
     - ``"medium"``
     - Одно из ``small`` / ``medium`` / ``large``.
   * - ``opacity``
     - ``1.0``
     - Значения вне диапазона ограничиваются ``[0.1, 1.0]``;
       только нечисловое значение откатывается к значению по
       умолчанию.
   * - ``click_through``
     - ``false``
     -
   * - ``anchor_locked``
     - ``false``
     -
   * - ``always_on_bottom``
     - ``false``
     - Взаимоисключающее с «всегда поверх».
   * - ``hide_on_fullscreen``
     - ``true``
     - Установите ``false``, чтобы оставить питомца видимым во
       время полноэкранного режима.
   * - ``snap_threshold``
     - ``24``
     - Ограничено диапазоном ``[0, 200]`` пикс.
   * - ``drivers``
     - ``auto_idle``, ``idle_motion``, ``auto_blink``
       ``true``; остальные ``false``
     - Поддиктионарий по id драйвера (``auto_idle``,
       ``idle_motion``, ``auto_blink``, ``drag_track``,
       ``mouse_gaze``, ``mic_lipsync``, ``webcam_tracking``).
       Неизвестные ключи проходят насквозь нетронутыми для
       совместимости вперёд.
   * - ``show_on_launch``
     - ``false``
     - Задаётся флажком **Show the pet when Imervue starts** в
       группе Window вкладки. Риг и драйверы восстанавливаются
       при запуске в любом случае; оверлей появляется, только
       если этот флажок включён.
   * - ``speech_enabled``
     - ``true``
     - Когда false, речевой пузырь никогда не появляется.

Поведение слияния словаря настроек одноуровневое: старые файлы
настроек без новых ключей всё равно дают полное состояние при
загрузке (значения по умолчанию заполняют пробелы); новые
ключи, которые вы сохранили, переживают откат к более старому
рантайму, не знающему о них.

Создание нового питомца
^^^^^^^^^^^^^^^^^^^^^^^

Любой ``.puppet``-файл работает как персонаж Desktop Pet —
вкладка Desktop Pet это чисто рендерер + оболочка взаимодействия;
авторинг рига происходит во вкладке Puppet (см.
*Рабочее пространство Puppet (вкладка Puppet)*).

Чтобы создать свой собственный риг питомца:

#. Переключитесь на вкладку Puppet и импортируйте иллюстрацию
   через **File > Import PNG…** или **File > Import PSD…**, или
   подгрузите модель Cubism через **File > Import Cubism…**.
#. Создайте деформеры поворота / искажения, параметры, движения,
   выражения и (опционально) области попадания, привязанные к
   частям тела, чтобы обработчик левого клика Desktop Pet мог
   запускать движения.
#. Сохраните риг через **File > Save As…** в zip ``.puppet``.
#. Переключитесь обратно на вкладку Desktop Pet и загрузите
   новый файл через **Open Puppet…**.

Если ваш риг определяет записи ``HitArea``, вы можете написать
реплики речевого пузыря для каждой области попадания в
``.petscript.json``, чьи ключи ``hit_responses`` соответствуют
id областей.

Устранение неполадок
^^^^^^^^^^^^^^^^^^^^

**Питомец появляется внутри серого прямоугольника вместо того,
чтобы быть полностью прозрачным.** Атрибут полупрозрачного фона
уровня ОС требует GL-поверхности с поддержкой альфа плюс
соответствующих атрибутов на встроенном виджете GL. Убедитесь,
что никакой сторонний инструмент управления окнами не
переопределяет атрибут ``WA_TranslucentBackground`` на окне
оверлея (некоторые пользовательские оконные менеджеры на Linux
так делают). На Windows / macOS это должно «просто работать».

**«Load bundled March 7th» сообщает, что файл не найден.**
Резолвер сначала смотрит в ``examples_dir()`` (безопасное для
заморозки место, используемое упакованными сборками), затем
падает обратно к пути относительно CWD. Если ни там, ни там нет
рига, метка статуса показывает ожидаемый путь. Проверьте, что
каталог ``examples/`` поставлен с вашей установкой — для
запуска из исходников запускайте Imervue из корня репозитория.

**Питомец не говорит, когда его кликают.** Три проверки:

#. Убедитесь, что переключатель **Speech bubble on click**
   включён (во вкладке или в правом клике).
#. Если вы загрузили собственный скрипт, проверьте, что JSON
   разбирается — метка статуса вкладки покажет ошибку загрузки.
#. Если включён **Click-through**, клик уходит окну позади
   питомца; выключите его во вкладке или в меню трея. (При
   включённой речи каждый клик получает реплику: риг без
   областей попадания не проигрывает движение, но клик всё равно
   вас приветствует.)

**Флажок отслеживания веб-камеры отскакивает обратно.**
Отслеживание веб-камеры требует, чтобы ``opencv-python`` и
``mediapipe`` были установлены в том же Python-окружении, в
котором работает Imervue. Установите через
``pip install opencv-python mediapipe``. После установки
снова отметьте флажок. Питомец не открывает окно предпросмотра;
чтобы увидеть, что обнаруживает камера, включите **Webcam
tracking** во вкладке Puppet — там показываются точки лица.

**Питомец не скрывается автоматически в полноэкранных
приложениях.** Детектор полноэкранного режима опрашивает
активное окно с частотой 1 Гц. На Windows он использует Win32
API ``GetWindowRect``; на macOS / Linux у него нет надёжного
кросс-платформенного эквивалента, и он бездействует (питомец
остаётся видимым). Для Windows: убедитесь, что **Hide when
other app is fullscreen** отмечено, и проверьте, что
полноэкранное окно действительно покрывает ≥ 99 % того же
монитора, что и питомец.

**Позиция питомца уплывает за пределы экрана между запусками.**
Это случается, когда экран, на котором был питомец, больше не
подключён при следующем запуске (док-станция ноутбука,
отключённый второй монитор). В этом случае питомец переходит на
первый экран, а сохранённая позиция ограничивается его пределами —
перетащите его туда, куда хотите, и следующее сохранение
перезапишет устаревшую позицию.

Воспроизведение анимации
------------------------

При открытии файлов GIF, APNG или анимированного WebP анимация воспроизводится автоматически. Анимация, которой в
декодированном виде нужно больше 512 МБ, декодируется по одному кадру во время
воспроизведения, поэтому её открытие не замораживает окно и не занимает всю память.
Кадр длительностью 10 мс и меньше показывается 100 мс, как в браузерах: на это рассчитаны многие GIF.

Многостраничный TIFF — отсканированный документ — не проигрывается: он показывается по одной странице, листается клавишами ``,`` и ``.``, а индикатор показывает номер страницы. Кадры, которые не являются анимацией, тоже не проигрываются: превью, которое камера встраивает в JPEG (MPF), слои PSD и изображение по умолчанию в APNG — статичная картинка для программ без поддержки APNG.

.. list-table::
   :header-rows: 1
   :widths: 30 70

   * - Клавиша
     - Действие
   * - ``Пробел``
     - Воспроизведение / Пауза
   * - ``,``
     - Предыдущий кадр
   * - ``.``
     - Следующий кадр
   * - ``]``
     - Ускорить
   * - ``[``
     - Замедлить

Сравнение изображений
---------------------

В режиме миниатюр выберите 2 или 4 изображения, затем правый клик > ``Сравнить изображения``
(или выберите их в списке диалога).

Диалог имеет четыре вкладки:

.. list-table::
   :header-rows: 1
   :widths: 25 75

   * - Вкладка
     - Назначение
   * - **Side-by-side**
     - Одновременное отображение 2 или 4 изображений; каждое автоматически масштабируется в своей панели.
   * - **Overlay**
     - Смешивание двух изображений с альфа-слайдером (0 → только A, 100 → только B). Требуется ровно 2 выбранных.
   * - **Difference**
     - Попиксельная визуализация ``|A − B|`` со слайдером усиления (0.10× – 20×) для усиления тонких изменений.
   * - **A | B Split**
     - Разделённое отображение До / после с перетаскиваемым вертикальным разделителем. Перетаскивайте маркер для пробега между двумя
       изображениями; идеально для показа регулировок рецепта проявки или сравнения экспортов. Требуется ровно 2 выбранных.

Когда два изображения имеют разные размеры, ``B`` пересэмплируется до
размеров ``A`` методом Lanczos. Очень большие изображения внутренне
ограничиваются 2048 пикс по длинной стороне, чтобы overlay / difference
оставались интерактивными.

.. seealso::
   Для встроенного сравнения без открытия диалога используйте **Разделённый вид** (``Shift + S``) или
   **Чтение разворотов** (``Shift + D`` / ``Ctrl + Shift + D``), описанные в разделе «Просмотр».

``IMG.JPG.xmp`` и ``IMG.JPG.annotations.json``. ``IMG.xmp``, который ещё
использует RAW из пары RAW + JPEG, копируется, а не перемещается.

Фото, переименованное в другой программе, пока его папка открыта в Imervue,
сохраняет те же данные; данные, которые уже были у нового имени, остаются как
есть.

Установить как обои
-------------------

В режиме Deep Zoom правый клик > ``Установить как обои``, чтобы установить
текущее изображение как обои рабочего стола.

Поддерживается в Windows, macOS и Linux (GNOME).

Получив файл, который не может декодировать, Windows делает рабочий стол чёрным и всё равно сообщает об успехе. Поэтому изображение не в формате JPEG, PNG или BMP — RAW с камеры, HEIC, PSD, TGA, WebP и другие форматы, которые открывает Imervue, — и фото, которое нужно повернуть, передаются как JPEG-копия того, что показывает просмотрщик. Копия хранится в ``%LOCALAPPDATA%\Imervue\wallpaper`` (``~/.local/share/imervue/wallpaper`` в macOS и Linux); остаётся только самая новая.

Управление библиотекой и метаданными
------------------------------------

Imervue поддерживает индекс на основе SQLite по адресу
``%LOCALAPPDATA%/Imervue/library.db`` (Windows) или
``~/.cache/imervue/library.db`` (POSIX) для межпапочного поиска,
иерархических тегов, умных альбомов, перцептивных хэшей, заметок
и флагов отбора. Всё нижеперечисленное находится в ``Extra Tools``,
если не указано иное. В последней версии меню организовано в восемь
функционально сгруппированных подменю — ``Batch``, ``Library & Metadata``,
``Views``, ``Workflow``, ``Export``, ``Develop (Non-Destructive)``,
``Retouch & Transform`` и ``Multi-Image`` — поэтому каждый путь ниже
показан как ``Extra Tools`` > ``<подменю>`` > ``<инструмент>``.

Поиск по библиотеке
^^^^^^^^^^^^^^^^^^^

``Extra Tools`` > ``Library & Metadata`` > ``Library Search`` позволяет
добавить одну или несколько **корневых папок** в глобальный индекс,
который обходится в фоновом потоке. После индексирования корня по нему
можно искать по имени файла, минимальной ширине / высоте и размеру файла
(до 2000 результатов); двойной клик по результату открывает его.

Правый клик > ``Search by Query…`` фильтрует текущую папку компактным языком запросов, например ``kw:beach rating:>=4 type:video place:Paris``. ``place:`` принимает город, страну или и то и другое (``Paris``, ``France``, ``Paris, France``); значение с пробелами берётся в двойные кавычки (``place:"Rio de Janeiro"``).

Умные альбомы
^^^^^^^^^^^^^

``Extra Tools`` > ``Library & Metadata`` > ``Smart Albums`` сохраняет
правила фильтрации (расширения, минимальные размеры, цветные метки,
рейтинг, избранное, состояние отбора, иерархические теги, подстрока
имени) под удобным именем. Повторное применение альбома фильтрует
активную папку по сохранённым правилам.

Поиск похожих изображений
^^^^^^^^^^^^^^^^^^^^^^^^^

``Extra Tools`` > ``Library & Metadata`` > ``Find Similar Images``
запускает 64-битный DCT pHash на текущем изображении Deep Zoom (или
первой выбранной плитке) и показывает близкие совпадения из индекса,
отсортированные по расстоянию Хэмминга. Регулируйте счётчик
``Max Hamming distance``, чтобы расширить или сузить сеть.

Семантический поиск (CLIP)
^^^^^^^^^^^^^^^^^^^^^^^^^^

``Extra Tools`` > ``Library & Metadata`` > ``Semantic Search``
позволяет ввести фразу на естественном языке (например, *"golden retriever in snow"* или
*"neon street at night"*) и возвращает ранжированные изображения
открытой папки. Каждое изображение встраивается
с помощью CLIP визуально-языкового кодировщика и сохраняется рядом
с его путём; текстовый запрос встраивается в то же векторное
пространство и сравнивается по косинусному сходству.

Эмбеддинги кэшируются в ``%LOCALAPPDATA%/Imervue/clip_cache.npz`` (Windows) или ``~/.cache/imervue/clip_cache.npz`` (POSIX) как один компактный архив ``.npz``. Диалог ищет в открытой папке: он кодирует только изображения, которых ещё нет в кэше или которые с тех пор изменились (размер или время изменения), поэтому повторный поиск в той же папке начинается сразу, а результаты берутся только из этой папки.

.. note::
   Семантический поиск требует опциональные пакеты ``open_clip_torch``
   и ``torch``. Если они не установлены, пункт меню объясняет, что
   отсутствует, а другие функции продолжают работать.

Автотегирование
^^^^^^^^^^^^^^^

``Extra Tools`` > ``Library & Metadata`` > ``Auto-Tag Images`` применяет
эвристические теги в ``auto/...`` (``photo`` / ``document`` /
``screenshot`` / ``graphic`` / ``landscape`` / ``portrait``), определяя их по
насыщенности цвета, краям и форме изображения в том виде, в каком его показывает
просмотрщик. Работает в рабочем потоке с живой шкалой прогресса.

Иерархические теги
^^^^^^^^^^^^^^^^^^

``Extra Tools`` > ``Library & Metadata`` > ``Hierarchical Tags``
управляет древовидно структурированными тегами, такими как
``animal/cat/british``. Выберите тег, чтобы увидеть каждое
изображение под этой веткой (включая потомков). Пометьте или
снимите тег с текущего выделения одним кликом. Иерархические теги
живут в индексе библиотеки и дополняют плоскую систему тегов в
меню правого клика.

Правый клик > ``Пакетные операции`` > ``Index Keywords`` (при выбранных миниатюрах)
добавляет XMP-ключевые слова выделения в библиотеку. Иерархия ключевых слов из Lightroom или darktable
(``lr:hierarchicalSubject``, ``Places|Taiwan|Taipei``) сохраняется как путь тега
``Places/Taiwan/Taipei``, а отдельные ``Places`` / ``Taiwan`` / ``Taipei``, лишь
повторяющие её уровни, повторно не добавляются.

Пакетное переименование по токенам
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

``Extra Tools`` > ``Batch`` > ``Token Batch Rename`` открывает таблицу
с предпросмотром в реальном времени, где вы вводите шаблон вроде
``{date:yyyymmdd}_{camera}_{counter:04}{ext}`` и видите точно, как
будет переименован каждый файл. Конфликты подсвечиваются, чтобы
ничего не было перезаписано. Поддерживаемые токены: ``{name} {ext}
{counter[:NN]} {date[:fmt]} {width} {height} {wxh} {size_kb}
{camera} {year} {month} {day} {hour} {minute}``. Новое имя, которое сейчас носит другой выбранный
файл, не считается конфликтом: перенумерация (``002`` → ``003``, пока ``003`` →
``004``) или обмен двух имён переименовывает весь выбор. Batch Rename работает так же.

Экспорт метаданных
^^^^^^^^^^^^^^^^^^

``Extra Tools`` > ``Library & Metadata`` > ``Export Metadata (CSV / JSON)``
записывает по строке на изображение в текущем виде, охватывая EXIF,
размеры, цветную метку, рейтинг, избранное, иерархические теги,
состояние отбора и заметки. Полезно для передачи решений отбора в
электронную таблицу или внешний рабочий процесс.

XMP-сайдкары
^^^^^^^^^^^^

Imervue умеет читать и записывать файлы Adobe XMP-сайдкаров
(``photo.jpg`` ↔ ``photo.xmp``), так что рейтинги, заголовки,
описания, ключевые слова и цветные метки без потерь передаются
в обе стороны между Imervue, Adobe Bridge и другими фотоменеджерами
с поддержкой XMP.

При сохранении данные сливаются с существующим sidecar-файлом: меняются только эти поля, поэтому сохранённые там настройки проявки, кадрирование и история другого редактора остаются, а нечитаемый sidecar никогда не перезаписывается.

Помимо ``photo.xmp`` (Lightroom, Bridge), читается и обновляется
``photo.jpg.xmp``, который пишут darktable и digiKam, если это единственный
sidecar. Цветовые метки понимаются в словах Lightroom (``Red`` … ``Purple``) и
Bridge (``Select``, ``Second``, ``Approved``, ``Review``, ``To Do``). Новый или
изменённый цвет экспортируется так, как его пишет Lightroom; sidecar, в котором для
того же цвета уже стоит слово Bridge, сохраняет это слово. Метка без цвета (своя)
остаётся в sidecar.

Отклонённое фото — ``xmp:Rating`` -1 в Lightroom, Bridge и darktable —
импортируется как **Reject** при отборе, без звёзд, а Reject экспортируется как
-1. Неотклонённый sidecar снимает Reject; Pick остаётся без изменений.

Файл без sidecar читается — и импортируется — из того, что встроено в него самого:
из XMP-пакета (JPEG, PNG, WebP, TIFF, CR3, RW2, ORF, RAF), затем из EXIF ``Rating`` / ``RatingPercent``.
Там Lightroom хранит оценку и ключевые слова JPEG, а Проводник Windows и некоторые
камеры — звёзды. Если sidecar есть, он главнее.

``Extra Tools`` > ``Library & Metadata`` > ``XMP Sidecars`` содержит две кнопки, которые
действуют на все изображения в текущем виде:

- **Export sidecars** — записывает рейтинг / заголовок / описание / ключевые слова /
  цветную метку каждого изображения в его сайдкар.
- **Import sidecars** — считывает их обратно во внутренние записи Imervue.

Парсинг XML использует ``defusedxml``, поэтому некорректные или
вредоносные сайдкары не могут вызвать XXE / billion-laughs атаки.

**Боковая панель EXIF** также предоставляет кликабельную **полосу
звёздного рейтинга** — рейтинг, который она устанавливает, — это то,
что будет записано при экспорте XMP.

Отбор (Pick / Reject)
^^^^^^^^^^^^^^^^^^^^^

Флаг отбора с тремя состояниями. Нажмите ``P``, чтобы выбрать текущее
изображение или каждую выбранную плитку, ``Shift + X`` для
отклонения, ``U``, чтобы снять флаг. ``Фильтр`` > ``По состоянию
отбора`` показывает только выбранные, отклонённые или без флага.
``Extra Tools`` > ``Workflow`` > ``Culling`` применяет фильтр через диалог и также
предоставляет кнопку **Delete all rejects**, которая навсегда удаляет
помеченные файлы с диска.

Тоут подготовки
^^^^^^^^^^^^^^^

``Extra Tools`` > ``Workflow`` > ``Staging Tray`` — это межпапочная
корзина. Добавьте любой набор плиток в тоут (список сохраняется
между перезапусками), затем переместите или скопируйте весь тоут в
папку назначения одним кликом. Полезно для сбора выбранных кадров
из множества съёмок перед экспортом.

Двухпанельный файловый менеджер
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

``Extra Tools`` > ``Workflow`` > ``Dual-Pane File Manager`` открывает
двухпанельный вид с двумя деревьями. Выберите папку в каждой панели
и перемещайте/копируйте выделение между ними, не покидая Imervue.

Вид временной шкалы
^^^^^^^^^^^^^^^^^^^

``Extra Tools`` > ``Views`` > ``Timeline View`` группирует текущий
набор изображений по дню, месяцу или году (группировка по дате).
Дата берётся из EXIF ``DateTimeOriginal``, затем из
``DateTimeDigitized``, затем из ``DateTime``, а иначе из времени
модификации файла. Двойной клик по любому изображению открывает его
в Deep Zoom.

Перетаскивание во внешние приложения
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

Нажмите и перетащите из **выбранной** плитки, чтобы бросить файл
в Проводник, Chrome, Discord или любое приложение, принимающее
файловые URL. Предпросмотр перетаскивания — миниатюра плитки.

Заметки на изображение
^^^^^^^^^^^^^^^^^^^^^^

Боковая панель EXIF включает поле свободного текста **Notes**.
При вводе автосохранение в индекс библиотеки происходит после
короткого debounce. Заметки путешествуют с путём изображения,
поэтому переживают повторное сканирование папок.

----

Продвинутая проявка и композитинг
---------------------------------

Тоновая кривая
^^^^^^^^^^^^^^

``Extra Tools`` > ``Develop (Non-Destructive)`` > ``Tone Curve``
открывает редактор кривой с перетаскиваемыми точками с четырьмя
каналами (RGB, R, G, B). Левый клик на пустом холсте добавляет точку;
перетаскивание перемещает; правый клик удаляет. Точки интерполируются
монотонным кубическим сплайном и сохраняются в рецепте изображения,
поэтому кривая применяется неразрушающе во время рендеринга.

Применить LUT .cube
^^^^^^^^^^^^^^^^^^^

``Extra Tools`` > ``Develop (Non-Destructive)`` > ``Apply .cube LUT``
позволяет выбрать любой файл Adobe ``.cube`` (3D до 65³, 1D до 65 536 точек). ``LUT_1D_INPUT_RANGE`` / ``LUT_3D_INPUT_RANGE``
из DaVinci Resolve задаёт входной диапазон так же, как ``DOMAIN_MIN`` /
``DOMAIN_MAX``, а файл, сохранённый с BOM, тоже читается.
LUT парсится с ``lru_cache`` по ключу пути + mtime, оценивается
трилинейной интерполяцией и смешивается с оригиналом через слайдер
интенсивности. Путь к LUT и интенсивность живут в рецепте.

Виртуальные копии
^^^^^^^^^^^^^^^^^

``Extra Tools`` > ``Workflow`` > ``Virtual Copies`` даёт каждому
изображению именованные снимки рецепта. Снимите текущее редактирование,
продолжайте экспериментировать и переключайтесь обратно на любой
ранний вариант позже. Варианты лежат рядом с основным рецептом в
хранилище рецептов и переживают сброс мастера к идентичности.

Слияние HDR
^^^^^^^^^^^

``Extra Tools`` > ``Multi-Image`` > ``HDR Merge`` объединяет две или
более скобочных экспозиций в одно изображение через слияние
экспозиций Mertens из OpenCV. Опциональный флажок «Align exposures»
сначала запускает ``cv2.AlignMTB`` для компенсации дрожания съёмки
с рук. Вывод сохраняется в выбранный пользователем файл — он не
затрагивает ни одно исходное изображение.

Сшивка панорамы
^^^^^^^^^^^^^^^

``Extra Tools`` > ``Multi-Image`` > ``Panorama Stitch`` оборачивает
высокоуровневый API ``Stitcher`` из OpenCV. Выберите режим
**Panorama** для пейзажей / городских пейзажей или **Scans** для
плоских документов и художественных работ. Чёрные края, возникающие
при искривлении, могут быть автоматически обрезаны.

Фокус-стекинг
^^^^^^^^^^^^^

``Extra Tools`` > ``Multi-Image`` > ``Focus Stacking`` объединяет
несколько кадров, снятых на разных расстояниях фокуса. Для каждого
пикселя алгоритм выбирает входной кадр с наибольшей локальной
резкостью (дисперсия Лапласиана), затем сглаживает маску выбора
гауссовым смешиванием, чтобы избежать швов. Выравнивание ECC
включено по умолчанию для лёгких смещений съёмки с рук.

Лечащая кисть
^^^^^^^^^^^^^

``Extra Tools`` > ``Retouch & Transform`` > ``Healing Brush``
показывает текущее изображение до 720 пикс по длинной стороне.
Левый клик добавляет круговое пятно; правый клик по существующему
пятну удаляет его; слайдер радиуса задаёт размер нового пятна. При
применении инпейнтинг OpenCV (Telea для скорости, Navier-Stokes для
более плавного смешивания) заполняет каждую замаскированную область
из окружающих пикселей, и результат сохраняется в новый файл.

Коррекция объектива
^^^^^^^^^^^^^^^^^^^

``Extra Tools`` > ``Retouch & Transform`` > ``Lens Correction``
предоставляет четыре чистых numpy-слайдера: радиальная дисторсия
``k1`` (бочка / подушка), подъём виньетки и поканальный радиальный
масштаб хроматической аберрации для красного и синего. Откорректированное
изображение того же размера, что и оригинал, сохраняется как новый файл.

Вид карты
^^^^^^^^^

``Extra Tools`` > ``Views`` > ``Map View`` отображает геотегированные
изображения открытой папки на интерактивной карте Leaflet + OpenStreetMap,
по одному маркеру на ближайший город с числом снимков в нём (требуется
``PySide6.QtWebEngineWidgets``). Без WebEngine диалог переходит на
список этих мест с числом снимков и координатами, чтобы функция оставалась
пригодной для использования на минимальных установках.

Вид календаря
^^^^^^^^^^^^^

``Extra Tools`` > ``Views`` > ``Calendar View`` показывает
``QCalendarWidget`` с подсвеченными днями, когда были сделаны
фотографии в этот день (EXIF ``DateTimeOriginal`` →
``DateTimeDigitized`` → ``DateTime`` → mtime файла). Выбор даты
выводит список изображений; двойной клик открывает одно в главном
просмотрщике.

Обнаружение лиц
^^^^^^^^^^^^^^^

``Extra Tools`` > ``Retouch & Transform`` > ``Face Detection``
запускает каскад Хаара OpenCV для фронтальных лиц на текущем
изображении и рисует каждое обнаружение прямоугольником. Двойной
клик по строке в списке для ввода имени человека; при сохранении
теги записываются в blob ``extra['face_tags']`` рецепта. Обнаружение
— это классическая техника — точность достаточна для «покажи мне
лица», но не замена современному распознаванию на основе CNN.
Нужен OpenCV 4 (``pip install "opencv-python<5"``): в OpenCV 5 каскадов Хаара
больше нет, и тогда диалог сообщает об этом вместо обнаружения.

Локальные маски регулировки
^^^^^^^^^^^^^^^^^^^^^^^^^^^

``Extra Tools`` > ``Develop (Non-Destructive)`` > ``Local Adjustment Masks``
накладывает на изображение кистевые, радиальные или линейные
градиентные маски. Каждая маска несёт собственные дельты экспозиции,
яркости, контраста, насыщенности, температуры, оттенка плюс слайдер
растушёвки. Маски сохраняются в ``recipe.extra['masks']`` и
применяются неразрушающе при загрузке, поэтому исходный файл
никогда не затрагивается.

Раздельное тонирование
^^^^^^^^^^^^^^^^^^^^^^

``Extra Tools`` > ``Develop (Non-Destructive)`` > ``Split Toning``
применяет различные оттенки к теням и светам с насыщенностью на
область и точкой опоры баланса. Сохраняется в
``recipe.extra['split_toning']`` и применяется после тоновой кривой
в конвейере проявки.

Штамп клонирования
^^^^^^^^^^^^^^^^^^

``Extra Tools`` > ``Retouch & Transform`` > ``Clone Stamp`` копирует
растушёванный исходный участок на место назначения — жёсткокраевое
дополнение к лечащей кисти. Shift+клик задаёт источник, обычный
клик штампует, правый клик отменяет. Результат записывается в
новый файл, чтобы оригинал оставался нетронутым.

Обрезка / Выпрямление
^^^^^^^^^^^^^^^^^^^^^

``Extra Tools`` > ``Retouch & Transform`` > ``Crop / Straighten``
объединяет нормализованный (0..1) прямоугольник обрезки с углом
выпрямления до ±15°. Вывод автоматически обрезается до наибольшего
внутреннего прямоугольника, чтобы у повёрнутых фотографий не было
чёрных углов.

Авто-выпрямление
^^^^^^^^^^^^^^^^

``Extra Tools`` > ``Retouch & Transform`` > ``Auto-Straighten``
обнаруживает доминирующий горизонт или вертикальные линии через
обнаружение линий Хафа и предлагает поворот. Один клик применяет
выпрямление; вы можете подкорректировать угол сначала, если
автоопределение выбирает неправильную опорную точку.

Шумоподавление / Резкость
^^^^^^^^^^^^^^^^^^^^^^^^^

``Extra Tools`` > ``Retouch & Transform`` > ``Noise Reduction / Sharpening``
применяет билатеральное (сохраняющее края) шумоподавление с
последующей резкостью методом unsharp-mask. «Только яркость»
сохраняет цветовой шум нетронутым, но сглаживает зерно без размытия
краёв цветности.

Небо / Фон
^^^^^^^^^^

``Extra Tools`` > ``Retouch & Transform`` > ``Sky / Background``
заменяет обнаруженное небо градиентом или убирает фон в прозрачный /
белый. Когда установлен ``rembg`` (U²-Net), маска переднего плана
берётся из сети сегментации; иначе используется эвристическое
правило HSV.

Софт-пруфинг
^^^^^^^^^^^^

``Extra Tools`` > ``Develop (Non-Destructive)`` > ``Soft Proof``
загружает ICC-профиль, конвертирует изображение через него и обратно
и подсвечивает пиксели, которые отсеклись во время кругового
обхода, пурпурным — быстрая проверка выхода за пределы гаммы перед
печатью.

Тональные и творческие эффекты
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

``Extra Tools`` > ``Develop (Non-Destructive)`` собирает набор
одноразовых эффектов «применить и сохранить», каждый из которых —
тонкий диалог со слайдерами поверх чистого NumPy-преобразования
(«Рамка и подпись» рисует через Pillow; та же логика также доступна
как инструмент MCP):

- **Градиентная плотность** — линейный нейтрально-серый градиент,
  задаваемый углом, жёсткостью и смещением, с опциональным
  тонированием; затемняет небо или передний план без ручной маски.
- **Тоновый эквалайзер** — независимая экспозиция для каждой зоны
  яркости (по слайдеру от чёрных к белым) поверх сглаженной маски,
  так что корректировка следует за тонами сцены.
- **Эквалайзер детализации** — слайдер усиления для каждой частотной
  полосы (от тонкой текстуры к грубому контрасту), многомасштабная
  альтернатива одному слайдеру чёткости.
- **Кинематографический тонмаппинг** — rolloff светов по Reinhard
  или Hable с поворотом контраста относительно опорной точки и
  восстановлением насыщенности, для высококонтрастных одиночных
  экспозиций.
- **Velvia** — повышение насыщенности с учётом яркости, усиливающее
  приглушённые цвета и щадящее уже насыщенные цвета и тени.
- **Цветной негатив** — инверсия отсканированного цветного негатива
  с вычитанием автоматически оценённой оранжевой основы плёнки и
  слайдером выходной гаммы.
- **Удаление каймы** — обесцвечивание пурпурных/зелёных каёмок
  хроматической аберрации вдоль высококонтрастных краёв, не
  затрагивая ровный цвет.
- **Тиснение** — рельеф направленного света по полю высот яркости
  (азимут / высота / глубина + переключатель оттенков серого).
- **Полярные координаты** — сворачивание кадра в диск или его
  разворачивание (эффект крошечной планеты / полярной инверсии).
- **Калейдоскоп** — зеркалирование одного углового сектора в
  ``n``-кратную симметрию.
- **Матовое стекло** — детерминированный, воспроизводимый по
  сид-ключу локальный разброс пикселей.
- **Рамка и подпись** — паспарту любого цвета, необязательная более
  широкая нижняя полоса в стиле Polaroid и подпись, впечатанная
  в неё своим цветом.

GPS-геотегирование
^^^^^^^^^^^^^^^^^^

``Extra Tools`` > ``Library & Metadata`` > ``GPS Geotag`` читает
существующие EXIF GPS-теги и позволяет редактировать или устанавливать
новые координаты в десятичных градусах. JPEG записывается на месте без
дополнительных пакетов: меняется только его блок EXIF, поэтому пиксели,
остальные теги и миниатюра остаются прежними. WebP обрабатывается так же; другие форматы пометить нельзя.

**Редактор EXIF** (кнопка ``Edit EXIF`` на боковой панели EXIF) меняет описание, автора, авторские права, производителя / модель камеры и комментарий. Для JPEG и WebP не нужны дополнительные пакеты, переписывается только блок EXIF; для других форматов показывается, почему их нельзя изменить.

Веб-галерея
^^^^^^^^^^^

``Extra Tools`` > ``Export`` > ``Web Gallery`` сохраняет выбранные изображения (или всю
папку) как самодостаточный сайт: ``index.html`` с lightbox, JPEG-миниатюры и копии
оригиналов, если не снять флажок **Копировать оригиналы в полном размере**. Вы сами
задаёте заголовок страницы, а также размер и качество миниатюр. Со скопированными оригиналами
странице не нужен сервер: откройте её прямо с диска или разместите на любом статическом
хостинге. Без них её ссылки на полный размер ведут к снимкам на вашем собственном диске.

Установите флажок **Проверка клиентом**, чтобы отправить галерею клиенту на отзыв. Под каждым
изображением появится поле для комментария; заметки хранятся в браузере проверяющего, а кнопка
**Export comments** на странице сохраняет их все в один JSON-файл.

Раскладка для печати
^^^^^^^^^^^^^^^^^^^^

``Extra Tools`` > ``Export`` > ``Print Layout`` компонует несколько
изображений в многостраничный PDF с настраиваемым размером страницы,
ориентацией, сеткой, полями, межпанельным промежутком и метками
обрезки. Требует ``reportlab``.

Использование из командной строки
---------------------------------

::

   imervue                        # Обычный запуск
   imervue /path/to/image         # Открыть определённое изображение
   imervue /path/to/folder        # Открыть определённую папку
   imervue --debug                # Включить режим отладки
   imervue --software_opengl      # Использовать программный рендеринг (когда GPU не поддерживается)

Пакетный CLI без интерфейса
^^^^^^^^^^^^^^^^^^^^^^^^^^^

``Imervue.cli`` выполняет чистые операции над изображениями из оболочки, **не запуская
Qt**, поэтому им можно пользоваться из скриптов, шагов CI и на серверах без дисплея::

   py -m Imervue.cli resize photos/ --max 1600 --out web/
   py -m Imervue.cli watermark a.jpg --text "(c) Me" --corner bottom-right
   py -m Imervue.cli info *.png --json
   py -m Imervue.cli list-ops          # вывести все доступные подкоманды

.. list-table::
   :header-rows: 1
   :widths: 30 70

   * - Подкоманда
     - Назначение
   * - ``info`` / ``stats``
     - Размеры и формат; безэталонные метрики качества (``--json`` для машиночитаемого вывода)
   * - ``convert`` / ``resize`` / ``thumbnail``
     - Конвертация формата (``--format`` / ``--quality``), масштаб по максимальной длинной стороне, размер миниатюры
   * - ``watermark`` / ``optimize``
     - Текстовый водяной знак (``--text`` / ``--corner`` / ``--opacity``); кодирование в рамках бюджета ``--max-kb``
   * - ``dehaze`` / ``clahe`` / ``dither`` / ``distort``
     - Удаление дымки по тёмному каналу, адаптивная эквализация, упорядоченный дизеринг Байера, swirl / pinch / ripple
   * - ``auto-orient`` / ``strip``
     - Запечь флаг ориентации EXIF в пиксели; пересохранить без EXIF / XMP / ICC
   * - ``collage`` / ``anaglyph``
     - Сетчатый монтаж (``--columns``); красно-голубое 3D из стереопары (``--method``)
   * - ``preset`` / ``pipeline``
     - Применить сохранённый пресет обработки по имени; выполнить упорядоченный JSON-конвейер
   * - ``list-ops``
     - Вывести все подкоманды (``--json`` для машиночитаемого вывода)

Каждая подкоманда декодирует так же, как просмотрщик: результат разворачивается по EXIF-ориентации и преобразуется в sRGB из встроенного цветового профиля, входные AVIF читает сам Pillow, а входные HEIC / JPEG XL читаются, если установлен соответствующий необязательный бэкенд. RAW-файл камеры проявляется так же, как в просмотрщике, а не читается как маленькое встроенное превью; ``resize`` и ``strip`` записывают его в PNG. Нечитаемый файл попадает в отчёт, остальные всё равно обрабатываются. Обрезанный файл читается до того места, где он обрывается, как в просмотрщике. 16-битные и вещественные оттенки серого масштабируются до 8 бит, как в просмотрщике; ``resize`` и ``strip`` сохраняют разрядность исходника.

Подкоманды, принимающие файлы или папки (все, кроме ``collage``, ``anaglyph`` и ``list-ops``), используют общие флаги ``--out`` (каталог вывода), ``--recursive``, ``--dry-run`` (только перечислить действия, ничего не писать), ``--overwrite`` и ``-j`` / ``--jobs`` (число параллельных обработчиков; ``0`` задействует все ядра). ``collage`` и ``anaglyph`` записывают один файл, указанный в ``--out``. ``--version`` выводит версию CLI.

MCP-сервер
----------

Imervue поставляется со встроенным сервером `Model Context Protocol
<https://modelcontextprotocol.io>`_, который позволяет AI-ассистентам
(Claude Code, Claude Desktop, Cursor, Cline, …) вызывать чистые
логические помощники проекта без работающего GUI. Запустите его
командой::

   python -m Imervue.mcp_server

Сервер не зависит от Qt и загружает только то, что нужно каждому
инструменту во время вызова.

Доступные инструменты
^^^^^^^^^^^^^^^^^^^^^

.. list-table::
   :header-rows: 1
   :widths: 28 72

   * - Инструмент
     - Назначение
   * - ``list_images``
     - Список файлов изображений в папке (путь, размер, mtime). Передайте
       ``recursive=true`` для обхода вложенных папок.
   * - ``read_image_metadata``
     - Размеры, формат, EXIF-теги и поля XMP (сайдкар, иначе встроенные) для одного
       изображения. Отсутствующие данные сообщаются как соответствующее
       пустое значение, а не вызывают исключение.
   * - ``read_xmp_tags``
     - Быстрый путь, который читает только XMP (сайдкар, иначе встроенный) — рейтинг,
       цветную метку, ключевые слова, заголовок, описание.
   * - ``convert_format``
     - Преобразовать одно изображение в другой формат. Формат назначения
       выводится из суффикса назначения (``png`` / ``jpg`` /
       ``jpeg`` / ``webp`` / ``tiff`` / ``bmp`` / ``avif``, а также ``heic`` /
       ``jxl``, если установлен необязательный бэкенд). Опциональное
       ``quality`` (1–100) применяется к JPEG / WebP / AVIF / HEIC / JXL.
   * - ``puppet_from_png``
     - Построить риг ``.puppet`` из PNG, используя авто-меш плагина
       puppet. Затравливает каталог параметров стандарта Cubism,
       поэтому риг сразу же управляем.
   * - ``puppet_inspect``
     - Открыть архив ``.puppet`` и вернуть структурированный инвентарь:
       drawables, deformers, parameters, motions, expressions, hit
       areas, parts, parameter blends и риги physics.
   * - ``image_statistics`` / ``quality_metrics`` / ``read_histogram``
     - Поканальные mean/min/max/std/median, метрики качества без эталона
       (красочность, энтропия, контраст, плотность краёв, шум) и
       256-корзинная гистограмма с долями верхнего/нижнего клиппинга.
   * - ``sharpness_score`` / ``ocr_text`` / ``image_thumbnail``
     - Оценка размытия по дисперсии лапласиана, текст OCR Tesseract
       (корректно при отсутствии) и ограниченный по размеру base64 PNG-предпросмотр.
   * - ``find_similar``
     - Группировка почти-дубликатов по перцептивному хешу (порог
       Хэмминга). Сообщает прогресс по каждому файлу, если передан
       токен прогресса.
   * - ``apply_watermark`` / ``apply_frame``
     - Впечатать текстовый водяной знак или обернуть изображение в
       паспарту / рамку-Polaroid с опциональной подписью.
   * - ``build_collage``
     - Композиция нескольких изображений в сетку-монтаж (настраиваемые
       столбцы, размер ячейки, зазор, поля, фон). Сообщает прогресс.
   * - ``crop_image`` / ``resize_image`` / ``rotate_image``
     - Обрезка по пиксельному прямоугольнику, изменение размера (одна
       сторона сохраняет пропорции, обе задают точный размер) и поворот
       без потерь на 90/180/270
       или горизонтальное/вертикальное отражение.
       Размеры и координаты относятся к изображению, повёрнутому по EXIF.
   * - ``collection_stats``
     - Сводка по оценкам, избранному, цветовым меткам и состояниям
       отбора в папке (количества, распределение 0–5 звёзд и среднее).
   * - ``reverse_geocode`` / ``extract_video_frame``
     - Сопоставить GPS-координаты ближайшему городу офлайн и декодировать
       один кадр видео в стоп-кадр.
   * - ``extract_gps`` / ``dominant_colors``
     - Прочитать широту/долготу GPS из EXIF (результат можно сразу передать
       в ``reverse_geocode``); извлечь цветовую палитру методом median-cut
       (rgb / hex / число пикселей).
   * - ``error_level_analysis``
     - Карта следов правки по Error-Level-Analysis (повторное JPEG-сжатие)
       в виде PNG data URI (отредактированные области выделяются на фоне).
   * - ``search_images``
     - Отфильтровать папку языком запросов умных альбомов (расширение / имя /
       размер / разрешение / соотношение сторон / камера EXIF / объектив / место).
   * - ``solarize_image`` / ``glow_image``
     - Применить тональную инверсию соляризации или рассеянное свечение /
       эффект Ортона и сохранить результат.
   * - ``velvia_image`` / ``emboss_image`` / ``defringe_image``
     - Усиление насыщенности в стиле Velvia с учётом яркости, рельефное
       тиснение с направленным светом и обесцвечивание пурпурной/зелёной
       каймы по краям.
   * - ``film_negative_image`` / ``graduated_density_image``
     - Инвертировать отсканированный цветной негатив (подложка плёнки
       определяется автоматически) и наложить линейный градиентный
       нейтрально-серый фильтр.
   * - ``filmic_tonemap_image`` / ``tone_equalizer_image`` / ``detail_equalizer_image``
     - Плёночный спад светов по Reinhard/Hable, экспозиция по зонам яркости
       и контраст по частотным полосам.
   * - ``colormap_image`` / ``false_color_image``
     - Перекрасить яркость по перцептивной карте viridis/magma/jet или
       отобразить её на шкалу экспозиции в ложных цветах.
   * - ``dither_image`` / ``split_toning_image`` / ``pixel_sort_image``
     - Упорядоченный дизеринг (Bayer) до нескольких тонов на канал,
       раздельное тонирование теней/светов и сортировка пикселей по
       полосам яркости.
   * - ``polar_image`` / ``kaleidoscope_image``
     - Преобразование между прямоугольными и полярными координатами
       («маленькая планета») или зеркальное отражение кадра в заданное
       число секторов калейдоскопа.
   * - ``frosted_glass_image`` / ``clahe_image`` / ``local_contrast_image``
     - Рассеивание «матового стекла» по случайным соседним пикселям,
       адаптивная эквализация гистограммы с ограничением контраста (CLAHE)
       и чёткость средних тонов + текстура мелких деталей.
   * - ``posterize_image`` / ``gradient_map_image``
     - Квантовать каждый канал до нескольких плоских уровней или
       переназначить яркость через градиент от чёрного к белому,
       смешанный по интенсивности.
   * - ``film_grain_image`` / ``dehaze_image`` / ``distort_image``
     - Настраиваемое гауссово плёночное зерно, удаление дымки методом
       dark channel prior и геометрические искажения «водоворот» /
       «сжатие» / «рябь».
   * - ``levels_image`` / ``curve_image``
     - Уровни с точками чёрного/белого и гаммой, а также пресет общей
       тоновой кривой (S-кривая, подъём теней, сжатие светов).
   * - ``auto_color_balance_image`` / ``channel_mixer_image``
     - Автоматический баланс белого (gray-world, white-patch,
       percentile-stretch, retinex) и микшер каналов 3x3 с переводом
       в монохром.
   * - ``lens_correction_image``
     - Исправление бочкообразной/подушкообразной дисторсии (k1), осветление
       или усиление виньетирования в углах и устранение красной/синей
       хроматической аберрации.

Каждый инструмент объявляет JSON ``outputSchema`` и аннотации
``annotations`` (только чтение / разрушающее действие) и возвращает
результат как ``structuredContent`` наряду с текстовой обёрткой
(согласно MCP 2025-11-25), поэтому клиенты получают типизированные
пейлоады без повторного парсинга. Долго выполняющиеся инструменты
транслируют ``notifications/progress``, когда вызывающая сторона
передаёт токен прогресса.

Подсказки
^^^^^^^^^

Сервер предоставляет четыре подсказки через ``prompts/list`` /
``prompts/get``: ``caption_image``, ``suggest_edits``,
``analyze_composition`` (критика композиции на основе карты значимости)
и ``flag_issues`` (триаж по резкости + качеству + клиппингу).
``completion/complete`` предлагает значения для аргумента ``style``
подсказки ``suggest_edits`` и аргумента ``focus`` подсказки
``analyze_composition``.

Claude Code (уровень проекта)
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

Репозиторий поставляется с проектным ``.mcp.json`` в корне репозитория:

.. code-block:: json

   {
     "mcpServers": {
       "imervue": {
         "type": "stdio",
         "command": "python",
         "args": ["-m", "Imervue.mcp_server"]
       }
     }
   }

Открытие любого подкаталога репозитория в Claude Code автоматически
обнаруживает этот сервер. Claude Code запрашивает подтверждение
перед включением проектных серверов в первый раз — примите
запрос для его использования.

Claude Desktop
^^^^^^^^^^^^^^

Добавьте ту же запись в свой конфиг Claude Desktop:

* macOS: ``~/Library/Application Support/Claude/claude_desktop_config.json``
* Windows: ``%APPDATA%\Claude\claude_desktop_config.json``

Используйте абсолютный рабочий каталог или активируйте virtualenv,
в котором установлен Imervue; вызов ``python`` должен разрешаться
в интерпретатор, который может ``import Imervue``.

Поверхность протокола
^^^^^^^^^^^^^^^^^^^^^

Сервер реализует stdio JSON-RPC 2.0 транспорт MCP версии
``2025-03-26``:

* ``initialize`` — рукопожатие; объявляет ``capabilities.tools``.
* ``tools/list`` — перечисляет зарегистрированные инструменты с их
  определениями входа в JSON-Schema.
* ``tools/call`` — вызывает инструмент с ``{"name", "arguments"}``;
  результаты возвращаются внутри массива ``content``.
* ``notifications/*`` — молча принимаются (без ответа).

Реализация находится в ``Imervue/mcp_server/``:

* ``server.py`` — цикл протокола + реестр инструментов.
* ``tools.py`` — функции-обработчики и определения инструментов по умолчанию.
* ``__main__.py`` — точка входа ``python -m Imervue.mcp_server``.

Пользовательские инструменты можно регистрировать, конструируя
:class:`MCPServer` вручную, вызывая :meth:`MCPServer.register` и
подавая сообщения через :meth:`MCPServer.handle_message` (или
управляя циклом stdio со встроенным помощником :func:`run`).
