# CLI next-stage assessment

Read-only assessment for the complete production complexity repair. The supplied hosted score of 151 for Imervue/cli.py is a prioritization input, not a new measurement. No source changes, tests or complexity measurements were performed.

## Current ownership

Imervue/cli.py combines the public parser and entry point, filesystem input selection, path naming, image operation adapters, pipeline decoding/execution, reporting, concurrent batch orchestration and composite commands. Existing cli_tools.py owns MCP schema-to-command adaptation and backend calls. Existing cli_output.py owns transactional output publication, conflict naming, metadata policy and machine-readable result encoding. Those existing owners should not become destinations for unrelated extracted complexity.

The central data shapes already exist. Parsed argparse namespaces select operation functions; _WRITE_SPEC maps a command to operation/suffix/extension policy; _PIPELINE_OPS maps ordered JSON step names to array transforms; JobItem carries publication outcomes. Preserve these shapes before introducing another registry. Model the Domain favors the existing maps over a second parallel command-description framework.

## Real repetition and scope choices

The clearest duplicated decision is parent-traversal validation at cli.py:354 and :448. Both construct a Path and reject a '..' part. A single path-check owner can serve both while retaining optional --out handling and the two exact error messages. Do not silently normalize, resolve, expand or reject additional path forms.

No-input detection and printing repeat in run (:311), cmd_collage (:464), cmd_preset (:524) and cmd_pipeline (:560). A shared input-selection boundary can own the sorted/deduplicated selection and diagnostic, but preserve validation timing. Preset lookup and pipeline decoding/validation currently precede input selection. Collage validates its output only after finding inputs. A generic decorator that validates every command first would change which error users see. Check actual aggregate reduction before accepting a helper that merely leaves the same branch in all four callers.

Native and bridged report/write routing repeat in run and _run_bridged (:329). The existing write specification can represent a bridged writer's resolved operation/suffix/extension without a second writer execution path. A bridged SINGLE still bypasses image selection. Avoid eagerly creating every bridged operation or caching bridged_commands, whose definitions currently resolve when called.

The four basic array-effect writers at :140-160 repeat decode, transform, Image.fromarray and save. Sharing the RGBA writer boundary may reduce statement duplication, but this mostly branch-free repetition is not evidence of lower cyclomatic complexity. Pipeline variants differ because they coerce values from untyped JSON, while CLI variants receive argparse values. Do not force both through a new conversion policy.

The sequential and threaded KeyboardInterrupt handlers at :424 intentionally set cancellation before leaving the executor context and waiting for active encoders. Do not move the catch outside the with block just to deduplicate it. Any consolidation must retain that ordering under a live worker barrier test.

Plausible cohesive owners are input/path policy; native image writers; reporting; pipeline schema and transforms; composite-image commands; preset application; parser declarations/construction; and batch execution/results. Keep main/run and stable public imports in cli.py. Batch target planning, execution and report publication share safety constraints and must remain easy to trace. A file split named only after execution phases would disperse those constraints. If a proposed owner exceeds the budget, first simplify repeated decisions rather than moving arbitrary function groups. Laziness Protocol favors the small validation/routing consolidations over a new generic command framework.

## Contracts to pin

- Input selection at :57 keeps explicitly named existing files regardless of extension/hidden name. Directory enumeration uses list_images with RASTER_EXTENSIONS and the recursive flag. Results are sorted and deduplicated Paths. Missing inputs are silently omitted until the empty-result diagnostic.
- output_path at :74 preserves the source extension's case when no replacement is requested, except RAW becomes PNG. Supplying --out removes the command suffix. Convert supports its extended-format backend route, while optimize uses a different extension fallback. Keep high-bit-depth, EXIF-upright and sRGB decoding policies for each writer.
- load_pipeline at :246 accepts UTF-8 BOM and either a list or a dictionary containing pipeline. Validation accumulates a too-many-steps error plus every malformed/unknown-step error in order. Execution wraps only TypeError with stage context; other failures retain their existing type/message. Empty pipelines still decode and save an image.
- run dispatches native multi-commands before bridged commands; bridged SINGLE avoids inputs; other commands choose reporter or writer after input selection. Unknown programmatic command names may still raise KeyError. Parser guarantees must not turn into redundant internal guards.
- _report at :337 continues only for IMAGE_READ_ERRORS, preserves successful input order and dictionary insertion order, prints one JSON list or key=value lines, and returns 1 if any image failed. Do not merge this with write summaries, which have different output rules.
- _write at :382 validates output/report paths and report/source/planned-output conflicts before work. plan_targets disambiguates same-name destinations before threads start. Completed results are keyed by source string, then emitted in input order rather than completion order. Missing completed entries become cancelled JobItems.
- Worker resolution at :374 uses inline execution for jobs=1 or at most one file; jobs<=0 selects CPU count; workers clamp to the cohort size. _run_outputs consumes submitted futures in submission order. KeyboardInterrupt sets the shared Event, cancels queued futures and waits for active encoders through the executor context. Unexpected worker exceptions are not silently converted into report rows here.
- Output publication remains in cli_output.process_output. Cancellation is checked before work and by write_output before commit. Dry-run skips encoding. Explicit output-conflict overrides --overwrite; strip forces no metadata even when another metadata policy was selected. Preserve original-file retention and temporary-stage cleanup.
- Write messages use stdout except failures, then print the processed/skipped/error summary to stderr. Actual-output/report collision checking happens again after publication. Report write failure returns 1 before the interrupted=130 branch. Preserve this precedence, including a report failure after Ctrl+C.
- Collage retains readable inputs after individual decode failures, returns 1 for partial success and publishes through OutputPolicy('replace'). Anaglyph requires both files before output validation, catches pair decode errors but not every later transform/write failure. Keep each command's distinct diagnostics and default output path.
- Preset lookup lazily loads settings only when PRESETS_KEY is absent, reports unknown names before checking inputs, and assigns args.recipe. Pipeline assigns args.pipeline_steps only after its validation and input-selection gates. Keep these observable Namespace mutations for programmatic callers.
- Parser construction at :719 adds native rows, bridged commands, then list-ops. Preserve order, help, defaults, flags, choices, nargs, required fields, BooleanOptionalAction behavior and prog/description/version strings. Module execution configures Pillow before main; importing/calling main does not do that extra setup. The CLI must remain headless with no Qt/OpenGL imports.

## Verification and integration hazards

Start with tests/test_cli.py, tests/test_cli_tools.py, tests/test_cli_output.py and tests/test_output_policy.py. Existing parser tests at test_cli.py:370 and :1245 and command-list tests around :1220 already pin public shape. tests/test_docs_coverage.py imports build_parser and _PIPELINE_OPS; preserve those import paths. test_puppet_format_schema.py also calls the CLI. This assessment inspected these paths but ran no tests.

Add a baseline/candidate replay that captures parsed Namespace values and exact help/list-ops output for every command, then exit code/stdout/stderr and filesystem outcomes for deterministic temporary-image fixtures. Include hidden/explicit/duplicate/missing inputs, RAW naming, same-stem collisions, all conflict policies, dry runs, metadata choices, bad report paths, partial decode failures and ordered pipeline errors. Normalize only temporary root prefixes, not message text or command order. Compare decoded pixels and dimensions where encoder bytes are not a stable contract; retain file-byte checks for source preservation and explicit transaction guarantees.

For threaded cancellation, use Events/barriers rather than sleep. Make one encoder wait, interrupt collection, assert cancellation is set before release/join, and verify no incomplete output is published. Separately test report-write failure precedence and unexpected worker exceptions. Run the real module entry in a background subprocess for help, malformed args, version, one successful conversion and one failure, with a process timeout and isolated output/settings paths. Check imported modules for the headless constraint.

Extraction changes function globals. test_cli_output.py:76 patches cli.op_resize and the shared cli._WRITE_SPEC mapping. Re-export the same mutable specification object where necessary; a copied dictionary would break the injection. Other tests import main, build_parser, load_pipeline, validate_pipeline, iter_image_paths, output_path, _CLI_VERSION and _SUBCOMMANDS directly. Re-exporting functions does not redirect their global dependency lookups, so move monkeypatch targets to the actual owner when the test intends dependency substitution. Do not add module-global forwarding machinery solely to preserve private patch locations.

No blocker prevents baseline characterization. Preserve CLI syntax/output so this remains an internal refactor; any actual public behavior change requires synchronized ten-language README/Sphinx updates and separate justification. Full project gates, independent review and fresh source-matched hosted scores remain required before claiming this unit complete.
