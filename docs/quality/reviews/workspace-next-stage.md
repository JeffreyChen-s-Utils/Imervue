## Ownership and repeated decisions

`PuppetWorkspace` owns the QMainWindow, action identity, canvas, docks and controller lifetimes. Existing collaborators already own menu construction (`workspace_menus.py`), import routing (`workspace_import.py`), capture and streaming (`workspace_live.py`), and welcome/inspector layout (`workspace_ui.py`). Moving more unrelated methods into those files would transfer the burden.

The strongest small consolidation is authoring. `workspace.py:355` and `:367` repeat document lookup, missing-document return, identifier selection, operation success, document reload and announcement for rotation and warp deformers. The parameter path at `:379` has the same lifecycle but a different identifier namespace and message. The identifier loops at `:430` and `:440` are identical after constructing the occupied-ID set and choosing the prefix separator. A pure first-free-ID function plus a narrow shared authoring operation can remove real decisions. Preserve `rotation_1` / `warp_1` versus `Param1`, first available rather than greatest suffix, and no document reload or announcement on failure.

Another concrete reuse is the existing `_reset_toggle` at `workspace.py:525`. The motion-record failure path at `:797`, recording completion/failure at `workspace_live.py:77` / `:86`, and VTS failure at `:207` repeat its exact blockSignals(True), setChecked(False), blockSignals(False) sequence. They can call that owner. Do not replace every setChecked(False) with it. `_reset_to_rest` deliberately emits toggled signals to shut producers down; recording-start cancellation currently emits the off signal and therefore stops the recorder. A QSignalBlocker would also change the existing behavior for an already-blocked action unless explicitly treated as a separate fix.

Lip-sync (`workspace.py:463`), webcam (`workspace_live.py:95`), virtual camera (`:148`) and NDI (`:181`) repeat the enable-only missing-package check, install callback, blocked reset and early return. A focused prerequisite helper is a later candidate. Preserve package-list identity, callback retry through the QAction, install-before-reset order, no dependency check on disable, and different downstream failure/status/preview behavior. Avoid a generic controller registry that hides those distinctions or eagerly resolves imports.

## Proposed sequence

The minimum safe implementation unit is authoring only. Add baseline contracts for identifiers, operation success/failure, reload/status order and key editing, then extract a cohesive authoring owner and consolidate the two identifier loops and deformer-add paths. Keep `PuppetWorkspace` method names available to actions and `ParameterDock`. This is an incremental reduction, not a claim that the entire workspace reaches 20.

For a subsequent complete workspace cohort, plausible owners are document open/save/recent state; authoring and identifiers; reset/lifecycle; optional dependency and input toggles; validation/repair/mirror commands; motion editing/recording/audio; and batch export. Construction and Qt overrides should remain in the shell unless a setup function genuinely compresses ownership. Measure the aggregate and every resulting owner before accepting a partition. Existing import/menu/live/UI modules must be included in any touched-file budget so complexity cannot disappear into them. Prefer helpers that remove repeated decisions over extra one-call forwarding layers. These choices follow Minimize Reader Load and Laziness Protocol.

## Contracts to pin

- Construction order is canvas, actions, menus/toolbar, docks, controllers, status, welcome, inspectors and tooltips (`workspace.py:85`). Actions connect bound slots before controllers exist. Preserve shared QAction identity and parent ownership. `showEvent` schedules inspector sizing once through a context-bound timer (`:111`).
- Docks share the right-side tab group while motions occupy the bottom (`:119`). Motion player default fades are 0.5 / 0.5. Controller signal connections and creation order are explicit at `:164`. Welcome handling initially hides motions and shows/sizes them only when transitioning from empty (`workspace_ui.py:29`).
- Open catches only FileNotFoundError/PuppetFormatError, leaves the old document on those failures, loads before status/recent updates, and returns bool (`workspace.py:223`). Save returns False without a document, catches OSError, and records recents only after success (`:331`). Dialog-only suffix insertion must not leak into the direct save API. `_push_recent` deduplicates exact strings and truncates to ten (`:941`); menu rebuild separately prunes missing files and captures each path in a callback default (`workspace_menus.py:286`).
- Setting a key snapshots forms and announces without reloading. Removing a key reloads the document, restores that parameter's current value, then announces (`workspace.py:392`, `:411`). Do not flatten their distinct post-success operations.
- Reset ordering is snap-stop playback/fade, emit off toggles for live producers, remove expressions, choose the first drawable of each nonempty pose group, reset physics, reset parameters and status (`:255`). Missing optional attributes are tolerated. Output streaming toggles are not part of this reset list.
- Shutdown visits webcam, input engine, virtual camera and NDI in that order, logs each failure independently, and continues; close calls shutdown before the Qt superclass (`:486`). Do not silently enlarge this set during an equivalence refactor.
- Hit areas prefer a motion group match over an individual motion name; expression toggling is independent and follows motion handling (`:822`). Timeline commits seek to the existing elapsed position (`:786`). Audio lip-sync chooses max when above default, otherwise min; only the listed decode/read errors are caught; successful append is followed by selection and status (`:875`).
