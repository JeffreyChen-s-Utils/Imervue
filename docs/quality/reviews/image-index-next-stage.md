# Image index next-stage assessment

Read-only assessment for the complete production complexity repair. The supplied hosted score of 151 for Imervue/library/image_index.py is a prioritization input, not a new measurement. No production edits, tests or complexity measurements were performed.

## Ownership and useful simplifications

The module contains one process-wide catalog, not independent per-domain databases. Its state is a writer connection, query-only reader, writer/read RLocks, configured path and thread-local query context. Public functions expose image metadata, path relocation, search, notes, hierarchical tags, culling, saved albums, roots and similarity. Most callers import the image_index module; scanner, file_transfer, smart_album and maintenance rely on its public functions.

The clearest repeated decision is hierarchical tag parsing. create_tag_path at line 587, delete_tag_path at 599, remove_image_tag at 673 and images_with_tag at 697 repeat slash splitting, whitespace trimming and empty-segment removal. A single pure parser can remove repeated comprehension decisions. Keep each caller's distinct empty-input result: ValueError for create, False for deletions and [] for search. Resolve tag IDs under the same writer lock or snapshot as before. Combining parse and lookup outside those contexts would introduce a race.

Deletion of image-related rows at line 363 repeats the same fixed set of tables already represented by _PATH_TABLES at 373. Reusing that closed table set would reduce duplicated SQL statements and make the ownership explicit, but it adds a loop and is not automatically a cyclomatic improvement. Measure rather than claiming it lowers complexity. Do not accept arbitrary SQL table names from callers.

get_image and get_smart_album share optional-row-to-dict conversion; get_note and get_cull_state share missing-row fallback structure. These are small repetitions. A generic CRUD framework or configurable table registry would conceal more domain behavior than it removes. Notes delete on falsey text and record timestamps; culling validates before opening the database and deletes only for the explicit unflagged state. Keep those policies visible rather than forcing them into one generic mutation engine.

Plausible owners are schema/version setup; canonical connection lifecycle; snapshot and batch policy; image storage/fingerprints; path relocation; ImageQuery/search; tag hierarchy resolution; tag assignment/query; notes/culling; saved albums/roots; and pHash similarity. These are candidate boundaries, not an accepted file allocation. Measure every resulting owner and the full aggregate. Do not transfer complexity into scanner, smart_album or maintenance. Tag traversal and tag links can share a hierarchy owner without importing the public facade back into implementation modules.

Separate Before Serializing Shared State leads to preserving the existing separate reader and writer. The writer is genuinely canonical, so all domain writers must retain the same lock and connection. If lifecycle and snapshot policy move to separate modules, they must reference one canonical state owner. Copying `_reader` or `_conn` with `from ... import ...` would leave stale aliases after close or path switch. Laziness Protocol favors the small tag-parser consolidation and direct domain SQL over a generic database abstraction.

## Contracts to preserve

- Connection setup at lines 152-185 uses autocommit, check_same_thread=False, sqlite3.Row, WAL, NORMAL synchronous mode and foreign_keys=ON. Schema creation is additive and runs on each first connection. _set_schema_version writes 2; there is no version-dispatch migration engine. Preserve current indexes, stored values and reopening behavior. A schema-version policy change is separate work.
- conn publishes the reader and writer together under the read lock after opening the reader. Reader-open failure closes the newly created writer. close takes writer then reader locks, closes the reader first, attempts PRAGMA optimize while suppressing only sqlite3.Error, then closes the writer. Path switching closes existing connections before assigning the new path. Do not broaden exception suppression or change partial-failure behavior casually.
- write_batch at line 207 holds the writer RLock throughout BEGIN/body/COMMIT or ROLLBACK. The writing thread reads its own changes through the writer. Other threads read only committed data without waiting for the scanner's writer lock. Nested write_batch is not implemented as a savepoint; do not silently add nesting semantics.
- _read_snapshot at line 261 initializes before acquiring the read lock and retries if close/path switching wins that race. Nested reads reuse thread-local context. Single-query reads need no extra BEGIN. Multi-query tag operations use one explicit snapshot that ends with ROLLBACK even on error. Materialize results before releasing the reader lock; no cursor may escape.
- Image upsert treats None as unknown and retains existing stored values through COALESCE. set_decoded_fields deliberately clears width, height and phash for None. Both convert unsigned pHash bits to signed SQLite integers. upsert normalizes through Path and refreshes parent/name/ext/indexed_at. Other APIs often preserve str(path) directly; do not unify path normalization as a side effect.
- library_exists, move_paths and stored_paths do not create an absent database. move_paths stages each table under the non-NUL moving prefix, handles chains independently of mapping order, and updates image path-derived fields. keep_existing is decided per table, leaving that source table's rows alone when a destination row exists. Default mode deletes stale destination rows, including notes/tags without an image row. All relocation operations share one batch transaction.
- delete_image and delete_tag_path currently serialize their sequences under the writer lock but do not open their own transaction. Under autocommit, this differs from wrapping every domain mutation in write_batch. Preserve the boundary in an equivalence refactor; assess any atomicity change separately.
- Fingerprints at lines 445-465 use keyset pages of 1000 ordered by path and only complete mtime/size rows. Each page is a separate committed snapshot. The generator must release the reader between yields/pages so close can proceed and the WAL is not pinned. It is not a globally frozen enumeration.
- ImageQuery keeps filter order and bound-argument order, case-folded extension matching, LIKE wildcard behavior and explicit None checks for numeric bounds. Search orders by taken_at DESC then mtime DESC; limit is int-coerced, with SQLite's existing zero/negative behavior. Do not add a tie-breaker or escaping policy during extraction.
- Hierarchical tags use parent_id IS ? for root lookup, preserve numeric IDs, and allow independently stored image links. Recursive deletion removes descendants and links. Multi-query path rendering and tag searches retain a single snapshot, sorted public path lists and include_descendants behavior.
- Culling preserves input ordering/duplicates in filter_by_cull. No filter returns the input list, unflagged means missing culling rows, and paths_with_cull_state(unflagged) returns []. Saved album JSON remains opaque here; smart_album handles decoding. Album ordering is NOCASE, root ordering is by path. Similarity compares signed/unsigned hashes by bit pattern, sorts stably by distance and applies ordinary Python slicing for limit.
